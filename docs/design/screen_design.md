### ページネーションおよびデータ取得の補足
- ページネーションUIはタスクリストの上下に配置する
- ホーム画面およびタスク一覧画面へのアクセス（Enter）時に、タスク一覧取得API（`GET /api/tasks?include_completed=true`）からユーザーが持つすべてのタスクデータを一括取得し、フロントエンド（クライアントサイド）のStateで保持する。
- ホーム画面においては、フロントエンド側で各タブ（優先タスク / 締切間近タスク / ピン留めタスク）の抽出条件およびソート条件に従ってタスクをフィルタリング・ソートし、20件単位のページ分割表示およびページネーション操作UIの制御を行う。
- ホーム画面、タスク一覧画面におけるページネーション操作UIのページ番号表示仕様:
   - 全ページ数 $N \le 10$ の場合:
     - すべてのページ番号 `[1, 2, ..., N]` を表示する。
   - 全ページ数 $N > 10$ の場合:
     - $n \le 3$（先頭付近）の場合: `[1, 2, 3, 4, ..., N]`
     - $n \ge N - 2$（末尾付近）の場合: `[1, ..., N-3, N-2, N-1, N]`
     - それ以外（中間ページ: $4 \le n \le N - 3$）の場合: `[1, ..., n-1, n, n+1, ..., N]`

### タスク操作補足
- タスク削除時は、確認ダイアログを表示
- タスク状態更新は、ボタン一つで更新できるようにする
- タスクピン止め状態は、ボタン一つで更新できるようにする
- 高優先度・ピン止めタスク表示およびカレンダー表示等では「完了タスク表示/非表示」切り替えトグルスイッチを提供（※「締切間近タスク表示」選択時は、要件上完了タスクは常に除外されるため、「完了タスク表示/非表示」切り替えトグルは非活性［Disabled］または非表示制御とする）
- **締切日絞り込み**:
  - 締切日絞り込み時は「指定日当日分の全タスク＋過去日付の期限超過未完了タスク（`status != 'completed'`）」を抽出対象とし、過去日付の完了タスクは常に除外される。
  - 「完了タスク表示/非表示」切り替えトグルがONの場合も、表示される完了タスクは指定日当日に締切を迎えた完了タスクのみとなり、過去日付の完了タスクは含まれない。
- **タスク作成時のピン留め初期値**: タスク作成ポップアップではピン留め指定UIは含めず、初期値（未ピン留め `false`）で作成される（ピン留めはタスク作成後に一覧・詳細等のワンクリック操作で設定する）。
- **タスク作成（繰り返し自動作成および締切クリア操作）**:
  - 「繰り返し作成」トグル有効時は単一用の「締切り日時入力欄」が非表示（または非活性）となり、期間（開始日・終了日: YYYY/MM/DD）、締め切り時刻、および曜日（日〜土）の選択チェックボックスを動的表示し、該当件数のリアルタイムプレビューを提供（例: 「5件作成予定」）。0件または100件超過時はエラー警告を表示して「決定」ボタンをDisabled制御する。範囲内の該当曜日ごとにタスクを即時一括生成する（最大100件/1年間・52週以内）。
  - 単一タスク作成およびタスク編集ポップアップの締切日時入力欄には「クリア（解除）」ボタンを備え、クリックにより `due_datetime` を未設定（`null`）状態へ戻すことができる。
  - 自動作成されたタスクは個別独立した通常タスクとしてDB登録され、タスク編集画面では個別タスクの編集のみを対象とする（一括連動更新は非提供）。
- **タスク画面におけるデータ取得およびクライアント処理仕様**:
  - タスク一覧・カレンダー画面（`/tasks`）にアクセスした瞬間に、タスク取得API（`GET /api/tasks?include_completed=true`）からユーザーの全タスク（未完了・完了含む全件）を一括取得し、フロントエンドのStateで管理する。
  - 検索（キーワード）、ソート順（ピン留め優先、締切昇順/降順、作成日時降順、優先度降順）、優先度絞り込み、ステータス絞り込み、締切日絞り込み、「完了タスク表示/非表示」トグルの切り替え、およびリスト表示時の20件単位のページネーションは、すべてフロントエンド側のState/メモリ上で即時フィルタリング・ソート・分割処理を行う。
  - タスク作成・更新・削除・ステータス直接変更・ピン留め変更の成功時は、APIレスポンスをもとにフロントエンドのタスクStateを直接更新し、リストおよびカレンダーへ即時反映する（必要に応じてタスク全件の再取得・同期も併用可能）。
- **カレンダー表示および日付詳細ポップアップ**:
  - カレンダー表示形式では「全体表示（5〜6週グリッド）」と「週表示（7日間）」を切り替え可能とし、全体表示は「前月（＜）」「次月（＞）」「今日」、週表示時は「前週（＜）」「翌週（＞）」「今日」ボタンによるナビゲーションを提供する。
  - **カレンダー表示時の完了タスク初期値とクライアント整形仕様**:
    - カレンダー表示切り替え時は、「完了タスク表示/非表示」トグルスイッチは初期状態で ON（完了タスクを含む）となる。
    - カレンダー表示への切り替えおよび月/週のナビゲーション（前月/次月、前週/次週、今日等）の操作時は、画面アクセス時に一括取得して保持している全タスクデータから、表示対象月/週のグリッドに含まれる各日付範囲（月全体表示時は前月末・翌月初を含む最大42日間、週表示時は日〜土の7日間）に該当する締切日時（`due_datetime`）を持つタスクをクライアントサイドで抽出し、各日付セルへマッピング・整形して描画する（期間ごとの個別APIリクエストは行わない）。
  - カレンダーグリッドの日付セルをクリックするとモーダル「日付詳細ポップアップ」が表示される。
    - ポップアップ構成要素: 該当日付、タスク一覧（タイトル・締切時刻・ステータス・優先度・コメント）、ステータス直接変更UI（未着手/進行中/完了）、タスク編集画面へのリンク、ピン止めUI、該当日締切「新規タスク作成」ボタン、閉じるボタン
    - ポップアップ遷移先: タスク編集ポップアップ、タスク作成ポップアップ（該当日の日付＋デフォルト時刻 23:59 を締切日時に事前入力して開き、完了・キャンセル時はカレンダー画面へ復帰してカレンダーグリッドを再描画）
  - カレンダーの日付セル上ではタスクステータスを直接変更可能とし、ピン止め操作は日付詳細ポップアップ内でのみ提供する（セル上でのステータス操作時は日付詳細ポップアップ展開イベントを抑止する）。

### OTP・セキュリティ操作補足
- 各OTP画面での送信先メールアドレス表示は「始め4文字＋ドメイン名のみ表示、他10文字固定幅マスク」とする。
- フロントエンドが各用途の有効な `otp_session_id` を保持している場合、対応する情報入力画面へアクセスしてもOTP入力画面へ復帰し、`request-otp` を再実行しない。手続き完了、全体期限切れ、またはセッション失効時に保持状態を削除する。
- OTP送信失敗時は送信失敗を通知し、同じセッションIDで再送できる状態を維持する。送信が5回連続で失敗してセッションが失効した場合、新規登録はアカウント情報入力画面、パスワードリセットはメールアドレス入力画面、メール変更はプロフィール編集画面へ戻す。
- 「再送信」ボタン押下直後は60秒間のクールダウン期間が設定され、ボタンが非活性化されるとともにカウントダウンタイマーが表示される。
- **OTP検証5回連続失敗時の自動再送挙動**: OTP入力の検証に5回連続で失敗した場合（APIより `422 OTP_REISSUED_DUE_TO_FAILURES` が返却された場合）、画面上に「入力試行回数の上限に達したため、新しい認証コードを再送信しました」という通知（ポップアップ/トースト）を表示し、OTP入力欄をクリアするとともに、「再送信」ボタンの60秒クールダウンカウントダウンを開始する。

### 共通UI・エラー表示補足
- 各種入力フォーム画面（ログイン、新規登録、パスワードリセット、プロフィール編集、パスワード変更、アカウント削除、タスク作成・編集等）においては、入力バリデーションエラーやAPIエラー（認証失敗・ロックアウト・サーバーエラー等）を明示するためのエラーメッセージ表示領域（各入力欄下部のインラインエラー表示およびフォーム上部のアラートバナー領域）を備える。
- **パスワード再認証失敗時の画面制御**:
  - 1〜4回目の認証失敗（`401 REAUTH_FAILED` 受信時）: 現在のパスワード入力欄の下部に「パスワードが正しくありません」とインラインエラーを表示し、入力欄の値をクリアして再入力を促す（※アカウント列挙・推測攻撃防止のため残試行回数は画面表示しない）。
  - 5回目の連続認証失敗（`401 SESSION_DESTROYED` 受信時）: アラート通知とともに直ちに全セッション破棄・Cookie消去を行い、ログイン画面へ強制リダイレクトする。
