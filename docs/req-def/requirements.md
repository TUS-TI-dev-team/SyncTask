# Requirements Definition

## システム概要
### 背景
- チーム開発の学習のため
### 目的
- 個人向けのクロスプラットフォーム対応タスク管理Webアプリを作成し、端末間でタスク管理をできるようにすること
- チーム開発の手法について学ぶこと
### プロジェクト概要
- 個人のユーザが利用するタスク管理用Webアプリを作成する

## 業務要件（システム要件）
### このアプリを何のために使うか
- タスク管理
### 利用者の範囲
- 対象：大学生
- 規模：数人
### 期待する成果・完了条件
- 自分のタスクを作成できる
- 自分のタスクの進捗状況を把握・記録できる
- これにより、効率的なタスク管理を可能にする

## 機能要件
### ユーザー視点でできる機能
- アカウント管理
	- アカウント作成
		- ユーザー名、パスワード、メールアドレスを入力
		- メール認証を行う
			- メールにてOTPを送信
			- サイト内のOTP入力欄にOTPを入力する
	- アカウント編集
		- ログイン後の画面からのみ可能
		- ユーザ名の変更
		- メールアドレスの変更
			- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
			- 変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する
			- 変更先メールアドレスが既に他ユーザーに登録済みの場合は、メールアドレスの登録有無を秘匿するため、実際にはOTPを発行せずダミーOTP入力画面へ遷移する
			- 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
	- アカウントの削除
		- ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要)
		- アカウント本体は論理削除、ログインセッションは物理削除とする
		- 論理削除後の登録メールアドレスでの再登録は可能
			- 再登録の際は自動付与されるUIDが異なるため同名のユーザ名などでも問題なく登録できる
		- アカウント論理削除に伴い、所有するタスクデータへの参照・操作アクセス権限も即座に無効化する
	- パスワード変更
		- ログイン後のみ可能
		- 既存のパスワードを知っていれば変更できる（5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト）
		- 変更後パスワードを入力した後、既存のログインセッションを破棄して再度ログインを要求する
- ログイン関係
	- ログイン
		- メールアドレス（ユーザー名ではない）とパスワードでログイン
	- ログアウト
	- パスワードリセット
		- パスワードリセットは、メール認証で行う
			- メールアドレスを持っている人間を本人とする
		- メールにてOTPを送信
		- サイト内のOTP入力欄にOTPを入力する
		- 変更後パスワードを入力後ログインを要求
- タスク管理
	- タスク作成
		- タスク名（1〜100文字、必須）
		- コメント（0〜1000文字、任意）
		- 優先度（高、中、低、初期値：中）
		- 締切日時（任意）
		- 初期ステータスは「未着手」
	- タスク編集（タスクの名前、コメント等）
		- タスクの名前変更（1〜100文字）
		- タスクの優先度変更（高、中、低）
		- 締切日時の変更・解除
		- コメントの変更（0〜1000文字）
	- タスク状態更新（未着手、進行中、完了）
	- タスク削除
	- タスクピン止め状態更新
	- タスク表示
		- 優先タスク表示（優先度：高のタスクを表示）
		- 締切間近タスク表示
			- 締め切り72時間前のタスクのみを表示する
		- ピン止めタスク表示
		- 一覧表示
			- 並び順（デフォルトソート）:
				1. ピン留めされているタスクを最上部に優先表示
				2. 締切日時が設定されているタスクを締切日の近い順（昇順）で表示
				3. 締切日時が未設定または同日のタスクは作成日時の新しい順（降順）で表示
			- ページネーション: 1ページあたり20件表示
			- タスク検索（and検索）
				- タスク名
					- 含むものを検索
				- 優先度
					- 完全一致（高、中、低）
				- 締切日
				- タスクステータス
					- 完全一致（未着手、進行中、完了）
				- コメント
					- 含むものを検索
		- カレンダー表示（締切日時が設定されているタスクをカレンダー上に表示）

## 非機能要件
### 性能
- 全てのページで、ターンアラウンドタイムが2秒以下
### 可用性
- 稼働率90%以上
### 対応プラットフォーム
- PC
	- OS
		- Windows
		- Linux
	- ブラウザ
		- Google Chrome
		- Microsoft Edge
		- Mozilla Firefox
- スマホ
	- OS
		- Android
	- ブラウザ
		- Google Chrome
		- Mozilla Firefox
### 運用・保守性
- サーバー異常時の管理者へのメール通知(管理者用のメーリングリストを作成)は送信しない
	- 送信する場合の検討メモ
		- プログラムエラー発生時
		- ハードウェアのメトリクス
			- CPU使用率
			- メモリ使用量
			- データベース容量
- 定期バックアップは一旦とらないことにする
### セキュリティ
- 不正アクセス対策
	- 本人以外は、そのアカウントの情報を見られない
		- 登録されているメールアドレスにアクセスできる人を本人とする
	- https通信
	- ログイン認証のセッション期限は1ヶ月とする
	- 論理削除アカウントでのログイン試行時は、一般的な「メールアドレスまたはパスワードが正しくありません」として認証を拒否し、論理削除の有無を秘匿する（応答遅延 1s±0.1s）
- ログイン認証
	- 同一メールアドレスまたは同一IPアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、30分間ロックアウトする
	- 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
	- ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする
	- OTPのセッション期限 5分 (入力制限5回超過または有効期限切れで無効化)
- アカウント新規作成
	- アカウント登録時にすでに登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- パスワードリセット
	- パスワードリセットのメールアドレス入力にて登録されていないメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- アカウント編集（メールアドレス変更）
	- 変更先にすでに他ユーザーで登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- パスワード変更時の，「現在のパスワード」認証
	- 5回連続で現在のパスワードの認証に失敗したら、セッションを破棄してログイン画面に戻す
- OTP要件
	- OTPは英数字8桁，英数字は大文字小文字を区別しない
	- 有効期限: 発行から5分間
	- 誤入力制限: 1つのOTPに対して最大5回まで入力試行可能
	- 5回失敗時の挙動:
		- 実在アカウント/新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 重複メールアドレス/未登録メールアドレス（ダミー画面）の場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う
	- 再送処理のターンアラウンドタイムは 1±0.1s とする
- 使用ライブラリの脆弱性発見
	- 定期的に npm audit, govulncheck
- ログ管理
	- ログイン情報
		- 日時、ユーザーID (UID)、メールアドレス、IPアドレス、ログイン成否
	- DBへのアクセスログ
		- 日時、ユーザーID (UID)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
	- メール認証
- 脆弱性対策
	- 入力文字列のエスケープ処理
	- CSRF対策 → CSRFトークンの導入
	- 開発後に一度脆弱性診断をおこなう
- ユーザ名要件
	- 2文字以上20文字以内
	- 英小大文字、数字
	- 同名のユーザー名登録は可（ログイン識別子にはメールアドレスを使用するため）
- パスワード要件
	- 8文字以上128文字以下
	- 英大文字、英小文字、数字、記号( `!"#$%&'()=-~^|\{}[]+;:*_/?.>,<` )の4種類のうち3種類以上を含むこと
	- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部を含むパスワードの設定を禁止する
- 検証・認証失敗時の応答速度を1s±0.1sの範囲で調整する
	- タイミング攻撃防止のため，処理の成否をユーザに判断させないために行う
- メールアドレス要件
  - 他ユーザとの重複なし
- セッション管理
  - トークンではなくセッションによって管理
  - OTPセッション
    - 有効期限　5分
    - セッションの内無効になったものをCRON, 15分ごとに削除する
  - ログインセッション
    - 有効期限　43200分(1ヶ月)
    - セッションの内無効になったものをCRON, 毎日00/00に削除する
