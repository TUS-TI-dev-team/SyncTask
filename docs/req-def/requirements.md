# Requirements Definition

## システム概要
### 背景
- チーム開発の学習のため
### 目的
- 個人向けのクロスプラットフォーム対応タスク管理Webアプリを作成し、端末間でタスク管理をできるようにすること
- チーム開発の手法について学ぶこと
### プロジェクト概要
- 個人のユーザが利用するタスク管理用Webアプリを作成する

## 業務要件（システム要件）
### このアプリを何のために使うか
- タスク管理
### 利用者の範囲
- 対象：大学生
- 規模：数人
### 期待する成果・完了条件
- 自分のタスクを作成できる
- 自分のタスクの進捗状況を把握・記録できる
- これにより、効率的なタスク管理を可能にする

## 機能要件
### ユーザー視点でできる機能
- アカウント管理
	- アカウント作成
		- ユーザー名、パスワード、メールアドレスを入力
		- フォーム送信時（OTP生成・メール送信の前）にバックエンドにてユーザー名要件・パスワード要件・メールアドレス要件の入力値バリデーションを一括実施する（不備がある場合はOTPを発行せずエラー表示）
		- メール認証を行う
			- メールにてOTPを送信
			- サイト内のOTP入力欄にOTPを入力する
			- OTP認証成功時、アカウントの作成を確定すると同時に自動的に新しいログインセッションを発行してログイン状態とし、タスク一覧画面へ遷移する（なお、ブラウザ上に既存の古いログインセッションが存在する場合は無効化・上書きし、複数アカウントへの同時重複ログイン状態を防止する）
			- OTPセッション有効期間中（初回発行から5分間、再送信を含め全体最大15分間）は、作成予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または全体有効期限切れまで排他維持する
	- アカウント編集
		- ログイン後の画面からのみ可能
		- ユーザ名の変更
			- 変更後のユーザー名を入力し、ユーザー名要件（2〜20文字、英小大文字・数字）に基づきバリデーションを行う
			- 変更先ユーザー名が現在設定中の自分自身のユーザー名と同一の場合は「現在のユーザー名と同じです」とエラー表示し拒否する
			- パスワード再認証は不要（入力・送信で即時変更）
			- ユーザー名変更完了後も現在のログインセッションは維持され、画面上の表示名（ユーザー名）が即座に更新される
		- メールアドレスの変更
			- フォーム送信時（OTP生成・メール送信の前）にバックエンドにて新メールアドレスの入力値バリデーションを一括実施する（不備がある場合はOTPを発行せずエラー表示）
			- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
			- 変更確定と同時に、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、新メールアドレスでの再度ログインを要求する
			- 変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する
			- 変更先メールアドレスが既に他ユーザーに登録済みの場合は、メールアドレスの登録有無を秘匿するため、実際にはOTPを発行せずダミーOTP入力画面へ遷移する
			- 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
			- メール認証未完了の「変更手続き中」状態においても、ログイン識別子は変更前の旧メールアドレスが維持される
			- OTPセッション有効期間中（初回発行から5分間、再送信を含め全体最大15分間）は、変更先予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または全体有効期限切れまで排他維持する
	- アカウントの削除
		- ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要。5回連続でパスワード再認証に失敗した場合はログインセッションを破棄［物理削除］してログイン画面にリダイレクトする)
		- アカウント本体は論理削除、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（DBから物理削除）し、クライアント側のCookieも消去してログイン画面へリダイレクトする
		- 論理削除後の登録メールアドレスでの再登録は可能
			- 再登録の際は自動付与されるUIDが異なるため同名のユーザ名などでも問題なく登録できる
		- アカウント論理削除に伴い、所有するタスクデータおよび関連データは即座にDBから物理削除する
	- パスワード変更
		- ログイン後のみ可能
		- 既存のパスワードを知っていれば変更できる（5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト）
		- 変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
- ログイン関係
	- ログイン
		- メールアドレス（ユーザー名ではない）とパスワードでログイン
	- ログアウト
		- ログイン後の画面からのみ実行可能（`POST` リクエスト + CSRFトークン検証必須）
		- ログアウト実行時、操作中の端末のログインセッションレコードをDBから即座に物理削除する（他端末・他ブラウザのセッションは維持する）
		- クライアント側のセッションCookieを即座に無効化（消去）し、ログイン画面にリダイレクトする
		- セッションが既に無効化または期限切れの状態でログアウトが実行された場合もエラーとせず、セッションCookieを消去してログイン画面へリダイレクトする（冪等性の確保）
	- パスワードリセット
		- パスワードリセットは、メール認証で行う
			- メールアドレスを持っている人間を本人とする
		- フォーム送信時（OTP生成・メール送信の前）にバックエンドにてメールアドレス等の入力値バリデーションを一括実施する（不備がある場合はOTPを発行せずエラー表示）
		- メールにてOTPを送信
		- サイト内のOTP入力欄にOTPを入力する
		- OTP検証成功時に当該OTPセッションのステータスを「検証済み」に変更し、そこから仮セッションの有効期限を15分間とする（この仮セッションは新パスワード設定APIへのアクセスのみを許可する制限付きセッションとし、タスク操作等の通常ログイン必須APIへのアクセス権限は付与しない）
		- 変更後パスワードを入力後、新パスワードを設定完了すると同時に当該パスワードリセット用OTP/仮セッションを直ちに失効・DBから物理削除し（クライアント側の仮セッションCookieも消去）、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
- タスク管理
	- タスク作成
		- タスク名（前後の空白文字［半角・全角スペース、タブ、改行］を除去［トリム］した上で1〜100文字必須。空白文字のみの入力はバリデーションエラーとして拒否する。なお、タスク名は1行テキストとし、文字列内部の改行コード［CR/LF］やタブ等の制御文字の入力はバリデーションエラーとして拒否する）
		- コメント（前後の空白文字をトリムして保持、0〜1000文字、任意。改行コードはシステム内部で一律 `\n`［LF］に正規化し、改行1つにつき1文字として文字数カウントを行う）
		- 優先度（高、中、低、初期値：中）
		- 締切日時（任意: YYYY/MM/DD hh:mm format JST。時刻部分［hh:mm］が未指定［省略］の場合はデフォルト締切時刻として「23:59 JST」を適用する）
		- 初期ステータスは「未着手」
		- 期間と曜日を指定し、その範囲内で毎週タスクを自動作成できる（即時一括生成方式）
			- 期間指定: 開始日と終了日をそれぞれYYYY/MM/DD形式で入力（テキスト入力またはポップアップ表示のカレンダーから選択可能）
			- 期間・生成件数バリデーション:
				- 開始日 <= 終了日（開始日と終了日が同一日の場合も指定曜日に合致すれば1件作成可能）
				- 開始日には過去日も指定可能
				- 指定可能な最大期間は1年間（最大52週）以内、かつ計算される生成タスク数は1件以上100件まで（期間内に選択された曜日が1日も含まれず生成件数が0件となる場合は「指定された期間内に該当する曜日が存在しません」とエラー表示し処理を中断する。また、期間および選択曜日の組み合わせにより生成予定件数が100件を超える場合は送信前に警告または送信時に「生成件数が上限（100件）を超えています」とエラー表示し、タスクの一括作成処理を一切実行せず中断する［All-or-Nothing］）
			- 曜日指定: 「月、火、水、木、金、土、日」より1つまたは複数選択可能（1つ以上選択必須）
			- 毎週作成サイクル: 開始日から終了日までの期間内で、選択された該当曜日ごとに毎週タスクを生成する
			- 生成タスクの属性: 入力されたタスク名、優先度、コメント、初期ステータス（「未着手」）を各タスクへコピーする。締切時刻（hh:mm JST）は任意入力とし、指定がある場合はその時刻を各該当日付に適用し、未指定（省略）の場合は該当日の「23:59 JST」をデフォルト締切時刻として適用する
			- 生成後の個別独立性: 自動作成されたタスクはそれぞれ独立した通常タスクとしてDBに個別登録され、以降は個別に編集・状態変更・削除が可能（繰り返しタスク間の一括連動更新機能は提供しない）
	- タスク編集（タスクの名前、コメント等）
		- タスクの名前変更（前後の空白文字をトリムした上で1〜100文字必須。空白文字のみの入力および改行コード等の制御文字を含む入力は拒否する）
		- タスクの優先度変更（高、中、低）
		- 締切日時の変更・解除
		- コメントの変更（前後の空白文字をトリムして保持、0〜1000文字。改行コードはシステム内部で一律 `\n`［LF］に正規化して文字数をカウントする）
	- タスク状態更新（未着手、進行中、完了）
	- タスク削除
		- ユーザー操作によるタスクの削除は物理削除とする
	- タスクピン止め状態更新
	- タスク表示
		- 優先タスク表示
			- 優先度「高」のタスクを表示
			- 対象ステータス: デフォルトは「未着手」「進行中」の未完了タスクのみを表示する（「完了」タスクの表示・非表示を切り替えるフィルタオプションを提供）
			- 並び順: 締切日時が早い順（昇順）。締切日時が同一または未設定の場合は作成日時の新しい順（降順）で表示（ピン留めによる並び替えは行わない）
			- ページネーション: 1ページあたり20件表示
		- 締切間近タスク表示
			- 対象ステータス: 「未着手」「進行中」のタスクのみ（「完了」タスクは除外）
			- 対象時間範囲: 締切日時が現在時刻から72時間以内、または締切日時を過ぎた未完了タスク（締切日時 <= 現在時刻 + 72時間）
			- 並び順: 締切日時が早い順（昇順）。締切日時が同一の場合は作成日時の新しい順（降順）で表示（ピン留めによる並び替えは行わない）
			- ページネーション: 1ページあたり20件表示
		- ピン止めタスク表示
			- ピン留め設定がオン（`is_pinned = true`）のタスクを表示
			- 対象ステータス: デフォルトは「未着手」「進行中」の未完了タスクのみを表示する（「完了」タスクの表示・非表示を切り替えるフィルタオプションを提供）
			- 並び順: 1. 締切日時が設定されているタスクを締切日の近い順（昇順） 2. 締切日時未設定または同日のタスクは作成日時の新しい順（降順）
			- ページネーション: 1ページあたり20件表示
		- 一覧表示
			- 対象ステータス: デフォルトは「未着手」「進行中」の未完了タスクのみを表示する（画面上に「完了タスクを含める / 除外する」の表示切り替えフィルタオプションを提供）
			- 並び順（デフォルトソート）:
				1. ピン留めされているタスクを最上部に優先表示
				2. 締切日時が設定されているタスクを締切日の近い順（昇順）で表示
				3. 締切日時が未設定または同日のタスクは作成日時の新しい順（降順）で表示
			- ページネーション: 1ページあたり20件表示
			- タスク検索（and検索）
				- キーワード検索（タスク名・コメント）は、入力された検索文字列の前後の空白文字を自動的に除去（トリム）し、英大文字・小文字を区別しない部分一致検索（Case-Insensitive）を行う（未入力またはトリム後空文字の場合はキーワードによる絞り込みを行わない）
				- タスク名
					- 含むものを検索（未入力時は絞り込みを行わない）
				- 優先度
					- 完全一致（高、中、低。未指定・すべて選択時は全優先度を対象とする）
				- 締切日
					- 指定日当日までの締め切り（〜指定日 23:59:59 JST）に該当する締切日時を持つタスクを検索。未設定（NULL）のタスクは除外する。未指定の場合は締切日による絞り込みを行わない
				- タスクステータス
					- 完全一致（未着手、進行中、完了。未指定時は一覧表示の「完了タスクを含める / 除外する」フィルタ設定に従う）
				- コメント
					- 含むものを検索（未入力時は絞り込みを行わない）
				- 検索結果の表示: 一覧表示の並び順ルール（1. ピン留めされているタスクを最上部に優先表示 2. 締切日時が設定されているタスクを締切日の近い順［昇順］ 3. 締切日時が未設定または同日のタスクは作成日時の新しい順［降順］）およびページネーション（1ページあたり20件表示）を適用する。また、新たな検索を実行した際は常に1ページ目を初期表示する
		- カレンダー表示
			- 締切日時が設定されている全ステータス（「未着手」「進行中」「完了」）のタスクについて、日本標準時（JST）における日付（YYYY-MM-DD）のセル上に配置して表示する
			- 同一日付セル内に複数のタスクが存在する場合の並び順は、1. ピン留めされているタスクを優先、2. 締切時刻（hh:mm:ss）が早い順（昇順）、3. 作成日時の新しい順（降順）で表示する
			- 「完了」ステータスのタスクは、視覚的に区別（文字の打消し線やグレーアウト表示等）して表示する
			- カレンダー画面上に「完了タスクを含める / 除外する」の表示切り替えフィルタを提供する
			- 表示形式は下記の2パターンを選択できる
				- (default)全体表示: 日-土曜日（日曜日始まり）にて、対象月の初日（1日）から末日（月末）までの全日程が確実に含まれる週（月により5週間または6週間、あるいは常時6週間グリッド）を表示する
					- 上スクロールまたは「前週/前月」操作にて前の週・月、下スクロールまたは「次週/次月」操作にて次の週・月へ遷移・表示できる
					- 次月または前月の1日を含む行を最上部にスクロール・フォーカス表示することができる
					- グリッド内に表示されている前月・翌月の日付セル（余白セル）はグレーアウト等の視覚的区別を行い、当該日付に締切を持つタスクも同様にセル上に配置してポップアップでの確認・操作を可能とする（バックエンドAPIはグリッド全体の開始日から終了日までのタスクを取得する）
				- 週表示: 日-土曜日（日曜日始まり）にて現在または指定日を含む週（7日間）を表示
					- 「前週（＜）」「翌週（＞）」ボタンや左右移動で切り替え可能
					- 「今日」ボタンにより現在日を含む週に即座に戻るナビゲーションを提供
			- それぞれの表示形式にてある日にちをクリックするとその日のタスクを詳細に表示するポップアップを表示する
				- ポップアップ内の機能: 該当日のタスク一覧表示（タイトル・締切時刻・ステータス・優先度）、タスクの完了ステータス切り替え（完了チェック）、クリックによるタスク詳細/編集画面への遷移、および該当日を締切日とする新規タスク作成ボタンを提供する

### 性能
- 全てのページで、ターンアラウンドタイムが2秒以下
### 可用性
- 稼働率90%以上

		- Google Chrome
		- Microsoft Edge
		- Mozilla Firefox

	- OS

		- Google Chrome

### 運用・保守性
- サーバー異常時の管理者へのメール通知(管理者用のメーリングリストを作成)は送信しない
	- 送信する場合の検討メモ
		- プログラムエラー発生時
		- ハードウェアのメトリクス
			- CPU使用率
			- メモリ使用量
			- データベース容量
- 定期バックアップは一旦とらないことにする
### セキュリティ
- 不正アクセス対策
	- 本人以外は、そのアカウントの情報および所有タスクを見られない・操作できない
		- 登録されているメールアドレスにアクセスできる人を本人とする
		- タスク操作・閲覧の認可（BOLA/IDOR対策）: タスクの取得・編集・状態変更・削除・ピン留め等の全API処理において、リクエスト元ログインユーザーのユーザーIDと操作対象タスクの所有ユーザーIDの一致を必須で検証する。存在しないタスクIDまたは他ユーザー所有のタスクIDへのアクセス・操作要求に対しては、タスクの存在有無を秘匿するため一律 `404 Not Found` を返却し処理を拒否する
	- https通信
	- ログイン認証のセッション期限は1ヶ月とする（APIアクセスごとに自動延長される Sliding Expiration 方式）
	- 論理削除アカウントでのログイン試行時は、一般的な「メールアドレスまたはパスワードが正しくありません」として認証を拒否し、論理削除の有無を秘匿する（応答遅延 1s±0.1s）
- ログイン認証
	- メールアドレス単位ロックアウト: 同一メールアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、該当メールアドレスに対するログイン試行を30分間ロックアウトする
	- IPアドレス単位レートリミット（パスワードスプレー対策）: 同一IPアドレスから直近5分間に累計30回以上のログイン認証失敗が発生した場合、該当IPアドレスからのログインAPIリクエストを一律15分間一時遮断（HTTP 429 Too Many Requests、遅延1s±0.1s）する
	- 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
	- ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする。なお、ロックアウト期間は初回ロックアウト発生時刻から30分経過時点で自動解除（固定時間）とし、ロックアウト中の追加試行による期間延長は行わない（永久ロックDoS防止）
	- OTPのセッション期限 5分 (入力制限5回超過または有効期限切れで無効化)
- アカウント新規作成
	- アカウント登録時にすでに有効な他ユーザー（未削除アカウント）として登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- OTPセッション有効期間中（初回発行から5分間、再送信を含め全体最大15分間）は、新規登録手続き中（未認証）のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または全体有効期限切れまで排他維持する
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- パスワードリセット
	- パスワードリセットのメールアドレス入力にて登録されていない（有効な他ユーザーとして存在しない）メールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- アカウント編集（メールアドレス変更）
	- 変更先にすでに有効な他ユーザー（未削除アカウント）で登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- パスワード変更時およびアカウント削除時の「現在のパスワード」認証
	- 5回連続でパスワードの認証に失敗したら、セッションを破棄（物理削除）してログイン画面に戻す
- OTP要件
	- OTPは英数字8桁，英数字は大文字小文字を区別しない
	- 有効期限: 発行から5分間（ただし再送信を行っても、1回の手続きにおけるセッションおよび排他ロックの全体最大有効期限は初回発行から15分間とする。15分経過時はセッションおよび排他ロックを失効して初期画面へ戻す）
	- 誤入力制限: 1つのOTPに対して最大5回まで入力試行可能
	- 5回失敗時の挙動:
		- パスワードリセット OTPの場合
			- 有効な登録済みメールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
			- 未登録（存在しない）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
		- 新規登録 OTPの場合
			- 新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
			- 重複（登録済み）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
		- アカウント編集（メールアドレス変更） OTPの場合
			- 未使用の新規メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
			- 他ユーザーに登録済みの重複メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信（初回発行、直前の手動再送、または5回失敗時の自動再送のいずれか）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する（5回失敗による自動再送発生時もクールダウン期間が即座にリセット・再適用される）。なお、再送信回数の上限は設けないが、初回発行から15分の全体有効期限が経過した時点で手続きは無効となる
	- 再送処理のターンアラウンドタイムは 1±0.1s とする
- 使用ライブラリの脆弱性発見
	- 定期的に npm audit, govulncheck
- ログ管理
	- ログイン情報
		- 日時、ユーザーID (UID)、メールアドレス、IPアドレス、ログイン成否
	- DBへのアクセスログ
		- 日時、ユーザーID (UID)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
	- メール認証ログ
		- 日時、ユーザーID (UID、未登録・未ログイン時は null)、対象メールアドレス、認証種別（新規登録 / パスワードリセット / メールアドレス変更）、アクセス元IPアドレス、処理イベント種別（OTP発行 / 検証成功 / 検証失敗 / 手動再送依頼 / 5回失敗時自動処理）、成否、ダミー処理区分（実処理 / ダミー表示）
	- ログ保持・パージ方針
		- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
		- DBへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
- 脆弱性対策
	- 入力文字列のエスケープ処理
	- CSRF対策 → CSRFトークンの導入（具体の検証方式・伝送形式等の詳細仕様は詳細設計フェーズにて定義する）
	- 開発後に一度脆弱性診断をおこなう
- ユーザ名要件
	- 2文字以上20文字以内
	- 英小大文字、数字
	- 同名のユーザー名登録は可（ログイン識別子にはメールアドレスを使用するため）
- パスワード要件
	- 8文字以上128文字以下
	- 英大文字、英小文字、数字、記号( `!"#$%&'()=-~^|\{}[]+;:*_/?.>,<` )の4種類のうち3種類以上を含むこと
	- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する（いずれも大文字・小文字を区別せず［Case-Insensitive］に部分一致判定を行う）
- OTP認証およびログイン処理における応答速度の調整（遅延制御）
	- 失敗またはダミー処理の場合は、一律1s±0.1sの範囲で応答速度を調整する
	- 認証・検証成功時は、人工的な遅延を挟まず即時にレスポンスを返し次の処理に移行する
- メールアドレス要件
  - 入力されたメールアドレス（新規登録、ログイン、メールアドレス変更、パスワードリセット等の全機能）は、前後の空白文字（半角・全角スペース、タブ、改行）を自動的に除去（トリム）して処理する
  - メールアドレスはシステム内部（登録・ログイン・重複判定・認証処理等）で一律小文字（`toLowerCase()`）に正規化して保持・比較し、Case-Insensitive な一意性を保証する
  - 有効な他ユーザ（未削除アカウント）との重複なし
- セッション管理
  - トークンではなくセッションによって管理
  - OTPセッション
    - 有効期限 5分（ただし再送時を含む1回の手続きにおける全体最大有効期限は初回発行から15分間。またパスワードリセットにおけるOTP検証成功時はステータスを「検証済み」に変更し、そこから有効期限を15分間とする）
    - 有効期限切れまたは無効化・使用済みとなったOTPセッションレコードは、新パスワード設定完了時等に直ちに物理削除するほか、Cronジョブ（15分ごと / Cron: `*/15 * * * *` JST）にてDBから一括物理削除する
  - ログインセッション
    - 有効期限 43200分(1ヶ月)
    - セッションCookie要件:
      - ログインセッションIDを保持するCookieには以下のセキュリティ属性を必須で付与する:
        - `HttpOnly`: JavaScript（`document.cookie`）からの読み取りを禁止しXSS対策を実施
        - `Secure`: HTTPS通信時のみCookieを送信（開発環境を除き常時有効）
        - `SameSite=Lax`: サードパーティコンテキストでの無駄なCookie送信を制限
      - セッションCookieの名称は標準的な名称（例: `sync_task_sid`）とし、有効期限はSliding Expirationに従い更新する
    - ユーザーがログイン中にリクエスト（API呼び出し）を行うたびに、セッションの有効期限をアクセス時刻から43200分（1ヶ月）後に自動更新（Sliding Expiration）する。最後のアクセスから43200分経過したセッションを無効（期限切れ）とする
    - 有効期限切れ（無効化済み）のセッションは、日次Cronジョブ（毎日 00:00 JST / Cron: `0 0 * * *`）にてDBから物理削除する
