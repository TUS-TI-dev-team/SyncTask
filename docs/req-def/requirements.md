# Requirements Definition

## システム概要
### 背景
- チーム開発の学習のため
### 目的
- 個人向けのクロスプラットフォーム対応タスク管理Webアプリを作成し、端末間でタスク管理をできるようにすること
- チーム開発の手法について学ぶこと
### プロジェクト概要
- 個人のユーザが利用するタスク管理用Webアプリを作成する

## 業務要件（システム要件）
### このアプリを何のために使うか
- タスク管理
### 利用者の範囲
- 対象：大学生
- 規模：数人
### 期待する成果・完了条件
- 自分のタスクを作成できる
- 自分のタスクの進捗状況を把握・記録できる
- これにより、効率的なタスク管理を可能にする

## 機能要件
### ユーザー視点でできる機能
- アカウント管理
	- アカウント作成
		- ユーザー名、パスワード、メールアドレスを入力
		- メール認証を行う
			- メールにてOTPを送信
			- サイト内のOTP入力欄にOTPを入力する
			- OTP有効期限内（5分間）は、作成予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または有効期限切れまで排他維持する
	- アカウント編集
		- ログイン後の画面からのみ可能
		- ユーザ名の変更
		- メールアドレスの変更
			- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
			- 変更確定と同時に、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、新メールアドレスでの再度ログインを要求する
			- 変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する
			- 変更先メールアドレスが既に他ユーザーに登録済みの場合は、メールアドレスの登録有無を秘匿するため、実際にはOTPを発行せずダミーOTP入力画面へ遷移する
			- 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
			- メール認証未完了の「変更手続き中」状態においても、ログイン識別子は変更前の旧メールアドレスが維持される
			- OTP有効期限内（5分間）は、変更先予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または期限切れまで排他維持する
	- アカウントの削除
		- ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要)
		- アカウント本体は論理削除、ログインセッションは物理削除とする
		- 論理削除後の登録メールアドレスでの再登録は可能
			- 再登録の際は自動付与されるUIDが異なるため同名のユーザ名などでも問題なく登録できる
		- アカウント論理削除に伴い、所有するタスクデータおよび関連データは即座にDBから物理削除する
	- パスワード変更
		- ログイン後のみ可能
		- 既存のパスワードを知っていれば変更できる（5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト）
		- 変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
- ログイン関係
	- ログイン
		- メールアドレス（ユーザー名ではない）とパスワードでログイン
	- ログアウト
	- パスワードリセット
		- パスワードリセットは、メール認証で行う
			- メールアドレスを持っている人間を本人とする
		- メールにてOTPを送信
		- サイト内のOTP入力欄にOTPを入力する
		- OTP検証成功時に当該OTPセッションのステータスを「検証済み」に変更し、そこから仮セッションの有効期限を15分間とする
		- 変更後パスワードを入力後、新パスワードを設定完了すると同時に当該パスワードリセット用OTP/仮セッションを直ちに失効・物理削除し、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
- タスク管理
	- タスク作成
		- タスク名（前後の空白文字［半角・全角スペース、タブ、改行］を除去［トリム］した上で1〜100文字必須。空白文字のみの入力はバリデーションエラーとして拒否する）
		- コメント（前後の空白文字をトリムして保持、0〜1000文字、任意）
		- 優先度（高、中、低、初期値：中）
		- 締切日時（任意）
		- 初期ステータスは「未着手」
	- タスク編集（タスクの名前、コメント等）
		- タスクの名前変更（前後の空白文字をトリムした上で1〜100文字必須。空白文字のみの入力は拒否する）
		- タスクの優先度変更（高、中、低）
		- 締切日時の変更・解除
		- コメントの変更（前後の空白文字をトリムして保持、0〜1000文字）
	- タスク状態更新（未着手、進行中、完了）
	- タスク削除
		- ユーザー操作によるタスクの削除は物理削除とする
	- タスクピン止め状態更新
	- タスク表示
		- 優先タスク表示（優先度：高のタスクを表示）
		- 締切間近タスク表示
			- 対象ステータス: 「未着手」「進行中」のタスクのみ（「完了」タスクは除外）
			- 対象時間範囲: 締切日時が現在時刻から72時間以内、または締切日時を過ぎた未完了タスク（締切日時 <= 現在時刻 + 72時間）
		- ピン止めタスク表示
		- 一覧表示
			- 並び順（デフォルトソート）:
				1. ピン留めされているタスクを最上部に優先表示
				2. 締切日時が設定されているタスクを締切日の近い順（昇順）で表示
				3. 締切日時が未設定または同日のタスクは作成日時の新しい順（降順）で表示
			- ページネーション: 1ページあたり20件表示
			- タスク検索（and検索）
				- キーワード検索（タスク名・コメント）は、入力された検索文字列の前後の空白文字を自動的に除去（トリム）し、英大文字・小文字を区別しない部分一致検索（Case-Insensitive）を行う
				- タスク名
					- 含むものを検索
				- 優先度
					- 完全一致（高、中、低）
				- 締切日
					- 指定日当日までの締め切り（〜指定日 23:59:59 JST）に該当する締切日時を持つタスクを検索。未設定（NULL）のタスクは除外する。未指定の場合は締切日による絞り込みを行わない。
				- タスクステータス
					- 完全一致（未着手、進行中、完了）
				- コメント
					- 含むものを検索
		- カレンダー表示
			- 締切日時が設定されている全ステータス（「未着手」「進行中」「完了」）のタスクについて、日本標準時（JST）における日付（YYYY-MM-DD）のセル上に配置して表示する
			- 「完了」ステータスのタスクは、視覚的に区別（文字の打消し線やグレーアウト表示等）して表示する
			- カレンダー画面上に「完了タスクを含める / 除外する」の表示切り替えフィルタを提供する

- サーバー異常時の管理者へのメール通知(管理者用のメーリングリストを作成)は送信しない
	- 送信する場合の検討メモ
		- プログラムエラー発生時
		- ハードウェアのメトリクス
			- CPU使用率
			- メモリ使用量
			- データベース容量
- 定期バックアップは一旦とらないことにする
### セキュリティ
- 不正アクセス対策
	- 本人以外は、そのアカウントの情報を見られない
		- 登録されているメールアドレスにアクセスできる人を本人とする
	- https通信
	- ログイン認証のセッション期限は1ヶ月とする（APIアクセスごとに自動延長される Sliding Expiration 方式）
	- 論理削除アカウントでのログイン試行時は、一般的な「メールアドレスまたはパスワードが正しくありません」として認証を拒否し、論理削除の有無を秘匿する（応答遅延 1s±0.1s）
- ログイン認証
	- 同一メールアドレスまたは同一IPアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、30分間ロックアウトする
	- 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
	- ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする
	- OTPのセッション期限 5分 (入力制限5回超過または有効期限切れで無効化)
- アカウント新規作成
	- アカウント登録時にすでに有効な他ユーザー（未削除アカウント）として登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- OTP有効期限内（5分間）は、新規登録手続き中（未認証）のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または期限切れまで排他維持する
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- パスワードリセット
	- パスワードリセットのメールアドレス入力にて登録されていない（有効な他ユーザーとして存在しない）メールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- アカウント編集（メールアドレス変更）
	- 変更先にすでに有効な他ユーザー（未削除アカウント）で登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
	- 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
	- ダミーOTP入力画面での誤入力検証は常に失敗扱い（応答速度1s±0.1s）とし、メールアドレスの登録有無を秘匿する
- パスワード変更時の，「現在のパスワード」認証
	- 5回連続で現在のパスワードの認証に失敗したら、セッションを破棄してログイン画面に戻す
- OTP要件
	- OTPは英数字8桁，英数字は大文字小文字を区別しない
	- 有効期限: 発行から5分間
	- 誤入力制限: 1つのOTPに対して最大5回まで入力試行可能
	- 5回失敗時の挙動:
		- パスワードリセット OTPの場合
			- 有効な登録済みメールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
			- 未登録（存在しない）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
		- 新規登録 OTPの場合
			- 新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
			- 重複（登録済み）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
		- アカウント編集（メールアドレス変更） OTPの場合
			- 未使用の新規メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
			- 他ユーザーに登録済みの重複メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信（初回発行または直前の再送信）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する
	- 再送処理のターンアラウンドタイムは 1±0.1s とする
- 使用ライブラリの脆弱性発見
	- 定期的に npm audit, govulncheck
- ログ管理
	- ログイン情報
		- 日時、ユーザーID (UID)、メールアドレス、IPアドレス、ログイン成否
	- DBへのアクセスログ
		- 日時、ユーザーID (UID)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
	- メール認証ログ
		- 日時、ユーザーID (UID、未登録・未ログイン時は null)、対象メールアドレス、認証種別（新規登録 / パスワードリセット / メールアドレス変更）、アクセス元IPアドレス、処理イベント種別（OTP発行 / 検証成功 / 検証失敗 / 手動再送依頼 / 5回失敗時自動処理）、成否、ダミー処理区分（実処理 / ダミー表示）
	- ログ保持・パージ方針
		- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
		- DBへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
- 脆弱性対策
	- 入力文字列のエスケープ処理
	- CSRF対策 → CSRFトークンの導入
	- 開発後に一度脆弱性診断をおこなう
- ユーザ名要件
	- 2文字以上20文字以内
	- 英小大文字、数字
	- 同名のユーザー名登録は可（ログイン識別子にはメールアドレスを使用するため）
- パスワード要件
	- 8文字以上128文字以下
	- 英大文字、英小文字、数字、記号( `!"#$%&'()=-~^|\{}[]+;:*_/?.>,<` )の4種類のうち3種類以上を含むこと
	- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する（いずれも大文字・小文字を区別せず［Case-Insensitive］に部分一致判定を行う）
- OTP認証およびログイン処理における応答速度の調整（遅延制御）
	- 失敗またはダミー処理の場合は、一律1s±0.1sの範囲で応答速度を調整する
	- 認証・検証成功時は、人工的な遅延を挟まず即時にレスポンスを返し次の処理に移行する
- メールアドレス要件
  - 入力されたメールアドレス（新規登録、ログイン、メールアドレス変更、パスワードリセット等の全機能）は、前後の空白文字（半角・全角スペース、タブ、改行）を自動的に除去（トリム）して処理する
  - メールアドレスはシステム内部（登録・ログイン・重複判定・認証処理等）で一律小文字（`toLowerCase()`）に正規化して保持・比較し、Case-Insensitive な一意性を保証する
  - 有効な他ユーザ（未削除アカウント）との重複なし
- セッション管理
  - トークンではなくセッションによって管理
  - OTPセッション
    - 有効期限 5分（ただしパスワードリセットにおけるOTP検証成功時はステータスを「検証済み」に変更し、そこから有効期限を15分間とする）
    - 有効期限切れまたは無効化・使用済みとなったOTPセッションレコードは、新パスワード設定完了時等に直ちに物理削除するほか、Cronジョブ（15分ごと / Cron: `*/15 * * * *` JST）にてDBから一括物理削除する
  - ログインセッション
    - 有効期限 43200分(1ヶ月)
    - ユーザーがログイン中にリクエスト（API呼び出し）を行うたびに、セッションの有効期限をアクセス時刻から43200分（1ヶ月）後に自動更新（Sliding Expiration）する。最後のアクセスから43200分経過したセッションを無効（期限切れ）とする
    - 有効期限切れ（無効化済み）のセッションは、日次Cronジョブ（毎日 00:00 JST / Cron: `0 0 * * *`）にてDBから物理削除する
