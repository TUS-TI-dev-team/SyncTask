# 01. アカウント・認証機能要件

本ドキュメントでは、SyncTaskにおけるアカウント管理および認証（ログイン・ログアウト・パスワードリセット等）に関する機能要件・バリデーション仕様を定義します。

---

## 1. アカウント属性・共通バリデーション要件

### 1.1 ユーザー名要件
| 項目 | 仕様・制約 |
| :--- | :--- |
| **文字数** | 2文字以上 20文字以内 |
| **使用可能文字** | 半角英大文字、半角英小文字、半角数字（`a-z`, `A-Z`, `0-9`） |
| **重複登録** | **許可**（ログイン識別子にはメールアドレスを使用するため、同名のユーザー名が存在しても可） |

### 1.2 メールアドレス要件
| 項目 | 仕様・制約 |
| :--- | :--- |
| **文字数** | 255文字以下 |
| **トリム処理** | 入力された文字列の前後の空白文字（半角スペース、全角スペース、タブ、改行）を自動除去 |
| **正規化** | システム内部（登録・ログイン・重複判定・認証処理等）で一律小文字（`toLowerCase()`）に正規化して保持・比較 |
| **一意性** | 有効な他ユーザー（未削除アカウント）との重複は不可（Case-Insensitive な一意性を保証） |

### 1.3 パスワード要件
| 項目 | 仕様・制約 |
| :--- | :--- |
| **文字数** | 8文字以上 128文字以下 |
| **使用可能文字種** | 以下の4種類中、**3種類以上** を含むこと<br>1. 半角英大文字 (`A-Z`)<br>2. 半角英小文字 (`a-z`)<br>3. 半角数字 (`0-9`)<br>4. 記号（ASCII印字可能半角記号全32種類: `! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ \ ] ^ _ ` { | } ~`） |
| **禁止パターン** | ・ユーザー名文字列を含むパスワードの設定を禁止（4文字以上の場合、Case-Insensitive）<br>・メールアドレスの `@` より前のローカル部文字列を含むパスワードの設定を禁止（4文字以上の場合、Case-Insensitive） |
| **保存方式** | ソルト（Salt）を用いた安全なハッシュ化を行い保存 |

## 2. アカウント管理機能

### 2.1 アカウント作成（新規登録）
1. **入力情報**: ユーザー名、メールアドレス、パスワード。
2. **事前バリデーション**:
   - フォーム送信時（OTP生成・メール送信の前）に、バックエンドにてユーザー名・メールアドレス・パスワードの入力値バリデーションを一括実施する。
   - バリデーションエラーがある場合はOTPを発行せずエラーを表示する。
3. **メール認証（OTP発行）**:
   - 入力されたメールアドレス宛にOTPを送信する。
   - **メールアドレス重複時の処理**: 既に有効な他ユーザー（未削除アカウント）として登録済みのメールアドレスが入力された場合は、メールアドレスの登録有無を秘匿するため、**実際にはOTPを発行せずダミーOTP入力画面へ遷移**させる（詳細は [03_security_and_system.md](file:///C:/Users/kazuh/Programming/repos/SyncTask/docs/req-def/requirements/03_security_and_system.md) 参照）。
   - **排他制御**: OTPセッション有効期間中（全体最大15分間）は、作成予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または全体有効期限切れまで排他維持する。
   - **既存セッションの画面制御**: クライアントが有効な新規登録用OTPセッションを保持している場合はOTP入力画面へ復帰し、登録情報送信APIを再実行しない。APIが再度呼ばれた場合は既存セッションを更新せず、ダミーOTPセッションを新規作成して同一形式の応答を返す。
4. **認証確定・自動ログイン**:
   - サイト内の入力欄に正しいOTPを入力し認証が成功した時点で、アカウント作成を確定する。
   - アカウント確定と同時に、自動的に新しいログインセッションを発行してログイン状態とし、ホーム画面へ遷移する。
   - ブラウザ上に既存の古いログインセッションが存在する場合は無効化（DBから物理削除）・新規発行し、複数アカウントへの同時重複ログイン状態を防止する。
5. **有効期限切れ処理**:
   - OTPのセッション有効期限（初回発行から15分）が切れた場合は、OTPセッションをDBから物理削除し、アカウント作成用画面へリダイレクトさせる。

### 2.2 アカウント編集
ログイン後の画面からのみ実行可能。

#### 2.2.1 ユーザー名の変更
- **変更手順**: 変更後のユーザー名を入力し送信。
- **入力検証**: ユーザー名要件に基づきバリデーションを実施。変更先が現在設定中のユーザー名と同一の場合は「現在のユーザー名と同じです」とエラー表示し拒否する。
- **パスワード再認証**: 不要（入力・送信で即時変更）。
- **セッション維持**: ユーザー名変更完了後も現在のログインセッションは維持され、画面上の表示名が即座に更新される。

#### 2.2.2 メールアドレスの変更
- **変更手順**: 変更先の新メールアドレスを入力し送信。
- **事前バリデーション**: フォーム送信時（OTP生成・メール送信の前）にバックエンドにて入力値バリデーションを一括実施。
- **同一アドレスチェック**: 変更先が現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する。
- **重複秘匿（ダミー処理）**: 変更先メールアドレスが既に他ユーザーに登録済みの場合は、登録有無を秘匿するためOTPを発行せずダミーOTP入力画面へ遷移する。
- **メール認証（OTP）**: 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する。
- **排他制御**: OTPセッション有効期間中（全体最大15分間）は、変更先予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または全体有効期限切れまで排他維持する。
- **既存セッションの画面制御**: クライアントが有効なメール変更用OTPセッションを保持している場合はOTP入力画面へ復帰し、OTP要求APIを再実行しない。APIが再度呼ばれた場合は既存セッションを更新せず、ダミーOTPセッションを新規作成する。
- **変更手続き中の識別子**: メール認証未完了の状態においては、ログイン識別子は変更前の旧メールアドレスが維持される。
- **変更確定時の処理**:
  - 変更確定と同時に、旧メールアドレス宛に変更完了通知メールを送信する。
  - 該当ユーザーの**すべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）**し、新メールアドレスでの再ログインを要求する。
- **有効期限切れ処理**: OTPセッション有効期限（初回発行から15分）切れ時は、OTPセッションを物理削除しアカウント編集画面へリダイレクトさせる。

#### 2.2.3 パスワード変更
- **変更手順**: ログイン後の画面から、現在のパスワードおよび変更後パスワードを入力して実行。
- **現在のパスワード再認証**: 既存のパスワードを知っている本人のみ変更可能。
- **連続失敗制限**: 再認証にて**5回連続で現在のパスワード認証に失敗**した場合は、ログインセッションを直ちに破棄（物理削除）してログイン画面にリダイレクトする。
- **変更確定時の処理**: 変更後パスワードを設定完了後、該当ユーザーの**すべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）**し、新しいパスワードでの再ログインを要求する。

### 2.3 アカウント削除
- **実行条件**: ログイン後の画面からのみ実行可能。
- **確認・再認証**: 削除確認ダイアログの表示に加え、**現在のパスワードによる再認証**を必須とする。
- **連続失敗制限**: 再認証にて**5回連続で現在のパスワード認証に失敗**した場合は、ログインセッションを直ちに破棄（物理削除）してログイン画面にリダイレクトする。
- **削除処理**:
  - アカウント本体は**論理削除**とする。
  - 該当ユーザーが所有するタスクデータおよび関連データは**即座にDBから物理削除**する。
  - 該当ユーザーの**すべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（DBから物理削除）**し、クライアント側のCookieも消去してログイン画面へリダイレクトする。
- **論理削除後の再登録**:
  - 論理削除されたアカウントのメールアドレスを用いた再登録は可能。
  - 再登録時は新しいUIDが自動付与されるため、過去と同名のユーザー名等であっても問題なく登録できる。

## 3. 認証機能

### 3.1 ログイン
- **認証情報**: メールアドレス（ユーザー名ではない）およびパスワード。
- **論理削除アカウントの扱い**: 論理削除済みのアカウント情報でログインが試行された場合は、論理削除の有無を秘匿するため、通常の認証失敗と同様に「メールアドレスまたはパスワードが正しくありません」とエラー応答し拒否する（応答遅延 1s±0.1s）。
- **連続失敗制御**:
  - 同一メールアドレスに対して5回連続で失敗した場合、アカウントロックアウト（30分間）を適用する。
  - 同一IPアドレスからの短時間の大量失敗に対してレートリミットを適用する（詳細は [03_security_and_system.md](file:///C:/Users/kazuh/Programming/repos/SyncTask/docs/req-def/requirements/03_security_and_system.md) 参照）。

### 3.2 ログアウト
- **実行条件**: ログイン後の画面からのみ実行可能（`POST` リクエスト + CSRFトークン検証必須）。
- **セッション破棄**:
  - 操作中の端末のログインセッションレコードのみをDBから即座に物理削除する（他端末・他ブラウザのセッションは維持する）。
  - クライアント側のセッションCookieを即座に無効化（消去）し、ログイン画面にリダイレクトする。
- **冪等性の確保**: セッションが既に無効化または期限切れの状態でログアウトが実行された場合もエラーとせず、Cookieを消去してログイン画面へリダイレクトする。

### 3.3 パスワードリセット
ログインできない状態のユーザーが、登録メールアドレスへのメール認証を用いてパスワードを再設定する機能。

1. **本人性確認方針**: 登録されているメールアドレスにアクセス可能な人物を本人とみなす。
2. **事前バリデーション**: フォーム送信時（OTP生成・メール送信前）に入力値バリデーションを一括実施。
3. **メール認証（OTP）**:
   - メールアドレス宛にOTPを送信する。
   - **未登録メールアドレスの扱い**: システムに登録されていない（有効な他ユーザーとして存在しない）メールアドレスが入力された場合、登録有無を秘匿するため**実際にはOTPを発行せずダミーOTP入力画面へ遷移**させる。
   - **既存セッションの画面制御**: クライアントが有効なパスワードリセット用OTPセッションを保持している場合はOTP入力画面へ復帰し、OTP要求APIを再実行しない。APIが再度呼ばれた場合は既存セッションを更新せず、ダミーOTPセッションを新規作成する。
4. **メール送信失敗**:
   - 初回送信または再送に失敗したOTPセッションは再送可能状態とし、ユーザーへ送信失敗を通知して同じセッションIDによる再送を許可する。
   - 送信成功時は連続送信失敗回数を0へ戻す。1セッションで初回送信を含め5回連続して送信に失敗した場合は、補償処理で対象OTPセッションを物理削除し、手続きを入力画面からやり直させる。
5. **OTP検証とパスワード再設定権限**:
   - サイト内の入力欄にOTPを入力する。
   - OTP検証成功時、当該OTPセッションのステータスを「検証済み（verified）」に変更し、そこから**15分間有効なパスワードリセット権限（仮セッション状態）**を付与する。
   - **仮セッション状態の権限**: 新パスワード設定APIへのアクセスのみを許可する制限付き状態とし、タスク操作等の通常ログイン必須APIへのアクセス権限は付与しない（専用の仮セッションCookie等は発行せず、検証済み `otp_session_id` で認可を制御）。
6. **パスワード再設定完了**:
   - 変更後パスワードを入力し、パスワード要件のバリデーションを通過して設定を完了する。
   - 新パスワード設定完了と同時に、当該パスワードリセット用OTPセッションを直ちにDBから物理削除（クライアント側で保持しているOTPセッションIDも破棄）する。
   - 該当ユーザーの**すべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）**し、新パスワードでの再ログインを要求する。
