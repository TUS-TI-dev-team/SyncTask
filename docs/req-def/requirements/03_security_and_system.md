# 03. セキュリティ・システム共通要件

本ドキュメントでは、SyncTaskにおけるOTP仕様、認証セキュリティ（ロックアウト・レートリミット・列挙対策）、セッション管理、脆弱性対策、および監査ログ管理・保持ポリシーについて定義します。

---

## 1. OTP（ワンタイムパスワード）共通仕様

新規登録、メールアドレス変更、パスワードリセットの各メール認証処理において共通で適用される仕様です。

### 1.1 生成・検証仕様
| 項目 | 仕様 |
| :--- | :--- |
| **桁数** | 英数字 **8桁**（大文字・小文字を区別しない） |
| **使用可能文字（26文字）** | 誤読・混同防止のため対象文字を除外した英大文字・数字よりランダム生成<br>`A, C, D, E, F, G, H, J, K, L, M, N, P, Q, R, T, U, V, W, X, Y, 3, 4, 6, 7, 9` |
| **除外文字（混同防止）** | `O`, `0`（オー/ゼロ）、`I`, `1`（アイ/イチ）、`S`, `5`（エス/ゴ）、`Z`, `2`（ゼット/ニ）、`B`, `8`（ビー/ハチ） |
| **入力値検証** | 前後の空白文字を除去（トリム）し、大文字に正規化（`toUpperCase()`）した上で照合 |
| **個別OTP有効期限** | 発行から **5分間**（再発行時は新OTPの有効期限を新たに5分として測定） |
| **全体セッション有効期限** | 再送信を行っても、1回の手続きにおけるセッションおよび排他ロックの全体最大有効期限は **初回発行から15分間**。15分経過時は失効し画面をリダイレクト |

### 1.2 誤入力制限および再送信挙動
- **誤入力制限**: 1つのOTPコードに対して最大 **5回** まで入力試行可能。
- **5回連続失敗時の挙動**:
  - **実在/新規メールアドレス（通常処理）**: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する。
  - **未登録/重複メールアドレス（ダミー処理）**: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）。
- **手動再送依頼**:
  - 画面上の「OTPを再送信する」ボタン押下時も上記と同様の判定を行う。
  - **クールダウン期間**: 直前の送信（初回発行、手動再送、5回失敗時自動再送のいずれか）から **60秒間** は再送ボタンを非活性化（カウントダウン表示）として連投を制限する。
  - 再送信回数に上限は設けないが、初回発行から15分の全体有効期限が優先される。

### 1.3 応答遅延制御（タイミング攻撃対策）
- 認証失敗時、ダミーOTP処理時、および再送処理時は、処理時間を一律 **`1s ± 0.1s`**（1000ミリ秒 ± 100ミリ秒）に調整する。
- 認証・検証成功時は、人工的な遅延を挟まず即時にレスポンスを返却する。

## 2. 認証・アクセスセキュリティ

### 2.1 ログインロックアウト（メールアドレス単位）
- **判定基準**: 同一メールアドレスに対して、15分間のインターバルを挟まずに **5回連続** でパスワード認証に失敗した場合。
- **ロックアウト期間**: 初回ロック発生から **30分間** 該当メールアドレスへのログイン試行を遮断。
- **解除・リセット条件**:
  - 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセット。
  - ロックアウト期間は初回発生から30分経過時点で自動解除（固定時間。ロックアウト中の追加試行による期間延長は行わない＝永久ロックDoS防止）。
- **ロックアウト中の応答**: 正しいパスワードが入力された場合であっても認証拒否（応答遅延 `1s ± 0.1s`）。

### 2.2 IPアドレス単位レートリミット（パスワードスプレー対策）
- **判定基準**: 同一IPアドレスから5分間のインターバルを挟まずに累計 **30回以上** のログイン認証失敗が発生した場合。
- **遮断措置**: 該当IPアドレスからのログインAPIリクエストを一律 **15分間** 一時遮断（HTTP `429 Too Many Requests`、応答遅延 `1s ± 0.1s`）。

### 2.3 メールアドレス存在秘匿（ユーザー列挙対策）
- 新規登録、パスワードリセット、メールアドレス変更において、重複アドレスや未登録アドレスが入力された場合でも画面遷移・メッセージ・応答速度（`1s ± 0.1s`）を同一にし、登録の有無を攻撃者に推測させない。

### 2.4 ログイン後再認証の制限
- アカウント削除時およびパスワード変更時、現在のパスワード認証に **5回連続で失敗** した場合、セッションを即座に破棄（物理削除）してログイン画面へリダイレクトする。

### 2.5 通信・脆弱性対策
- **通信暗号化**: 常時 HTTPS 通信を必須とする。
- **XSS対策**: 入力文字列の適切なエスケープ処理を実施。
- **CSRF対策**: 状態変更リクエスト（ログアウトや各種更新等）に CSRF トークンを導入・検証（詳細仕様は設計フェーズにて定義）。
- **脆弱性診断**: 開発完了後に一度脆弱性診断を実施。
- **ライブラリ脆弱性対応**: 使用ライブラリの脆弱性管理・更新方針を設計段階にて検討。

## 3. セッション管理

本システムではトークン方式ではなく、**データベースおよびCookieを用いたサーバーサイドセッション**で管理する。

### 3.1 ログインセッション
| 項目 | 仕様 |
| :--- | :--- |
| **有効期間** | **43200分（30日間）** |
| **延長方式** | **Sliding Expiration**: ユーザーがログイン中にAPIアクセスを行うたびに、セッション有効期限をアクセス時刻から30日後に自動更新。最後のアクセスから30日経過したセッションを無効化 |
| **Cookie属性** | ・`HttpOnly`: JavaScript（`document.cookie`）からの読み取りを禁止<br>・`Secure`: HTTPS通信時のみ送信（開発環境を除き常時有効）<br>・`SameSite=Lax`: サードパーティコンテキストでの不要なCookie送信を制限 |
| **Cookie名** | 標準的な識別名（例: `sync_task_sid`） |
| **パージ（クリーンアップ）** | 日次Cronジョブ（毎日 **00:00 JST** / Cron: `0 0 * * *`）にて有効期限切れセッションをDBから物理削除 |

### 3.2 OTPセッション・仮セッション
| 項目 | 仕様 |
| :--- | :--- |
| **有効期間** | セッション発行から最大 **15分間**（パスワードリセットにおけるOTP検証成功後の仮セッションも検証成功から15分間） |
| **権限** | パスワードリセット仮セッションは新パスワード設定APIへのアクセスのみ許可 |
| **パージ（クリーンアップ）** | 新パスワード設定時等の処理完了時に直ちに物理削除するほか、Cronジョブ（**15分ごと** / Cron: `*/15 * * * *` JST）にて期限切れレコードを一括物理削除 |

## 4. ログ管理・保持ポリシー

監査およびセキュリティ監視のため、以下のログを記録・管理する。

### 4.1 記録対象ログ一覧

| ログ種別 | 記録項目 | 保持期間 | パージCronスケジュール |
| :--- | :--- | :--- | :--- |
| **ログイン情報ログ** | 日時, ユーザーID（UID, 未登録時null）, メールアドレス, IPアドレス, ログイン成否, セッション利用の認証か | **1年間（365日）** | 毎日 **02:00 JST**<br>(`0 2 * * *`) |
| **メール認証ログ** | 日時, ユーザーID（UID, 未登録時null）, 対象メールアドレス, 認証種別（新規登録/パスワードリセット/メールアドレス変更）, アクセス元IPアドレス, 処理イベント種別（OTP発行/検証成功/検証失敗/手動再送依頼/5回失敗時自動処理/有効期限切れ失効）, 成否, ダミー処理区分（実処理/ダミー表示） | **1年間（365日）** | 毎日 **02:00 JST**<br>(`0 2 * * *`) |
| **APIアクセスログ** | 日時, ユーザーID（UID, 未登録・未ログイン時null）, アクセス元IPアドレス, エンドポイント, 閲覧・操作対象リソースID | **90日間** | 毎日 **01:00 JST**<br>(`0 1 * * *`) |

※ 保持期限を過ぎたレコードは、各CronジョブによってDBから物理削除される。
