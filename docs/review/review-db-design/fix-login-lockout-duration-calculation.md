# LOGIN_LOCK_UNTILのロック期間起算点記述の誤り（初回失敗 vs ロックアウト発生時）

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-17 14:05:00
- **Target Files**:
  - [database_design.md](docs/design/database_design.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
`LOGIN_ACCOUNT` テーブルの `LOGIN_LOCK_UNTIL` カラムの備考に「5回失敗で初回失敗から30分間ロック」と記載されていますが、要件定義書に定められている「5回失敗時に30分間ロックアウト」「初回ロックアウト発生時刻から30分間」という仕様と矛盾・誤認を招く記述となっています。

## 2. 詳細な指摘内容
- `docs/design/database_design.md` の23行目において以下のように定義されています：
  > `LOGIN_LOCK_UNTIL` | `TIMESTAMPTZ` | `5回失敗で初回失敗から30分間ロック`
- 一方で、`docs/req-def/requirements.md` の194行目および197行目では以下のように定義されています：
  > 194: メールアドレス単位ロックアウト: 同一メールアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、該当メールアドレスに対するログイン試行を30分間ロックアウトする
  > 197: ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする。なお、ロックアウト期間は初回ロックアウト発生時刻から30分経過時点で自動解除（固定時間）とし、ロックアウト中の追加試行による期間延長は行わない（永久ロックDoS防止）
- 「初回失敗から30分間」と解釈・実装してしまうと、例えば1回目失敗から14分後に5回目の失敗に達した場合に、残り16分間しかロックアウトされず、要件である「5回連続失敗時に30分間ロックアウトする」を満たせなくなります。
- 要件定義書が意図している「初回ロックアウト発生時刻」とは、「ロックアウト期間中に更なる試行があってもロック期限を再延長しない（固定30分）」という意味であり、起算点は5回目の失敗（ロックアウト発生時）です。

## 3. 推奨される修正案
- `LOGIN_ACCOUNT` テーブルの `LOGIN_LOCK_UNTIL` の備考を以下のように修正してください：
  - 「5回連続失敗時にロックアウト発生時刻から30分後（`NOW() + INTERVAL '30 minutes'`）を設定。ロックアウト期間中の追加試行では延長しない（固定30分）」
- 併せて、直近15分間のカウント判定において、最後の失敗日時（`LOGIN_LAST_FAILED_AT`）から15分超過時のリセット判定ロジック（または初回失敗日時カラム `LOGIN_FIRST_FAILED_AT` の追加要否）を実装方針として明確化することを推奨します。

### 実施した修正内容
- `docs/design/database_design.md` の `LOGIN_ACCOUNT` テーブル定義における `LOGIN_LOCK_UNTIL` の備考欄を修正しました。
- ロック期間の起算点を「初回失敗から」ではなく「5回連続失敗時にロックアウト発生時刻から30分後（`NOW() + INTERVAL '30 minutes'`）を設定。ロック中の追加試行では延長しない（固定30分）」と明記し、要件定義書（`requirements.md`）の仕様と整合させました。
