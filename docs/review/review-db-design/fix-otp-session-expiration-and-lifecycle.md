# OTP_SESSIONテーブルの有効期限定義およびライフサイクル仕様の不整合

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-17 12:45:00
- **Target Files**:
  - [database_design.md](docs/design/database_design.md)
  - [requirements.md](docs/req-def/requirements.md)
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
`OTP_SESSION` テーブルの `EXPIRES_AT` カラムの備考に「5分 (検証成功後も5分間有効)」と記載されていますが、要件定義書および画面設計書の「検証成功後15分間有効」「全体最大有効期限15分間」という定義と矛盾しています。

## 2. 詳細な指摘内容
- `docs/design/database_design.md` の84行目において、`EXPIRES_AT` の備考が `5分 (検証成功後も5分間有効)` と記載されています。
- 一方で、`docs/req-def/requirements.md` の74行目、216行目、264行目および `docs/design/screen_design.md` の12行目では以下のように定義されています：
  > 74: OTP検証成功時に当該OTPセッションのステータスを「検証済み」に変更し、そこから仮セッションの有効期限を15分間とする
  > 216: 有効期限: 発行から5分間（ただし再送信を行っても、1回の手続きにおけるセッションおよび排他ロックの全体最大有効期限は初回発行から15分間とする。15分経過時はセッションおよび排他ロックを失効して初期画面へ戻す）
  > 264: 有効期限 5分（ただし再送時を含む1回の手続きにおける全体最大有効期限は初回発行から15分間。またパスワードリセットにおけるOTP検証成功時はステータスを「検証済み」に変更し、そこから有効期限を15分間とする）
  > `screen_design.md` 12: 15分以内に操作が完了していない場合はセッション切れとしてパスワードリセット/メールアドレス入力画面へ戻るよう表示する
- 単発のOTP有効期限（5分）と、検証成功後の新パスワード設定用仮セッション有効期限（15分）、および再送信を含む全体最大有効期限（初回発行から15分）の扱いが設計書内で混同・不整合となっています。

## 3. 推奨される修正案
- `OTP_SESSION` テーブルの `EXPIRES_AT` の説明を修正し、OTP発行時は5分後、パスワードリセットのOTP検証成功（`STATUS = verified`）時はその時点から15分後に `EXPIRES_AT` を延長・更新する旨を明記してください。
- また、初回発行から15分の全体最大有効期限の管理や、手動/自動再送時の60秒クールダウン判定を正確に行うため、初回発行日時（`SESSION_EXPIRES_AT` または `FIRST_ISSUED_AT`）や直前送信日時（`LAST_SENT_AT`）などのカラム追加・設計を検討・反映してください。

## 修正完了報告

- **Resolved At**: 2026-08-17 13:22:30
- **Status**: Resolved

### 実施した修正内容
`OTP_SESSION` テーブルに全体最大有効期限（`MAX_EXPIRES_AT`: 初回発行から15分）および直前送信日時（`LAST_SENT_AT`: 60秒クールダウン判定用）のカラムを追加し、`EXPIRES_AT` の備考を「発行から5分（パスワードリセットの検証成功時はその時点から15分間に延長）」に修正しました。また、パージ方針（確定時即時削除、期限切れは15分ごとのCronで物理削除）を追記しました。
