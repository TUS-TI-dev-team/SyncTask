# パスワード変更完了後のセッション一括無効化およびログイン画面リダイレクトの画面遷移不整合

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-14 20:45:00
- **Target Files**:
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
要件定義書（`docs/req-def/requirements.md`）ではパスワード変更完了時に全ログインセッションを一括無効化（物理削除）してログイン画面へリダイレクトする仕様となっていますが、`screen_design.md` の「パスワード変更画面」の遷移先が「プロフィール表示画面」となっており画面遷移の不整合が発生しています。

## 2. 詳細な指摘内容
1. `requirements.md`（機能要件 パスワード変更 Line 60）には以下のように規定されています：
   - 「変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する」
2. `screen_design.md` の「パスワード変更画面」(Line 41) では：
   - 役割・機能欄に「5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト」と失敗時の挙動は追記されたものの、正常完了時の遷移先が「プロフィール表示画面」のままとなっています。
   - パスワード変更確定時に全セッションが即座に物理削除されるため、セッション切れとなりログイン画面へリダイレクトして再ログインを求める必要がありますが、この仕様が画面遷移に反映されていません。

## 3. 推奨される修正案
1. 「パスワード変更画面」(Line 41) の遷移先を「変更完了・5回連続失敗：ログイン画面」「キャンセル：プロフィール表示画面」に修正してください。
2. 役割・機能欄に「パスワード変更完了時、全ログインセッションを一括物理削除してログイン画面へリダイレクトし再ログインを要求する」旨を明記してください。
