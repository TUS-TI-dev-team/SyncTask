# メールアドレス変更完了後のセッション一括無効化およびログイン画面リダイレクトの画面遷移不整合

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-14 20:28:00
- **Target Files**:
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
要件定義書（`docs/req-def/requirements.md`）ではメールアドレス変更の認証（OTP完了）確定時に全ログインセッションを物理削除してログイン画面にリダイレクトし、再度ログインを要求する仕様となっていますが、`screen_design.md` ではOTP入力後の遷移先が「プロフィール表示画面」になっており、画面遷移フローの不整合が発生しています。

## 2. 詳細な指摘内容
1. `requirements.md`（機能要件 メールアドレスの変更 Line 45）では：
   - 「変更確定と同時に、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、新メールアドレスでの再度ログインを要求する」と定義されています。
2. `screen_design.md` の「アカウント関連/OTP入力画面」(Line 39) では：
   - 遷移先が「プロフィール表示画面」と記載されています。
   - このため、メールアドレス変更完了後に画面上でログイン画面へ強制リダイレクトされ再度ログインを行うという仕様が画面設計に反映されていません。

## 3. 推奨される修正案
1. 「アカウント関連/OTP入力画面」(Line 39) の遷移先を「ログイン画面」に修正してください。
2. 役割・機能または補足事項に、「OTP検証成功によるメールアドレス変更確定時、ログインセッションが一括無効化されるためログイン画面へ強制リダイレクトし、新メールアドレスでの再ログインを促す」旨の注記を追加してください。

## 修正完了報告

- **Status**: Resolved

### 実施した修正内容
`screen_design.md` の「アカウント関連/OTP入力画面」の遷移先を「ログイン画面」に修正し、OTP完了・メールアドレス変更確定時の全ログインセッション一括物理削除および再ログイン要求のフローを明記しました。
