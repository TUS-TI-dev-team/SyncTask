# アラート通知仕様の要件定義書との不整合

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-17 17:15:00
- **Target Files**:
  - [job_design.md](docs/design/job_design.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
`job_design.md` の「4-2. アラート通知」において、バッチ処理連続失敗時に「運用管理者通知用メーリングリスト/チャネル（`requirements.md` 運用・保守性要件）に通知を送信する」と記載されていますが、要件定義書（`requirements.md`）では「サーバー異常時の管理者へのメール通知は送信しない」と明確に規定されており、記述が矛盾しています。

## 2. 詳細な指摘内容
- 要件定義書（[requirements.md:L177](docs/req-def/requirements.md#L177)）の「非機能要件 > 運用・保守性」では以下のように明記されています：
  > サーバー異常時の管理者へのメール通知(管理者用のメーリングリストを作成)は送信しない
- しかし、[job_design.md:L96-98](docs/design/job_design.md#L96-L98) には以下のように記載されています：
  > ### 4-2. アラート通知
  > - バッチ処理が連続で失敗した場合、運用管理者通知用メーリングリスト/チャネル（`requirements.md` 運用・保守性要件）に通知を送信する。

要件定義書で「送信しない」と明記されているメーリングリストへの通知を、あたかも要件定義書で規定されているかのように参照して記述しているため、不整合となっています。

## 3. 推奨される修正案
要件定義書の非機能要件に合わせて、以下のいずれかの方法で設計書を修正してください：
1. 要件定義書通り、メール通知等の能動的アラート送信は行わず、失敗時はログ（ERRORレベル）への出力・記録に留める方針に修正する。
2. もし外部通知（Webhook / チャットツール等）を行う設計とする場合は、要件定義書との整合性を整理した上で、通知方式や設定値を明確に定義する（要件定義書側の改訂も検討）。

### 実施した修正内容
- 要件定義書（`docs/req-def/requirements.md` 非機能要件）の規定に合わせて、システムからの能動的なメール・メーリングリスト通知の記述を削除しました。
- ジョブ失敗時は JSON 構造化ログ（`ERROR` レベル）を出力・記録し、外部のログ監視・メトリクス監視基盤にて検知する設計方針（第5章 5-3）に改訂・統一しました。
