# ホーム画面における複数タスクビュー表示とページネーションUI仕様・状態管理の曖昧性

## 1. 問題の概要
画面設計書（`screen_design.md`）ではホーム画面に「優先タスク」「締切間近タスク」「ピン留めタスク」の3つの表示欄が同一画面内に並ぶ構成になっているが、ページネーション操作UIが単数形で「タスクリストの上下に配置する」と記載されており、各セクションごとに個別のページネーションUIとページ番号状態を持つのか、あるいは画面全体で1つのページネーションなのかが曖昧である。また、3つの表示欄を表示するためのAPIリクエスト仕様（並行取得か集約か）およびクライアントサイドでのページ制御仕様が未確定である。

## 2. 詳細な指摘内容
1. **画面設計書の構成要素とレイアウト定義の矛盾・曖昧さ**:
   - `docs/design/screen_design.md` の「ホーム画面」構成要素には以下のように記載されている：
     > 優先タスク一覧表示欄、締切間近タスク一覧表示欄、ピン留めタスク一覧表示欄、「完了タスク表示/非表示」切り替えトグル、ページネーション操作UI（前へ/次へボタン、ページ番号）、「タスク作成」ボタン
   - 補足（line 19）には「ページネーションUIはタスクリストの上下に配置する」とあるが、ホーム画面で3つのリストが同時に並ぶ場合、各リストごとに上下計6箇所のページネーションUIが存在するのか、それともリストの下部のみ（計3箇所）なのか、あるいは画面最上部・最下部（計2箇所）で何らかのページ送りを行うのかが明確でない。
2. **要件定義書のページネーション要件との整合性**:
   - `docs/req-def/requirements/02_task_management.md` 3.1 節では「優先タスク表示: 1ページ20件」「締切間近タスク表示: 1ページ20件」「ピン留めタスク表示: 1ページ20件」と、各ビューごとに独立したページネーション（20件）が規定されている。
3. **APIリクエストと状態管理の未定義**:
   - API設計書（`04_tasks.md`）には単一のビューを取得する `GET tasks?view_type=...` のみが定義されており、ホーム画面描画時にフロントエンドが `view_type=high_priority`, `view_type=near_deadline`, `view_type=pinned` の3つのAPIリクエストを個別に並行発行して取得する想定となっている。
   - ホーム画面において各セクションが独立してページ遷移を行う場合、フロントエンド側で3つの独立したタスクリスト配列およびページ番号状態（`page_priority`, `page_near_deadline`, `page_pinned`）を管理する必要があるが、画面設計書上でこのUI操作挙動（各欄内のページ送り）が明示されていない。

## 3. 推奨される修正案
- `docs/design/screen_design.md` の「ホーム画面」の構成要素およびページネーション補足を改訂し、以下を明記する：
  1. ホーム画面の各表示欄（優先タスク、締切間近タスク、ピン留めタスク）は独立したカード/セクションとして表示され、各セクションごとに独立したページネーション操作UI（各リスト下部または上下）およびページ番号状態を持つこと。
  2. または、ホーム画面が3つのタブ切り替えUIで1画面に1つのリストを表示する仕様とする場合は、構成要素をタブ切り替え形式に修正すること。
  3. 各セクションのデータ取得は、フロントエンドが `GET /api/tasks?view_type=...` を各々呼び出し、クライアントサイドでそれぞれの配列に対して20件単位のページ分割制御を行うことを明記する。

### 実施した修正内容
ホーム画面において「優先タスク」「締切間近タスク」「ピン留めタスク」を切り替えるタブ切り替えUIを採用し、選択中のタブに応じてフロントエンドが `GET /api/tasks?view_type={priority|near_deadline|pinned}` を呼び出し、タスクリスト上下に配置された単一のページネーションUIで20件単位のページ制御を行う仕様を明記しました。
