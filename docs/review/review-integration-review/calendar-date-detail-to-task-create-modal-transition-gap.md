# カレンダーの日付詳細ポップアップからの新規タスク作成モーダル遷移と初期値連携仕様の未確定

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-22 13:50:00
- **Target Files**:
  - [screen_design.md](docs/design/screen_design.md)
  - [02_task_management.md](docs/req-def/requirements/02_task_management.md)

## 1. 問題の概要
画面設計書（`screen_design.md`）ではカレンダーの日付詳細ポップアップ内の新規タスク作成操作について「タスク作成画面（該当日付を締切日に事前入力）」へ遷移すると記載されているが、タスク作成UIは画面遷移ではなく「タスク作成ポップアップ（モーダル）」として定義されている。モーダル展開中に別のモーダルを開く際の多重モーダル制御（親モーダルを閉じるかスタックするか）や、キャンセル・作成完了後の復帰先、および締切日時（該当日付およびデフォルト時刻 `23:59`）の初期値プリフィル仕様が未確定である。

## 2. 詳細な指摘内容
1. **画面設計書の用語・UI遷移の矛盾**:
   - `docs/design/screen_design.md` line 53 では以下のように記載されている：
     > ポップアップ遷移先: タスク編集画面、タスク作成画面（該当日付を締切日に事前入力）
   - しかし同ドキュメントのタスク関連画面一覧（line 31-35）では、タスク作成・編集はすべて画面遷移ではなく「タスク作成ポップアップ」「タスク編集ポップアップ」というモーダル（ポップアップ）として定義されている。
2. **多重モーダルとUIスタック制御の未定義**:
   - カレンダー上の日付セルをクリックして「日付詳細ポップアップ」を開いている状態で「新規タスク作成」ボタンや「タスク編集」を押下した場合：
     - 日付詳細ポップアップを閉じてからタスク作成/編集ポップアップを開くのか？
     - 日付詳細ポップアップの上にタスク作成/編集ポップアップを多重に重ねて表示する（スタック）のか？
     - タスク作成/編集ポップアップで「キャンセル」または「決定（作成/更新完了）」した際に、日付詳細ポップアップへ戻るのか、それともカレンダー画面へ直接復帰するのかが定義されていない。
3. **初期値プリフィル仕様の具体化不足**:
   - 「該当日付を締切日に事前入力」とする際、タスク作成ポップアップの「締切り日時入力欄」に対して、日付のみ（`YYYY/MM/DD`）が設定されるのか、デフォルト締切時刻（`23:59`）を含む日時（`YYYY/MM/DD 23:59`）として設定されるのかのUI挙動が明記されていない。

## 3. 推奨される修正案
- `docs/design/screen_design.md` の第53行の記述を「ポップアップ遷移先: タスク編集ポップアップ、タスク作成ポップアップ（該当日付を締切日に事前入力）」へ修正する。
- カレンダーの日付詳細ポップアップからタスク作成/編集ポップアップを開く際の挙動として以下を明記する：
  1. 日付詳細ポップアップを閉じてタスク作成ポップアップ（またはタスク編集ポップアップ）を開く。
  2. タスク作成ポップアップの「締切り日時入力欄」には該当日の日付＋デフォルト時刻 `23:59`（例: `2026/08/20 23:59`）が初期入力された状態で開く。
  3. タスク作成/編集完了時およびキャンセル時は、カレンダー画面へ復帰し、完了時はカレンダーグリッドのタスクデータを最新化して再描画する。
