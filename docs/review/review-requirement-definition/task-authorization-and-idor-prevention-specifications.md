# タスク操作およびデータアクセスにおける所有者認可（BOLA/IDOR防止）仕様の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-16 02:22:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「機能要件 > タスク管理（L77-L146）」および「非機能要件 > セキュリティ（L178-L180）」において、タスクの各操作（詳細取得、編集、状態更新、削除、ピン留め切り替え、カレンダー・一覧表示等）を実行する際に、操作対象のタスクが「現在ログイン中の認証済みユーザー自身が作成・所有するタスクであるか」をバックエンドで検証する認可（Authorization / IDOR対策）の明文仕様が欠落しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L94-L102（タスク編集・状態更新・削除・ピン留め）および L178-L180（セキュリティ）には以下の記述があります：

```markdown
- タスク編集（タスクの名前、コメント等）
- タスク状態更新（未着手、進行中、完了）
- タスク削除
	- ユーザー操作によるタスクの削除は物理削除とする
- タスクピン止め状態更新
```
```markdown
- 不正アクセス対策
	- 本人以外は、そのアカウントの情報を見られない
		- 登録されているメールアドレスにアクセスできる人を本人とする
```

### 仕様・セキュリティ上の不備：
1. **BOLA / IDOR（オブジェクトレベルの認可不備）脆弱性リスク**:
   - Web APIにおいて、クライアントから送信されたタスクID（例: UUIDや連番ID）に基づいてDBを操作・取得する際、「該当タスクの `user_id` とリクエスト元のログインセッションの `user_id` が一致すること」を必ず検証しなければ、他ユーザーのタスクIDを推測・改ざんして送信することで他人のタスクを不正に閲覧・改ざん・削除できてしまう重大な脆弱性（OWASP API Security Top 10 第1位: BOLA）が発生します。
2. **他ユーザー所有リソースへのアクセス試行時の応答仕様の未定義**:
   - 存在しないタスクID、または他ユーザーが所有するタスクIDを指定してアクセス・更新・削除を試みた場合に、システムがどのようなレスポンスを返却すべきか（リソースの存在自体を秘匿するため一律 `404 Not Found` を返すのか、または `403 Forbidden` を返すのか）が定義されていません。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > 不正アクセス対策」および「機能要件 > タスク管理」に、すべてのタスク操作APIにおけるユーザー所有権の厳格な認可チェックおよび存在秘匿（404 Not Found 返却）仕様を明記してください。

### 実施した修正内容
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > 不正アクセス対策」に、タスクの取得・編集・状態変更・削除・ピン留め等の全API処理において、リクエスト元ログインユーザーのユーザーIDと操作対象タスクの所有ユーザーIDの一致を必須で検証し、他ユーザー所有または存在しないタスクへのアクセス要求時はタスクの存在有無を秘匿するため一律 `404 Not Found` を返却する規定を追加しました。
