# ログイン失敗時のアカウントロックアウト条件とリセット周期の仕様矛盾

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-11 22:45:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
セキュリティ要件におけるログイン認証のロックアウト仕様（L123-L125）において、「5回連続失敗で30分ロック」と「初失敗から1時間ごとにロックをリセット」という2つのルールが記載されていますが、両者の関係性およびカウントリセットのタイミングが不整合であり、かつロック対象の単位（メールアドレス単位かIPアドレス単位か）が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に問題があります：

- **L123-L125（ログイン認証）**:
  ```markdown
  - ログイン認証
  	- 5回連続でログインに失敗したら、30分間ロックがかかる
  		- 初失敗から1時間ごとにロックをリセット
  ```

1. **仕様上の矛盾・解釈のゆらぎ**:
   - 初回のログイン失敗が `10:00` に発生し、`10:04` に5回目の失敗で30分間のロック（`10:04`〜`10:34`）がかかった場合、`11:00` に行われる「初失敗から1時間ごとのリセット」は「失敗カウントのリセット」なのか「ロック状態自体の強制解除」なのかが曖昧です。
   - もし `10:00` に1回失敗、`10:50` に1回失敗の状態で `11:00` を迎えた場合、失敗カウントは0にリセットされるのか、それとも連続失敗カウントは保持されるのかが明確ではありません。
2. **ロックアウト対象識別子の未定義（DoSセキュリティリスク）**:
   - ロックアウトの対象が「メールアドレス単位」なのか「IPアドレス単位」なのか記載がありません。
   - 仮に「メールアドレス単位」のみでロックする場合、第三者が任意のユーザーのメールアドレスで意図的に5回失敗することで、正当な所有者を30分間ログイン不可にするサービス拒否（DoS）攻撃が成立してしまいます。

## 3. 推奨される修正案
ロックアウトの判定ロジックとリセット条件を以下のように整理・再定義してください：

```markdown
- ログイン認証
  - 同一メールアドレスまたは同一IPアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、対象アカウント（および当該IPからのログイン試行）を30分間ロックアウトする
  - 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
  - ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする
```

### 実施した修正内容
`docs/req-def/requirements.md` のログイン認証要件を更新し、同一メールアドレスおよび同一IPアドレスに対して直近15分間に5回連続失敗で30分間ロックアウトするロジック、および最後の失敗から15分経過またはログイン成功時に失敗カウントをリセットする仕様を明記・統一しました。
