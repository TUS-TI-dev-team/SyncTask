# メールアドレスの正規化（小文字化）およびトリム処理仕様の未定義

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-13 21:12:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
新規登録、ログイン、メールアドレス変更、パスワードリセット等で用いられるメールアドレスについて、入力値の前後の空白除去（トリム）および大文字・小文字の正規化（Case-Insensitive / 小文字化 `toLowerCase()`）に関する仕様が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L27, L34, L53, L57, L145, L201 等でメールアドレスがシステムの識別子および連絡先キーとして指定されていますが、大文字・小文字の扱い（例: `User@Example.com` と `user@example.com`）や入力前後の空白（トリム）についての定義がありません（※ タスク検索要件 L90 には検索キーワードのトリムおよび Case-Insensitive が明記されていますが、アカウント管理のメールアドレスには規定がありません）。

メールアドレスが大文字小文字を区別（Case-Sensitive）して扱われた場合、大文字混じりで入力すると同一人物が別アカウントとして重複登録できてしまったり、重複登録拒否・ダミーOTP処理（L40, L146, L172, L202）をすり抜けて実在する他人のメールアドレスと大文字小文字違いで二重登録される重大なセキュリティおよびデータ不整合を引き起こします。

## 3. 推奨される修正案
アカウント管理（新規登録・ログイン・メールアドレス変更・パスワードリセット）におけるメールアドレス入力の共通要件として以下を明記してください：
- 入力されたメールアドレスの前後の空白文字を自動的にトリムすること。
- メールアドレスはシステム内部（登録・ログイン・重複判定・認証処理）で一律小文字（`toLowerCase()`）に正規化して保持・比較すること（Case-Insensitive 一意性保証）。

### 実施した修正内容
`docs/req-def/requirements.md` のメールアドレス要件セクションに、全機能（新規登録、ログイン、メールアドレス変更、パスワードリセット等）で入力前後の空白文字（半角・全角・タブ・改行）を自動トリムする旨、および一律小文字（`toLowerCase()`）に正規化してシステム内部で保持・比較し Case-Insensitive な一意性を保証する旨を明記しました。
