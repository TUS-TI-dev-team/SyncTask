# パスワード変更およびパスワードリセット時における他端末ログインセッション一括無効化要件の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 20:27:29
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
パスワード変更およびパスワードリセット完了時の要件として「ログインセッションを破棄して再度ログインを要求する」と記載されていますが、該当ユーザーが複数端末でログインしている場合の「破棄対象となるセッションのスコープ（操作中セッションのみか、全端末の全セッションか）」が明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の記述にスコープの曖昧さがあります：

- **L48（アカウント管理 - パスワード変更）**: `変更後パスワードを入力した後、既存のログインセッションを破棄して再度ログインを要求する`
- **L58（ログイン関係 - パスワードリセット）**: `変更後パスワードを入力後ログインを要求`

### セキュリティ上の課題：
ユーザーがパスワード変更またはパスワードリセットを行う主な動機の一つに、他端末でのログイン放置や第三者による不正アクセス・アカウント乗っ取りの遮断があります。
ここで破棄されるログインセッションが「変更操作を行った端末のセッション」のみである場合、攻撃者や別端末で既に確立されているログインセッション（有効期限1ヶ月: L131）が維持されたままとなり、パスワード変更後も不正アクセスが継続してしまうセキュリティリスクが存在します。

## 3. 推奨される修正案
パスワード変更およびパスワードリセットの完了時挙動として、セッションの破棄スコープを全端末対象に明確化してください：

```markdown
- パスワード変更・リセット完了時のセッション破棄要件:
  - パスワード変更またはパスワードリセットが成功した時点で、該当ユーザーIDに紐づくすべての既存ログインセッション（他端末・他ブラウザを含む）を一括して無効化（物理削除）し、すべての環境で再ログインを強制する。
```

`docs/req-def/requirements.md` において、パスワード変更およびパスワードリセット成功時の挙動として「該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、すべての環境で再度ログインを要求する」ことを明記し、セッション破棄スコープを明確化しました。
