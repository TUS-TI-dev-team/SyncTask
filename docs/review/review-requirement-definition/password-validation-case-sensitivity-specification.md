# パスワード要件におけるユーザ名・メールローカル部部分一致判定の大文字・小文字区別仕様の未明記

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:31:30
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「パスワード要件」において、ユーザ名およびメールアドレスのローカル部文字列を含むパスワードの設定を禁止するルールが記載されていますが、部分一致判定時に大文字・小文字を区別（Case-Sensitive）するか否か（Case-Insensitive）が明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L202 において以下の記述があります：

```markdown
- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する
```

### 仕様上の不備：
1. **大文字・小文字の区別（Case-Sensitivity）の曖昧さ**:
   - メールアドレス自体は L207 にて `toLowerCase()` で小文字化正規化されてシステム内部に保持されることが定義されています。
   - しかし、パスワード設定時のバリデーションにおいて、例えばメールアドレスが `admin1234@example.com`（ローカル部: `admin1234`）のユーザーが、パスワードに `P@sswordADMIN1234!`（大文字表記 `ADMIN1234`）を指定した場合に、Case-Sensitive（区別あり）で比較すると一致せず、パスワードが許可されてしまうセキュリティ上の抜け穴が存在します。
2. **ユーザ名・ローカル部両方での判定基準不統一リスク**:
   - ユーザ名においても大文字・小文字が含まれうる（L197）ため、Case-Insensitive（大文字小文字を区別せず比較）で禁止文字列を含んでいるかを検証することがセキュリティ上必要です。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > パスワード要件」のバリデーション記述に、大文字小文字を区別しない比較を行う旨を追加してください：

```markdown
- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する（いずれも大文字・小文字を区別せず［Case-Insensitive］に部分一致判定を行う）
```

`docs/req-def/requirements.md` の「パスワード要件」において、ユーザ名およびメールアドレスのローカル部（4文字以上）を含むパスワードの禁止判定時に、大文字・小文字を区別せず（Case-Insensitive）部分一致判定を行う旨を明確に規定しました。
