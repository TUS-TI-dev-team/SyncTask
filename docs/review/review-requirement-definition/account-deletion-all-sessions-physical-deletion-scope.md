# アカウント削除（論理削除）時における全端末ログインセッション一括物理削除スコープの明記不足

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-16 02:04:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「機能要件 > アカウント管理 > アカウントの削除（L51-L56）」において、削除時のセッション処理について「ログインセッションは物理削除とする」と記載されていますが、他機能（メールアドレス変更やパスワード変更）のように「該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括物理削除する」という全端末スコープが明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L52-L53（アカウントの削除）**:
  - `ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要。5回連続でパスワード再認証に失敗した場合はログインセッションを破棄［物理削除］してログイン画面にリダイレクトする)`
  - `アカウント本体は論理削除、ログインセッションは物理削除とする`
- **L45（メールアドレスの変更）**:
  - `変更確定と同時に、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、新メールアドレスでの再度ログインを要求する`
- **L60（パスワード変更）**:
  - `変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する`

### 仕様上の不備：
- L53の「ログインセッションは物理削除とする」という記述のみでは、操作を実行した端末のセッションのみを削除するのか、それとも該当ユーザーIDに紐づく他端末・他ブラウザを含む全セッションを削除するのかが不明確です。
- アカウントが論理削除された後に他端末のセッションが残存していると、その端末からAPIリクエストが送られた際に予期せぬエラー（データ取得不能やゴースト状態）が発生するリスクがあるため、他機能と同様に全セッションの一括物理削除を明記する必要があります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「アカウントの削除」要件の記述を以下のように明確化してください：

```markdown
	- アカウントの削除
		- ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要。5回連続でパスワード再認証に失敗した場合はログインセッションを破棄［物理削除］してログイン画面にリダイレクトする)
		- アカウント本体は論理削除、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（DBから物理削除）し、クライアント側のCookieも消去してログイン画面へリダイレクトする
		- 論理削除後の登録メールアドレスでの再登録は可能
			- 再登録の際は自動付与されるUIDが異なるため同名のユーザ名などでも問題なく登録できる
		- アカウント論理削除に伴い、所有するタスクデータおよび関連データは即座にDBから物理削除する
```

## 修正完了報告

### 実施した修正内容
`docs/req-def/requirements.md` の「アカウント管理 > アカウントの削除」において、アカウント論理削除時に他機能（メールアドレス変更やパスワード変更）と同様、「該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（DBから物理削除）し、Cookieを消去してログイン画面へリダイレクトする」全端末スコープを明確に規定しました。
