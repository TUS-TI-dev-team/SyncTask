# 新規登録・パスワードリセット・メール変更時におけるOTP発行APIのレート制限仕様の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-16 02:40:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「非機能要件 > セキュリティ（L184-L220）」において、手動再送ボタンに対するクールダウン（L219: 60秒）は規定されていますが、アカウント新規作成・パスワードリセット・メールアドレス変更の初期フォーム送信時におけるOTP発行（メール送信）APIに対するIPアドレス単位およびメールアドレス単位のレート制限（Rate Limiting）が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L27-L33（アカウント作成）、L41-L49（メールアドレス変更）、L68-L75（パスワードリセット）、および L219（OTP手動再送）に記述があります：

```markdown
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信（初回発行または直前の再送信）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する。なお、再送信回数の上限は設けないが、初回発行から15分の全体有効期限が経過した時点で手続きは無効となる
```

### セキュリティおよび可用性上の不備：
1. **初期フォーム送信におけるレートリミット欠落**:
   - 手動再送ボタンの連打は60秒クールダウンで防止されていますが、最初のフォーム送信（新規登録画面、パスワードリセット画面、メールアドレス変更画面からメールアドレスを入力してフォームを送信するAPIリクエスト）に対する送信頻度制限がありません。
2. **メールフラッディング攻撃およびリソース枯渇リスク**:
   - 悪意のあるユーザーやボットが同一IPアドレスからスクリプト等でフォーム送信APIを大量に連打した場合、外部メール送信サービス（SES/SendGrid等）のクォータ枯渇や課金コストの急増、あるいは特定メールアドレスに対するメール爆弾（Mail Flooding / 迷惑メール送信）の踏み台として悪用される恐れがあります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ」配下のOTP要件または各機能要件に、初回OTP発行リクエストに対するIP単位およびメールアドレス単位のレート制限を追加してください：

```markdown
- OTP発行・メール送信レートリミット（メールフラッディングおよびDoS防止）
	- 同一IPアドレスからのOTP発行APIリクエストは、直近1分間に最大5回、直近1時間に最大30回までに制限し、超過時は一律一時遮断（HTTP 429 Too Many Requests、遅延1s±0.1s）とする
	- 同一宛先メールアドレスに対する新規発行・再発行要求は、直近1分間に最大1回（手動再送クールダウン60秒を含む）、直近15分間に最大5回までに制限し、超過時は「リクエスト頻度が高すぎます。しばらく時間をおいてから再度お試しください」とエラー表示（遅延1s±0.1s）してメール送信を抑制する
```

### 実施した修正内容
