# 手動OTP再送依頼実行時における誤入力失敗カウントリセット規定の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 22:47:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
`docs/req-def/requirements.md` の「OTP要件 - 手動再送依頼」（L189）において、ユーザーが画面上の「OTPを再送信する」ボタンを押下して手動で再送を行った際、それまでの誤入力失敗カウント（誤入力試行回数）を0にリセットする規定が欠落しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L189 には以下の記述があります：

```markdown
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信（初回発行または直前の再送信）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する
```

### 仕様上の問題点:
5回自動失敗時の挙動（L181, L184, L187）では、「新OTPを自動生成・再送信して失敗カウントをリセットし...」と明記されています。
しかし、誤入力回数が5回に達する前（例: 2回〜4回失敗時点）で、ユーザーが「OTPが届かない」「入力し直したい」等の理由で手動の「OTPを再送信する」ボタンを押下した場合の「誤入力失敗カウント（0〜5）」のリセット有無が明記されていません。

もし手動再送信時に失敗カウントを0にリセットしない場合、新しいOTPが再発行・送信された後も過去の失敗カウント（例: 4回失敗）がDB/セッション上に維持され、新OTPに対する最初の1回の誤入力で即座に5回超過の自動再送・旧OTP失効処理が誘発される不具合・UX劣化が発生します。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「OTP要件 - 手動再送依頼」（L189）の記述に、手動再送成功時（またはダミー再送処理時）に誤入力失敗カウントを0にリセットする旨を明記してください。

例:
```markdown
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。手動再送処理の実行に伴い、該当セッションの誤入力失敗カウントを0にリセットする。ただし、直前の送信（初回発行または直前の再送信）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する
```
