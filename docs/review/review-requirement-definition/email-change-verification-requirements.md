# メールアドレス変更機能におけるメール所有確認（OTP認証）およびセキュリティ要件の不足

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-11 22:45:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
アカウント編集機能（L31-L34）に「メールアドレスの変更」が挙げられていますが、新規登録やパスワードリセット時のような新メールアドレスの到達性・所有確認（OTP検証）要件、他ユーザーとの重複チェック、およびセキュリティ認証（現在のパスワード入力）要件が定義されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の記述に不備があります：

- **L31-L34（アカウント編集）**:
  ```markdown
  - アカウント編集
  	- ログイン後の画面からのみ可能
  	- ユーザ名の変更
  	- メールアドレスの変更
  ```

メールアドレスは本システムにおいてログイン識別子（L46）およびパスワードリセットの本人確認手段（L50）として利用される極めて重要な情報です。
しかし、メールアドレス変更時における以下の要件が完全に欠落しています：
1. 変更後の新しいメールアドレスに対するOTP送信・メール所有確認プロセス。
2. 変更先のメールアドレスが既に他ユーザーに登録されていないかどうかのユニーク制約チェック。
3. アカウント乗っ取り防止のための現在のパスワード再認証、または変更前・変更後の両アドレスへの通知メール送信要件。

## 3. 推奨される修正案
「アカウント編集」セクションにおける「メールアドレスの変更」フローを以下のように詳細化・追記してください：

```markdown
- アカウント編集
  - ログイン後の画面からのみ可能
  - ユーザ名の変更（2〜20文字、英数字）
  - メールアドレスの変更
    - 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
    - 変更先メールアドレスが既に登録済みの場合は変更不可とする（エラー表示）
    - 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
```

### 実施した修正内容
`docs/req-def/requirements.md` の「アカウント編集」における「メールアドレスの変更」要件に、新メールアドレスへのOTP送信・認証完了フロー、既存アドレスの重複チェック、および変更完了時の旧メールアドレス宛への通知メール送信要件を追記・規定しました。
