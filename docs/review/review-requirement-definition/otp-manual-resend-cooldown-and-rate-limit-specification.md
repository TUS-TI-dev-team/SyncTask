# 手動OTP再送信処理における連投防止（クールダウン時間・レート制限）仕様の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:31:30
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書のOTP機能において、手動で画面上の「OTPを再送信する」ボタンを押下した際のリクエスト連投防止（クールダウン期間・レート制限）に関する仕様が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L177-L178 において、以下の規定があります：

```markdown
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う
- 再送処理のターンアラウンドタイムは 1±0.1s とする
```

### 仕様上の不備：
1. **短時間でのボタン連打・リクエスト連投の防止手段の欠落**:
   - ユーザーが手動で画面上の「OTPを再送信する」ボタンを毎秒連打した場合、あるいは自動化スクリプトで連続アクセスが発生した場合の待機時間（クールダウン期間、例: 前回の再送信から60秒間は再送不可）が指定されていません。
2. **セキュリティ・運用上のリスク**:
   - 連投制限がない場合、外部メール送信プロバイダ（AWS SES, SendGrid等）のクォータ上限超過、従量課金コストの肥大化、および特定メールアドレス宛ての大量メール送信（メール爆撃 / Mail Bombing）の脆弱性につながります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > OTP要件」に、手動再送信に関するクールダウンおよびレートリミット規定を追加してください：

```markdown
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する。
```

## 修正完了報告

- **Resolved At**: 2026-08-13 21:34:00
- **Status**: Resolved

### 実施した修正内容
`docs/req-def/requirements.md` の「OTP要件」において、画面上の「OTPを再送信する」ボタン押下による手動再送時に、直前の送信（初回発行または直前の再送信）から60秒間のクールダウン期間を設定し、ボタン非活性化・カウントダウン表示による連投制限ルールを追加しました。
