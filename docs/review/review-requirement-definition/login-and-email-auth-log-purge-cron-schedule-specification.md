# ログイン情報およびメール認証ログの定期削除Cronスケジュールの未定義

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-13 21:37:30
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「非機能要件 > ログ管理 > ログ保持・パージ方針」において、DBアクセスログについてはパージ処理の実行頻度・時刻・Cron表記が明記されていますが、ログイン情報およびメール認証ログのパージ処理（1年超過レコードの削除）については具体的な実行メカニズム（Cronジョブのスケジュール・時刻等）が記述されておらず、定義が不統一です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L188-L190 に以下の記述があります：

```markdown
- ログ保持・パージ方針
	- ログイン情報・メール認証ログ: 1年間保持し、経過後に順次物理削除する
	- DBへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
```

### 仕様上の不備：
- `DBへのアクセスログ`（L190）については、`日次Cronジョブ（毎日 01:00 JST / Cron: 0 1 * * *）` とパージ処理の実行タイミング・タイムゾーン・Cron構文が明確に記載されています。
- 一方、`ログイン情報・メール認証ログ`（L189）は「1年間保持し、経過後に順次物理削除する」と漠然と記載されているのみで、パージをどのようなタイミング（日次Cronジョブ等）かつどの時刻に実行するのかが明確になっていません。

定期パージ処理の仕様が曖昧な場合、実装時にバッチジョブが未実装となったり、パージ処理の実行タイミングが開発者ごとに異なってデータベースに余計な負荷をかけるリスクがあります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「ログ保持・パージ方針」における「ログイン情報・メール認証ログ」のパージ実行仕様を、DBアクセスログの標準表記に合わせて明確化してください：

```markdown
- ログ保持・パージ方針
	- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
	- DBへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
```
