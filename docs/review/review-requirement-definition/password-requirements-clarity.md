# パスワード強度要件および「推測不可」の判定基準の曖昧さ

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-11 22:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
セキュリティ要件の「パスワード要件」（L153-L156）において、文字種の必須組み合わせ定義が不明確であり、また「ユーザ名, メールアドレスから推測不可のもの」というバリデーション条件の判定基準が客観的に検証不能な記述となっています。

## 2. 詳細な指摘内容
- **L153-L156（パスワード要件）**:
  ```markdown
  - パスワード要件
  	- 8文字以上128文字以下
  	- 英小大文字、数字、記号( `!"#$%&'()=-~^|\{}[]+;:*_/?.>,<` )
  	- ユーザ名, メールアドレスから推測不可のもの
  ```

1. **文字種必須制約の曖昧さ**:
   「英小大文字、数字、記号」と並べられていますが、これら4つの文字種すべて（英大文字・英小文字・数字・記号）を最低1文字ずつ含むことが必須なのか、あるいは使える使用可能文字の指定なのかが判断できません。
2. **「推測不可」の検証不可能性**:
   システムプログラムで自動判定・バリデーションを行うにあたり、「推測不可」という定性的表現では実装およびテストコード（ユニットテスト/E2Eテスト）が作成できません。具体的に「ユーザー名またはメールアドレスのローカル部と一致・部分一致しないこと」といった技術的要件に落とし込む必要があります。

## 3. 推奨される修正案
要件定義書の「パスワード要件」を以下のように厳密化してください：

```markdown
- パスワード要件
  - 文字数: 8文字以上128文字以下
  - 必須文字種: 英大文字、英小文字、数字、記号 (`!"#$%&'()=-~^|\{}[]+;:*_/?.>,<`) のうち、少なくとも3種類以上（あるいは4種類すべて）を含むこと
  - アカウント情報との類似性チェック: ユーザー名文字列、およびメールアドレスのローカル部（`@`より前の文字列）を含むパスワードの登録を禁止する
```
