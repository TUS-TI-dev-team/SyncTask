# 論理削除アカウントおよび未登録メール宛OTP認証の境界挙動の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-11 22:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
アカウント削除後の「論理削除」データの扱い、並びに新規作成・パスワードリセット時における「メールアドレス未存在・重複時におけるダミーOTP遷移」のセッション管理・エラー応答仕様に境界状態の不全が見られます。

## 2. 詳細な指摘内容
1. **論理削除アカウントの認証・操作遮断要件 (L35-L39)**:
   - アカウント削除時「アカウント本体は論理削除、ログインセッションは物理削除とする」とあります。
   - 論理削除済みのユーザーが削除前の資格情報（ユーザー名・パスワード）で再度ログインを試みた場合、どのような応答を返すか（「ユーザー名またはパスワードが正しくありません」として認証拒否するか）が明記されていません。
   - 削除済みアカウントのタスクデータ（論理削除か物理削除か、アクセス拒否か）の保持ポリシーが未定義です。
2. **OTP発行偽装処理のセッション・トークン管理 (L123-L128, L161-L165)**:
   - 新規作成時に登録済みアドレスが入力された場合、またはリセット時に未登録アドレスが入力された場合に「OTPの発行を行わない状態でOTP入力画面に遷移させる」と定めています（アドレス列挙攻撃の防止）。
   - しかし、この「ダミーOTP画面」においてユーザーがダミーコードを入力した場合の挙動（常に認証失敗とし、応答速度1s±0.1sでレスポンスする等）および失敗カウントの挙動が明記されていません。

## 3. 推奨される修正案
1. **論理削除アカウントのセキュリティ要件追加**:
   - 認証処理（ログイン）において、論理削除フラグが立っているユーザーは認証失敗として扱い、削除済みであること自体も秘匿するため一般の認証失敗エラーと同じレスポンスを返す旨を明記する。
   - アカウント論理削除に伴い、所有するタスクデータへの参照・操作アクセス権限も即座に無効化される要件を追加する。
2. **OTP偽装画面のレスポンス仕様明確化**:
   - 登録済みアドレスへの新規登録試行、および未登録アドレスへのパスワードリセット試行時の「ダミーOTP画面」における入力検証は、正解が存在しないため常に失敗（応答速度1s±0.1s）扱いとし、最大失敗回数制限に達した後は「再送メッセージ（ダミー）」を表示して画面を維持する仕様を明記する。

## 修正完了報告

- **Resolved At**: 2026-08-11 22:56:00
- **Status**: Resolved

### 実施した修正内容
`docs/req-def/requirements.md` において、論理削除アカウントのログイン試行時は「メールアドレスまたはパスワードが正しくありません」で認証拒否（遅延1s±0.1s）しデータアクセスを即遮断する旨を明記しました。また、ダミーOTP画面でのコード誤入力検証は常に失敗扱い（遅延1s±0.1s）とし、失敗制限超過時もダミーの再送メッセージを表示してアドレスの有無を秘匿する仕様を明確化しました。
