# ログ管理要件における「メール認証ログ」の記録対象項目の未定義

- **Status**: Open
- **Severity**: Medium
- **Created At**: 2026-08-13 20:40:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「ログ管理」セクション（L168-L173）において、「ログイン情報」および「DBへのアクセスログ」には記録対象項目が具体的に定義されているのに対し、「メール認証」の項目が単一の箇条書き見出し（`- メール認証`）として記載されたままになっており、具体的に何をログとして記録すべきかの仕様が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L168-L173 に以下の記述があります：

```markdown
- ログ管理
	- ログイン情報
		- 日時、ユーザーID (UID)、メールアドレス、IPアドレス、ログイン成否
	- DBへのアクセスログ
		- 日時、ユーザーID (UID)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
	- メール認証
```

### 仕様上の不備：
- 「ログイン情報」や「DBへのアクセスログ」と同様に、メール認証（OTP発行・検証・手動再送・ロックアウト等）の監査ログ記録項目が定義されていません。
- OTP発行や検証はセキュリティ上の最重要イベント（アカウント登録、パスワードリセット、メールアドレス変更）であり、不正なOTP当たり調査や大量リクエスト攻撃の兆候を監査するために、明確なログ出力項目の規定が必要です。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「ログ管理 - メール認証」を以下のように記録項目を明記した記述へ更新してください：

```markdown
- ログ管理
	- ログイン情報
		- 日時、ユーザーID (UID)、メールアドレス、IPアドレス、ログイン成否
	- DBへのアクセスログ
		- 日時、ユーザーID (UID)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
	- メール認証ログ
		- 日時、ユーザーID (UID、未登録・未ログイン時は null)、対象メールアドレス、認証種別（新規登録 / パスワードリセット / メールアドレス変更）、アクセス元IPアドレス、処理イベント種別（OTP発行 / 検証成功 / 検証失敗 / 手動再送依頼 / 5回失敗時自動処理）、成否、ダミー処理区分（実処理 / ダミー表示）
```
