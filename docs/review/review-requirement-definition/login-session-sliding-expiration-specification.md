# ログインセッション有効期限（1ヶ月）の自動延長（Sliding Expiration）有無の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:12:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
セキュリティ要件およびセッション管理（L137, L208-L210）において「ログインセッション: 有効期限 43200分 (1ヶ月)」と定義されていますが、この有効期限がログイン発行時からの固定（Absolute Expiration）か、アクティブ利用時の自動延長（Sliding Expiration）かが未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` L137 (`ログイン認証のセッション期限は1ヶ月とする`) および L208-L210 (`ログインセッション: 有効期限 43200分(1ヶ月)` `有効期限切れのセッションは日次Cronで削除`) において、有効期限のカウントダウン基準が明記されていません。

- 固定期限（Absolute）の場合: アクティブに日常利用しているユーザーであっても、ログイン完了後30日経過した時点で強制的にログアウトされます。
- 延長期限（Sliding）の場合: アプリ操作（API呼び出し）ごとにセッション有効期限がその時点から30日後に更新され、1ヶ月間全くアクセスがなかった場合（`last_activity_at` から30日経過）に失効となります。

仕様が不明確な場合、日次Cronジョブの削除クエリ（`created_at` を基準にするか `last_activity_at` を基準にするか）やセッション維持の実装で齟齬が生じます。

## 3. 推奨される修正案
ログインセッションの有効期限について、以下のように更新ロジックを明記してください：
```markdown
- ログインセッション
  - 有効期限 43200分 (1ヶ月)
  - ユーザーがログイン中にリクエスト（API呼び出し）を行うたびに、セッションの有効期限をアクセス時刻から43200分（1ヶ月）後に自動更新（Sliding Expiration）する。最後のアクセスから43200分経過したセッションを無効（期限切れ）とする。
```

### 実施した修正内容
`docs/req-def/requirements.md` のセキュリティおよびセッション管理セクションを更新し、ログインセッションの有効期限（1ヶ月 / 43200分）がAPIアクセスごとに最終アクセス時刻から43200分後へと自動更新される Sliding Expiration 方式であることを明記しました。最後のアクセスから43200分経過した無効セッションが日次Cronで削除対象となります。
