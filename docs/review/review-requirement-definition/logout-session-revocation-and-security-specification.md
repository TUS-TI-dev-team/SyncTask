# ログアウト処理におけるセッション破棄スコープ・セキュリティ・画面遷移仕様の不足

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-13 22:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書（L57）の「ログイン関係」に「ログアウト」という項目のみが記述されていますが、ログアウト実行時の具体的な処理（セッション破棄スコープ、HTTPメソッド、CSRF対策、クッキー消去、レスポンス・画面遷移）についての仕様が一切定義されていません。

## 2. 詳細な指摘内容
1. **セッション破棄スコープの未定義**:
   - パスワード変更/リセットやメールアドレス変更時（L38, L53, L64）では「すべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化」と全端末破棄が明記されています。
   - 一方で、通常のログアウト操作時に「操作を行った端末のセッションのみを物理削除する」のか「ユーザーの全端末セッションを破棄する」のかが未定義です。
2. **HTTPメソッドおよびCSRF対策の不足**:
   - ログアウトを GET リクエストで実装した場合、`<img>` タグの埋め込みやサードパーティサイトからのリンク遷移によって意図しないログアウトを引き起こす CSRF ログアウト攻撃の脆弱性が生じます。
   - ログアウト処理が `POST` リクエストであり、CSRFトークンの検証を必須とする旨が明記されていません。
3. **レスポンス・クッキー消去・画面遷移の未定義**:
   - ログアウト完了時にクライアント側のセッションCookie（`session_id` 等）を無効化（`Max-Age=0` または過去日時設定）する挙動、およびログイン画面（`/login`）へのリダイレクト（Web APIの場合は `200 OK` または `204 No Content` レスポンス）についての記載が不足しています。
4. **無効セッション/未ログイン状態でのリクエスト処理**:
   - 既にセッションが切れている（またはログアウト済み）状態でログアウトAPIが呼び出された場合の挙動（冪等性を保ちエラーとせず `200 OK` またはログイン画面リダイレクトとするか）が不明確です。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「ログイン関係 -> ログアウト」要件を以下のように更新・明記してください：

```markdown
- ログアウト
  - ログイン後の画面からのみ実行可能（`POST` リクエスト + CSRFトークン検証必須）
  - ログアウト実行時、操作中の端末のログインセッションレコードをDBから即座に物理削除する（他端末・他ブラウザのセッションは維持する）
  - クライアント側のセッションCookieを即座に無効化（消去）し、ログイン画面にリダイレクトする
  - セッションが既に無効化または期限切れの状態でログアウトが実行された場合もエラーとせず、セッションCookieを消去してログイン画面へリダイレクトする（冪等性の確保）
```

### 実施した修正内容
要件定義書（`docs/req-def/requirements.md`）の「ログイン関係 -> ログアウト」要件を更新し、`POST` リクエストおよびCSRF検証の必須化、操作端末のみのセッション物理削除スコープ、セッションCookieの即時消去・ログイン画面リダイレクト、ならびに無効/期限切れセッション時の冪等性確保仕様を明記しました。
