# アカウント削除処理における「パスワード再認証」失敗時のセキュリティ制御仕様の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書において、アカウント削除の実行時には「確認ダイアログ + パスワード再認証要」と規定されていますが、このパスワード再認証に連続して失敗した場合の保護措置（失敗回数制限やセッション破棄等のセキュリティ制御）が明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L43-L48（アカウントの削除）**:
  ```markdown
  - アカウントの削除
  	- ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要)
  	- アカウント本体は論理削除、ログインセッションは物理削除とする
  ```

- **L51（パスワード変更時のセキュリティ保護）**:
  ```markdown
  - 5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト
  ```

- **L163-L164（セキュリティ - パスワード変更時の「現在のパスワード」認証）**:
  ```markdown
  - 5回連続で現在のパスワードの認証に失敗したら、セッションを破棄してログイン画面に戻す
  ```

### 仕様上の不備：
パスワード変更機能においては、パスワード認証失敗が5回連続した段階でセッションを強制破棄してログイン画面へ戻すセキュリティ保護が明確に定められています。
しかし、アカウント削除実行時のパスワード再認証については、誤ったパスワードが連続入力された場合の挙動（失敗上限回数やセッション破棄制御の有無）が一切定義されていません。

アカウント削除画面で誤ったパスワードの試行が無制限に許可された場合、不正にセッションを取得した第三者がアカウント削除を試みてブルートフォース攻撃を行ったり、認証試行の制御が機能しないセキュリティ上の穴となる恐れがあります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「アカウントの削除」（L44付近）および「セキュリティ - パスワード認証」（L164付近）に、アカウント削除時におけるパスワード再認証の失敗制御仕様を追加・明記してください。

```markdown
- アカウントの削除
	- ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要。5回連続でパスワード再認証に失敗した場合はログインセッションを破棄［物理削除］してログイン画面にリダイレクトする)
```
