# OTP失敗時における再送処理・無効化処理・ダミー応答仕様の競合

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-11 22:45:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
OTP（ワンタイムパスワード）の認証失敗時および期限切れ時における処理フローにおいて、「入力制限5回超過での無効化（L126）」、「5回誤入力時の自動再送（L139）」、「ダミー再送メッセージの表示（L129, L133）」が混在しており、実際のユーザー画面状態および入力制限超過後のリカバリーフローが曖昧です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の記述に不整合・混同が見られます：

- **L126**: `OTPのセッション期限 5 分 (入力制限5回超過または有効期限切れで無効化)`
- **L139**: `入力制限(5回)を超えて間違えた場合はOTPを新しいものにして再送する`
- **L129, L133**: `入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(...)`

1. **実在アドレスの場合の5回失敗時の挙動の揺れ**:
   - L126では「5回超過で無効化」とあり、L139では「新しいものにして自動再送する」とあります。
   - 5回間違えた瞬間にシステムが新しいOTPを発行して自動送信し、画面の失敗カウントを0にリセットしてそのまま同じ入力画面で新しいOTPの入力を待つのか、それとも一度セッションを無効化してユーザーに「最初からやり直す」よう求めるのかが不明確です。
2. **手動での再送依頼と自動再送の区別**:
   - ユーザーが「再送ボタン」を押した場合の挙動（L141）と、誤入力5回による自動再送（L139）で、OTPの有効期限や送信回数制限（例: 再送上限3回など）がどのように制御されるかが定義されていません。

## 3. 推奨される修正案
OTPセッションのステータス遷移と誤入力・再送時の仕様を整理・明確化してください：

```markdown
- OTP認証仕様
  - 有効期限: 発行から5分間
  - 誤入力制限: 1つのOTPに対して最大5回まで入力試行可能
  - 5回失敗時の挙動:
    - 実在アカウント/新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する。
    - 重複メールアドレス/未登録メールアドレス（ダミー画面）の場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）。
  - 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定（実在時のみ新OTP送信、ダミー時は送信メッセージのみ）を行う。
```
