# 短いメールアドレスローカル部によるパスワード設定バリデーション誤検知のリスク

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 20:55:00
- **Target Files**:

## 1. 問題の概要
パスワード要件において「メールアドレスの `@` より前のローカル部を含むパスワードの設定を禁止する」と規定されていますが、ローカル部が短文字（1〜2文字等）の場合に、広範な正常パスワードが誤って拒否される（False Positive）リスクが存在します。

## 2. 詳細な指摘内容
- **[requirements.md](file:///c:/Users/kazuh/Programming/repos/SyncTask/docs/req-def/requirements.md#L192)**:
  ```markdown
  - ユーザ名文字列、およびメールアドレスの `@` より前のローカル部を含むパスワードの設定を禁止する
  ```

例えば、ユーザーのメールアドレスが `a@example.com` や `me@example.com` の場合、ローカル部が `a` や `me` となります。この時、パスワード文字列内に文字 `a` や部分文字列 `me` が含まれるだけでパスワード設定が拒否されてしまいます。これにより、正規の安全なパスワード（例: `P@ssword1a` や `Awesome!2026`）が登録不能になる不具合・利便性阻害が発生します。

## 3. 推奨される修正案
メールアドレスのローカル部チェックについて、最小文字数しきい値（例: 3文字以上の場合のみ判定対象とする）や部分一致条件を明確化してください。

```markdown
- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし3文字以上の場合に限る）を含むパスワードの設定を禁止する
```
