# OTP 5回誤入力時の処理定義におけるパスワードリセット分岐の記述不整合およびメールアドレス変更OTP仕様の欠落

- **Status**: Open
- **Severity**: Major
- **Created At**: 2026-08-13 20:40:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「OTP要件 - 5回失敗時の挙動（L157-L163）」において、「パスワードリセット OTPの場合」のサブ項目にパスワードリセットとは無関係な「変更先メールアドレスが新規の場合」という不適切な記述（転記ミス）が存在します。さらに、同様にOTP検証を伴う「アカウント編集（メールアドレス変更） OTPの場合」の5回失敗時における挙動定義が完全に欠落しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L157-L163 に以下の記述があります：

```markdown
- 5回失敗時の挙動:
	- パスワードリセット OTPの場合
		- 現在登録済みのメールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 変更先メールアドレスが新規の場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- 新規登録 OTPの場合
		- 新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 重複メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
```

### 仕様上の不備・問題点：
1. **パスワードリセット時の分岐表現の誤り**:
   パスワードリセットは既存アカウントのパスワード再設定手続きであり、「変更先メールアドレス」という概念は存在しません。「変更先メールアドレスが新規の場合」は「未登録（システム上に存在しない）メールアドレスが指定された場合（ダミーOTP処理）」の誤記です。
2. **「アカウント編集（メールアドレス変更） OTP」の5回失敗時挙動の未定義**:
   アカウント編集（メールアドレス変更）においてもOTPによる認証（L35, L147-L150）が行われます。メールアドレス変更時には「変更先が新規メールアドレス（実体ありOTP送信）」と「変更先が既存他ユーザー登録済みメールアドレス（ダミーOTP送信）」の2パターンが存在しますが、L157-L163の5回失敗時挙動一覧に「アカウント編集（メールアドレス変更） OTPの場合」のセクションが存在せず、開発・実装時の仕様抜けが発生します。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「5回失敗時の挙動」セクションを以下のように修正・明確化してください：

```markdown
- 5回失敗時の挙動:
	- パスワードリセット OTPの場合
		- 有効な登録済みメールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 未登録（存在しない）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- 新規登録 OTPの場合
		- 新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 重複（登録済み）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- アカウント編集（メールアドレス変更） OTPの場合
		- 未使用の新規メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 他ユーザーに登録済みの重複メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
```
