# 新規アカウント登録（アカウント作成）完了時におけるログインセッション発行有無および画面遷移仕様の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書において、アカウント作成（新規登録）時にメール認証（OTP入力）を行うことが規定されていますが、OTP検証が成功しアカウント作成が確定した直後の動作（自動的にログインセッションを発行してログイン完了状態とするのか、それとも登録完了画面・ログイン画面へ遷移させて再度ログインを要求するのか）が明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L26-L31（アカウント作成）**:
  ```markdown
  - アカウント作成
  	- ユーザー名、パスワード、メールアドレスを入力
  	- メール認証を行う
  		- メールにてOTPを送信
  		- サイト内のOTP入力欄にOTPを入力する
  		- OTP有効期限内（5分間）は、作成予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または有効期限切れまで排他維持する
  ```

### 仕様上の不備：
他の認証・アカウント操作フロー（パスワード変更［L52］、パスワードリセット［L63］、メールアドレス変更［L37］）においては、処理完了時に「既存セッションを一括無効化し再度ログインを要求する」等のセッション取り扱いおよび画面遷移の挙動が明確に規定されています。

しかし、アカウント作成フローでは、サイト内でOTP入力を完了して「認証確定」となった後に：
1. 自動的にログインセッションを発行してログイン完了状態とし、メイン画面（タスク一覧画面）へ遷移させるのか
2. あるいは「アカウント登録が完了しました」等のメッセージを表示してログイン画面へリダイレクトし、ユーザーに手動での初回ログインを要求するのか

のいずれであるかが定義されていません。
この仕様が未定義であると、フロントエンドの画面遷移設計やバックエンドのAPIレスポンス仕様（セッションCookie発行の有無）で実装者・テスト担当者間の齟齬が発生するリスクがあります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「アカウント作成」セクション（L31付近）に、OTP検証成功・アカウント作成完了時のログインセッション発行有無および画面遷移仕様を追加・明記してください。

例（自動ログインとする場合）：
```markdown
	- アカウント作成
		- ユーザー名、パスワード、メールアドレスを入力
		- メール認証を行う
			- メールにてOTPを送信
			- サイト内のOTP入力欄にOTPを入力する
			- OTP認証成功時、アカウントの作成を確定すると同時に自動的にログインセッションを発行してログイン状態とし、タスク一覧画面へ遷移する
			- OTP有効期限内（5分間）は、作成予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または有効期限切れまで排他維持する
```
