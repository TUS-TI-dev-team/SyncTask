# タスク管理機能におけるステータス定義・バリデーション要件・優先度定義の不足

- **Status**: Open
- **Severity**: Major
- **Created At**: 2026-08-11 22:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
タスク管理機能（L57-L83）において、タスクが取り得るステータス値の完全な定義、各属性（タスク名、コメント等）の文字数制限・入力バリデーション、および優先度の定義が不足しています。

## 2. 詳細な指摘内容
1. **タスクステータスの定義不全 (L64, L78-L79)**:
   - L64では `タスク状態更新（進行中、完了）` と記載されていますが、タスク作成直後の初期状態が「未着手」なのか「進行中」なのかが不明です。
   - L78-L79の検索要件（`タスクステータス 完全一致`）を実装・テストする上で、ステータスの値の列挙（例: `未着手 (TODO)`, `進行中 (IN_PROGRESS)`, `完了 (DONE)` など）が定義されていません。
2. **優先度（Priority）の仕様未定義 (L61, L68, L76)**:
   - 「タスクの優先度変更」「優先タスク表示」「優先度での検索」が記載されていますが、優先度の定義（例: 高/中/低 の3段階なのか、数値1〜5なのか）や、優先表示の並び順（昇順・降順）が指定されていません。
3. **入力値の境界値・制限の欠落 (L58-L63)**:
   - タスク名およびコメントの文字数上限・下限（空文字許可か否か）が定義されておらず、DB設計やフロントエンド/バックエンドの入力バリデーションの基準が曖昧です。
4. **カレンダー表示の基準 (L82)**:
   - カレンダー表示時にプロットする基準日（締切日時なのか作成日時なのか）が明記されていません。

## 3. 推奨される修正案
1. **タスクステータス要件の追加**:
   - 取るべきステータス一覧（例: `未着手`, `進行中`, `完了`）および作成時の初期ステータス（例: `未着手`）を明確に記述する。
2. **優先度のドメイン定義追加**:
   - 優先度の値の種類（例: `高`, `中`, `低`）およびソート順の基準を明記する。
3. **タスク属性の入力バリデーション要件追加**:
   - タスク名: 1文字以上100文字以内（必須）
   - コメント: 0文字以上1000文字以内（任意）
   - 締切日時: 過去日の設定可否についての規定
4. **カレンダー表示仕様の明確化**:
   - 締切日時が設定されているタスクを対象にカレンダー上に表示する旨を追記する。
