# アカウント編集におけるユーザー名変更フローの仕様記述不足および整合性課題

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 22:20:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「アカウント編集」（L33-L43）において、「メールアドレスの変更」には詳細な画面遷移・エラー判定・OTP検証・セッション無効化ルールが規定されているのに対し、「ユーザ名の変更」（L35）には詳細な仕様記述が存在しません。
そのため、パスワード再認証の有無、同名（現在と同一）変更時の動作、セッション維持方針、およびパスワードの制約（「ユーザー名文字列の含有禁止」L213）との整合性処理が未定義となっています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に不備が存在します：

- **L33-L36（アカウント編集）**:
  ```markdown
  - アカウント編集
  	- ログイン後の画面からのみ可能
  	- ユーザ名の変更
  	- メールアドレスの変更
  ```

### 仕様上の不備・漏れ：
1. **パスワード再認証要件の有無**:
   「アカウント削除」（L45）や「パスワード変更」（L52）では、不正操作防止のため「確認ダイアログ + パスワード再認証（5回連続失敗でセッション破棄）」が定義されています。しかしユーザー名変更においてはパスワード再認証が必要であるかが明記されていません。セッション乗っ取りや離席時の勝手な表示名改ざんを防止するため、再認証要件を整理する必要があります。
2. **現在のユーザー名と同一名への変更挙動**:
   メールアドレス変更（L39）では「変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は『現在のメールアドレスと同じです』とエラー表示し拒否する」と明記されていますが、ユーザー名変更においては同様のエラー表示・拒否ルールが定義されていません。
3. **変更成功時のログインセッションの取り扱い**:
   メールアドレス変更やパスワード変更では「全既存ログインセッションを一括無効化し再度ログインを要求する」仕様が規定されています。ユーザー名変更時において、現在のログインセッションを維持したまま遷移するのか、セッションを再発行・更新するのかの挙動が明示されていません（ユーザー名はログイン識別子ではないため、セッション維持が標準的な挙動と考えられますが、明記が必要です）。
4. **既存パスワード要件（ユーザー名文字列の含有禁止）との整合性**:
   `パスワード要件`（L213）では「ユーザ名文字列...を含むパスワードの設定を禁止する」と規定されています。もしユーザーがユーザー名を変更した結果、変更後のユーザー名文字列が現在設定中のパスワードに含まれてしまうケース（例: パスワードが `john1234!` の状態で、ユーザー名を `john` に変更した場合）において、システムがユーザー名変更をバリデーションエラーとして拒否するのか、あるいは同時にパスワード変更を要求するのかの処理方針が未定義です。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「アカウント編集」セクション（L35付近）に「ユーザ名の変更」に関する詳細仕様を追加・補強してください。

例：
```markdown
	- アカウント編集
		- ログイン後の画面からのみ可能
		- ユーザ名の変更
			- 変更後のユーザー名を入力し、ユーザー名要件（2〜20文字、英数字）に基づきバリデーションを行う
			- 変更先ユーザー名が現在設定中の自分自身のユーザー名と同一の場合は「現在のユーザー名と同じです」とエラー表示し拒否する
			- 変更先ユーザー名が現在設定中のパスワード文字列に含まれる場合（大文字・小文字を区別せず部分一致）は、「現在のパスワードに新しいユーザー名が含まれているため変更できません。先にパスワードを変更してください」とバリデーションエラーを返し拒否する
			- ユーザー名変更完了後も現在のログインセッションは維持され、画面上の表示名（ユーザー名）が即座に更新される
```

## 修正完了報告

### 実施した修正内容
`docs/req-def/requirements.md` の「アカウント編集 > ユーザ名の変更」セクションに以下の詳細仕様を追記しました：
- 入力値に対するユーザー名要件バリデーション（2〜20文字、英小大文字・数字）。
- 現在と同一のユーザー名への変更要求時は「現在のユーザー名と同じです」とエラー表示し拒否。
- ユーザー名変更時のパスワード再認証は不要（入力・送信で即時変更）。
- 変更成功時も現在のログインセッションを維持し、画面上の表示名（ユーザー名）を即座に更新。
- 変更先ユーザー名が現在設定中のパスワードに含まれていても拒否せず許可する（ヒアリング結果に基づき決定）。
