# セキュリティ項目の「5回誤入力時非再送記述」とOTP要件「実処理時自動再送信仕様」の記述矛盾

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-13 22:47:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
`docs/req-def/requirements.md` の非機能要件 > セキュリティ配下の「アカウント新規作成」「パスワードリセット」「アカウント編集」セクション（L163, L167, L171）に「5回誤入力時は実際に再送処理は行わない」旨が一律に記述されていますが、これは同ドキュメントの「OTP要件 > 5回失敗時の挙動」（L179-L188）で定義されている「有効/新規メールアドレス（実処理）の場合は旧OTPを失効させ、新OTPを自動生成・再送信する」という正の仕様と明確に矛盾しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` 内で、5回誤入力時の再送処理に関して以下の通り相反する記述が存在します：

- **L163, L167, L171（セキュリティセクション）**:
  ```markdown
  - 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(通常の処理と見た目(表示と処理時間( 1±0.1s ))を同じにするが実際に再送処理は行わない)
  ```

- **L179-L188（OTP要件セクション）**:
  ```markdown
  - 5回失敗時の挙動:
  	- パスワードリセット OTPの場合
  		- 有効な登録済みメールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
  		- 未登録（存在しない）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
  	- 新規登録 OTPの場合
  		- 新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
  		- 重複（登録済み）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
  	- アカウント編集（メールアドレス変更） OTPの場合
  		- 未使用の新規メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
  		- 他ユーザーに登録済みの重複メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
  ```

### 仕様上の問題点:
L163, L167, L171 の記述は、未登録・重複メールアドレス等の「ダミーOTP処理対象」時の応答表示およびメール送信抑制を説明した項目ですが、「ダミーOTP処理対象の場合」という対象条件が文頭に明記されていません。
そのため、アカウント新規作成、パスワードリセット、アカウント編集のすべてのケース（実処理含む）で「5回誤入力時には実際に再送信を行わない」と読み取れてしまい、L179-L188の「実処理時の新OTP自動生成・再送信仕様」と記述上の直接的な矛盾・バッティングが発生しています。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の L163, L167, L171 の記述を、「ダミーOTP処理対象の場合」であることを明確にするか、重複・矛盾を避けるために「OTP要件（L179-L188）」の記載を参照・統一する形へ修正してください。

例（対象条件を明記する場合）:
```markdown
- ダミーOTP入力画面において入力制限(5回)を超えて間違えた場合は、画面上に「新しいOTPを再送しました」とメッセージを表示させる（通常の再送処理と表示および処理時間［1±0.1s］を統一するが、実際にメール送信や新OTP生成は行わない）
```
