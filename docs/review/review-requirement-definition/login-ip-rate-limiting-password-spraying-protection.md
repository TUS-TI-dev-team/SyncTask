# 単一IPアドレスからの分散パスワードスプレー攻撃に対するレート制限仕様の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-16 02:04:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「非機能要件 > セキュリティ > ログイン認証（L184-L186）」において、同一メールアドレスに対する5回連続失敗時のアカウントロックアウトが規定されていますが、同一IPアドレスから多数の異なるメールアドレスに対して行われる「パスワードスプレー攻撃（分散辞書攻撃・ブルートフォース攻撃）」に対するIP単位のレート制限（Rate Limiting）仕様が欠落しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L184-L186 に以下の記述があります：

```markdown
- ログイン認証
	- 同一メールアドレス、または同一IPアドレスと同一メールアドレスの組み合わせに対して、直近15分間に5回連続でログイン認証に失敗した場合、該当メールアドレスに対するログイン試行を30分間ロックアウトする
	- 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
	- ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする
```

### セキュリティ上の不備：
1. **パスワードスプレー攻撃（Password Spraying）の無防備性**:
   - 現在の仕様（L184）は「同一メールアドレス」を軸として5回失敗を検知するため、攻撃者が単一のIPアドレスから多数のアカウント（例: 100件以上の異なるメールアドレス）に対して共通の推測されやすいパスワード（例: `Password123!` 等）を1回ずつ試行した場合、各アカウントの失敗回数は「1回」にとどまります。
   - その結果、どのアカウントもロックアウト条件（5回連続失敗）に達せず、攻撃者はシステム全体の複数アカウントに対して無制限に辞書攻撃を継続できてしまいます。
2. **IPアドレス単位でのレート制限の必要性**:
   - 同一IPアドレスからの総ログイン試行失敗回数（例: 同一IPから直近5分間に30回以上失敗した場合に該当IPからのログインAPIを一時的に15分間ブロックする等）に対する制限が定められていません。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > ログイン認証」に、IPアドレス単位での総試行失敗レートリミット規定を追加してください：

```markdown
- ログイン認証
	- メールアドレス単位ロックアウト: 同一メールアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、該当メールアドレスに対するログイン試行を30分間ロックアウトする
	- IPアドレス単位レートリミット（パスワードスプレー対策）: 同一IPアドレスから直近5分間に累計30回以上のログイン認証失敗が発生した場合、該当IPアドレスからのログインAPIリクエストを一律15分間一時遮断（HTTP 429 Too Many Requests、遅延1s±0.1s）する
	- 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
	- ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする。なお、ロックアウト期間は初回ロックアウト発生時刻から30分経過時点で自動解除（固定時間）とし、ロックアウト中の追加試行による期間延長は行わない（永久ロックDoS防止）
```

### 実施した修正内容
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > ログイン認証」において、以下の仕様を追加・明記しました：
1. パスワードスプレー攻撃（同一IPからの複数アカウント総当たり）対策として、同一IPアドレスから直近5分間に累計30回以上のログイン認証失敗が発生した場合に該当IPアドレスからのログインAPIリクエストを一律15分間一時遮断（HTTP 429、遅延1s±0.1s）するレートリミット規定を追加しました。
2. アカウント単位のロックアウト期間（30分間）について、初回ロックアウト発生時刻から30分経過時点で自動解除（固定時間）とし、期間中の追加アクセスによる期間延長を行わない（永久ロックDoS防止）仕様を明記しました。
