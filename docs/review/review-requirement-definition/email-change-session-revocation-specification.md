# メールアドレス変更完了時におけるログインセッション無効化・更新仕様の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:37:30
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書において、パスワード変更およびパスワードリセットの完了時には「該当ユーザーのすべての既存ログインセッションを一括無効化（物理削除）する」旨が明確に規定されていますが、メールアドレス変更が完了した際における既存ログインセッション（他端末・他ブラウザを含む）の無効化またはセッション情報の更新仕様が定義されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L50（パスワード変更）**: `変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する`
- **L61（パスワードリセット）**: `新パスワードを設定完了すると同時に...該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する`
- **L31-L40（メールアドレスの変更）**:
  ```markdown
  - メールアドレスの変更
  	- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
  	- 変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する
  	- 変更先メールアドレスが既に他ユーザーに登録済みの場合は、メールアドレスの登録有無を秘匿するため、実際にはOTPを発行せずダミーOTP入力画面へ遷移する
  	- 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
  	- メール認証未完了の「変更手続き中」状態においても、ログイン識別子は変更前の旧メールアドレスが維持される
  	- OTP有効期限内（5分間）は、変更先予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または期限切れまで排他維持する
  ```

### 仕様上の不備：
メールアドレスは本システムにおいてログイン時の認証識別子（L53）として利用される最重要情報です。
ユーザーがメールアドレス変更を完了した場合、別端末や別ブラウザで継続している既存のログインセッションについて：
1. パスワード変更と同様に、セキュリティの観点から他端末を含めて一括無効化し、新メールアドレスでの再ログインを求めるのか
2. あるいは、既存のログインセッションを維持したまま、セッション保持データ内のメールアドレス情報を新メールアドレスへ即座に同期・更新するのか

のいずれであるかが定義されていません。
仕様が未定義のままだと、他端末のセッションデータに旧メールアドレスがキャッシュされたまま残り続けたり、不正アクセス対策・アカウントセーフティ上の考慮漏れが生じるリスクがあります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「アカウント編集 - メールアドレスの変更」セクション（L38付近）に、メールアドレス変更確定時のセッション処理仕様を追加・規定してください。一般的にセキュリティの観点からは全セッション破棄・再ログイン強制が推奨されます：

```markdown
- メールアドレスの変更
	- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
	- 変更確定と同時に、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、新メールアドレスでの再度ログインを要求する
```

## 修正完了報告

### 実施した修正内容
`docs/req-def/requirements.md` の「メールアドレスの変更」に、変更確定と同時に該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）し、新メールアドレスでの再度ログインを要求する規定を追加・明記しました。
