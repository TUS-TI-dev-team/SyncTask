# OTP誤入力5回失敗時の自動再送に伴う手動再送クールダウンタイマーのリセット仕様未定義

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-16 02:49:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「非機能要件 > セキュリティ > OTP要件（L215-L225）」において、OTP誤入力5回失敗時に新OTPを自動生成・再送信する仕様と、画面上の手動再送ボタンに対する60秒間のクールダウン期間が規定されていますが、5回失敗による「自動再送」が発火した際に、画面上の手動再送ボタンのクールダウンタイマー（60秒）がリセット・再適用されるかどうかの仕様が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L215-L225 に以下の記述があります：

```markdown
- 5回失敗時の挙動:
	- パスワードリセット OTPの場合
		- 有効な登録済みメールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 未登録（存在しない）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- 新規登録 OTPの場合
		- 新規有効メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 重複（登録済み）メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
	- アカウント編集（メールアドレス変更） OTPの場合
		- 未使用の新規メールアドレスの場合: 5回失敗した時点で旧OTPを失効させ、新OTPを自動生成・再送信して失敗カウントをリセットし、画面上に「新しいOTPを再送しました」と通知する
		- 他ユーザーに登録済みの重複メールアドレスの場合: 5回失敗した時点で画面上に「新しいOTPを再送しました」とメッセージを表示する（実際のメール送信・OTP生成は行わず、ダミー検証失敗を継続する）
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信（初回発行または直前の再送信）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する。なお、再送信回数の上限は設けないが、初回発行から15分の全体有効期限が経過した時点で手続きは無効となる
```

### 仕様上の不備：
1. **自動再送時のクールダウンタイマー連動の曖昧さ**:
   - 初回発行または前回の送信からすでに60秒以上経過している状態で、ユーザーが5回連続で誤入力を行って自動再送が発火した場合、手動再送ボタンのクールダウン（60秒）が直ちに再適用（60秒カウントダウン再スタート）されるのかが明確ではありません。
2. **連続送信（二重送信）の発生リスク**:
   - 自動再送発生時に手動再送ボタンのタイマーがリセットされない場合、自動再送によってメールが送信された直後にユーザーが手動再送ボタンを押下できてしまい、ほぼ同時に2通のメールが送られる不整合やメール送信リソースの浪費が生じる恐れがあります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の L225（手動再送依頼）または L215-L224（5回失敗時の挙動）に、5回失敗による自動再送（ダミー時のダミー表示を含む）が行われた際も手動再送ボタンのクールダウン（60秒）が即座にリセット・再適用される旨を追記してください：

```markdown
- 手動再送依頼: 画面上の「OTPを再送信する」ボタン押下時も、上記と同様の判定を行う。ただし、直前の送信（初回発行、直前の手動再送、または5回失敗時の自動再送のいずれか）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する（5回失敗による自動再送発生時もクールダウン期間が即座にリセット・再適用される）。なお、再送信回数の上限は設けないが、初回発行から15分の全体有効期限が経過した時点で手続きは無効となる
```

### 実施した修正内容
ヒアリングに基づき、`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > OTP要件 > 手動再送依頼」に「ただし、直前の送信（初回発行、直前の手動再送、または5回失敗時の自動再送のいずれか）から60秒間のクールダウン期間を設定し、画面上の再送ボタンを非活性化（カウントダウン表示）として連投を制限する（5回失敗による自動再送発生時もクールダウン期間が即座にリセット・再適用される）」と明記・更新しました。
