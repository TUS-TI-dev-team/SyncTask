# 監査ログの保存期間およびパージ・ローテーション方針の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 20:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
非機能要件の「ログ管理」において、ログイン情報・DBアクセスログ・メール認証ログの記録項目が細かく定められていますが、ログデータの保存期間（Retention Period）および古いログの削除・ローテーション方針が定義されていません。

## 2. 詳細な指摘内容
- **[requirements.md](file:///c:/Users/kazuh/Programming/repos/SyncTask/docs/req-def/requirements.md#L174-L180)**:
  ```markdown
  - ログ管理
  	- ログイン情報
  		- 日時、ユーザーID (UID)、メールアドレス、IPアドレス、ログイン成否
  	- DBへのアクセスログ
  		- 日時、ユーザーID (UID)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
  	- メール認証ログ
  		- 日時、ユーザーID (UID、未登録・未ログイン時は null)、対象メールアドレス、認証種別...
  ```

特に「DBへのアクセスログ」はユーザーのリクエスト毎・エンドポイント呼び出し毎に膨大なレコードが生成されるため、保存期間および肥大化対策（例: 90日間保持後に削除/アーカイブ）を規定しない場合、DBストレージの無制限な圧迫やクエリ性能低下を招きます。

## 3. 推奨される修正案
監査ログの保存期間およびローテーション・パージルールを明記してください。

```markdown
- ログ保持・パージ方針
  - ログインログ・メール認証ログ: 1年間保持し、経過後に順次物理削除する
  - DBアクセスログ: 90日間保持し、日次Cronジョブにて経過レコードを物理削除する
```

### 実施した修正内容
`docs/req-def/requirements.md` の「非機能要件 > ログ管理」に「ログ保持・パージ方針」を追加定義しました。
- ログイン情報およびメール認証ログは 1 年間保持し、経過後に順次物理削除する方針としました。
- DBへのアクセスログは 90 日間保持し、日次 Cron ジョブにて経過レコードを物理削除する方針を明記しました。
