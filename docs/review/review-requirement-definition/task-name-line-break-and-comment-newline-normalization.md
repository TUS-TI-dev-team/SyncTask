# タスク名における改行・制御文字の入力禁止およびコメント改行コード正規化仕様の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-16 02:40:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「機能要件 > タスク管理 > タスク作成（L78-L79）」および「タスク編集（L94, L97）」において、タスク名（1〜100文字）に対する前後の空白文字トリムは定義されていますが、文字列内部に含まれる「改行コード（CR/LF）」や制御文字の入力可否（1行制限）が未定義です。また、コメント（0〜1000文字）における改行文字のカウント基準および改行コード正規化方針が未定義です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L78-L79, L94, L97 に以下の記述があります：

```markdown
- タスク名（前後の空白文字［半角・全角スペース、タブ、改行］を除去［トリム］した上で1〜100文字必須。空白文字のみの入力はバリデーションエラーとして拒否する）
- コメント（前後の空白文字をトリムして保持、0〜1000文字、任意）
- タスクの名前変更（前後の空白文字をトリムした上で1〜100文字必須。空白文字のみの入力は拒否する）
- コメントの変更（前後の空白文字をトリムして保持、0〜1000文字）
```

### 仕様上の不備：
1. **タスク名（タイトル）の内部改行・制御文字の扱い**:
   - タスク名は前後のトリムが行われますが、文字列の中間に改行（`\n`, `\r\n`）が含まれる場合、それを許容するかどうかが明記されていません。
   - タスク名に改行が含まれると、タスク一覧画面のテーブル行、カレンダーセル内のタスク名表示、ポップアップ表示などのUIにおいて予期せぬ複数行レイアウト崩れやテキストはみ出しが発生します。
2. **コメントの改行コード（CRLF vs LF）の文字数カウントと正規化**:
   - コメント（0〜1000文字）において、Windows環境から送信されたCRLF（2文字/2バイト）とLinux/Android環境から送信されたLF（1文字/1バイト）で文字数カウントの判定結果やDB保存時のサイズに差異が生じる可能性があります。システム共通での改行コード正規化（LFへの統一）仕様が記載されていません。

## 3. 推奨される修正案
`docs/req-def/requirements.md` のタスク作成およびタスク編集要件を以下のように具体化してください：

```markdown
- タスク名（前後の空白文字［半角・全角スペース、タブ、改行］を除去［トリム］した上で1〜100文字必須。空白文字のみの入力はバリデーションエラーとして拒否する。なお、タスク名は1行テキストとし、文字列内部の改行コード［CR/LF］やタブ等の制御文字はバリデーションエラーとして拒否、または半角スペース1文字に自動置換して保持する）
- コメント（前後の空白文字をトリムして保持、0〜1000文字、任意。改行コードはシステム内部で一律 `\n`［LF］に正規化し、改行1つにつき1文字として文字数カウントを行う）
```

### 実施した修正内容
ヒアリング結果に基づき、`docs/req-def/requirements.md` のタスク作成およびタスク編集要件を更新しました。「タスク名は1行テキストとし、文字列内部の改行コード［CR/LF］やタブ等の制御文字の入力はバリデーションエラーとして拒否する」旨、および「コメントの改行コードはシステム内部で一律 `\n`［LF］に正規化し、改行1つにつき1文字として文字数カウントを行う」旨を明記しました。
