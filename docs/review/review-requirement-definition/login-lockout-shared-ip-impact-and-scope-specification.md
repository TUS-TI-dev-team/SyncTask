# ログイン失敗ロックアウトにおける「同一IPアドレス」判定条件による共有ネットワーク影響の仕様明確化

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-13 21:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書において、ログイン連続失敗時のアカウントロックアウト条件として「同一メールアドレスまたは同一IPアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、30分間ロックアウトする」と定められています。しかし、大学等の共有ネットワーク環境（同一送信元IP）において同一IP判定のみで全体ロックアウトが発動した場合、無関係な第三者ユーザーが巻き込まれてログイン不能になるリスク（DoS状態）について、条件や挙動が明確化されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L16（利用者の範囲）**:
  ```markdown
  - 対象：大学生
  ```

- **L146-L148（ログイン認証のロックアウト要件）**:
  ```markdown
  - 同一メールアドレスまたは同一IPアドレスに対して、直近15分間に5回連続でログイン認証に失敗した場合、30分間ロックアウトする
  - 失敗カウントの保持期間: 最後の失敗試行から15分経過、またはログイン成功時に失敗カウントを0にリセットする
  - ロックアウト期間中（30分間）のログイン試行は、正しいパスワードが入力された場合であっても認証拒否（1s±0.1s遅延）とする
  ```

### 仕様上の不備：
本アプリのターゲット層は「大学生」であり、大学のキャンパスWi-Fi、図書館、研究室などのNAT環境・共有プロキシを経由して多数のユーザーが「同一の送信元IPアドレス」から同時に利用することが強く想定されます。

もしロックアウトのトリガー条件が「同一IPアドレス単体での5回失敗」かつその対象が「そのIPからの全ログインリクエストの拒否」である場合、ある1人のユーザー（または悪意ある第三者）が5回パスワードを間違えただけで、同一大学Wi-Fiを利用するその他の全ての正常なユーザーが30分間ログインできなくなる深刻なサービス拒否（DoS）状態が発生します。

逆に、ロックアウト判定を「同一IPアドレスかつ同一メールアドレスの組み合わせ」とするのか、あるいは「同一メールアドレスでの5回失敗」および「同一IPアドレスからの異種アカウントに対する爆発的なパスワードハザード攻撃（全アカウント対象の閾値）」を区別するのか、判定の組み合わせ単位および影響範囲が曖昧です。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「ログイン認証」（L146付近）に、共有ネットワーク（同一IPアドレス）環境でのロックアウト判定単位（「同一メールアドレス、または同一IPアドレスかつ同一メールアドレスの組み合わせ」等）を明確に規定してください。

例（組み合わせ単位とする場合）：
```markdown
- ログイン認証
	- 同一メールアドレス、または同一IPアドレスと同一メールアドレスの組み合わせに対して、直近15分間に5回連続でログイン認証に失敗した場合、該当メールアドレスに対するログイン試行を30分間ロックアウトする
```

### 実施した修正内容
`/grill-me` インタビューでの合意に基づき、`docs/req-def/requirements.md` のログイン認証（ロックアウト）セクションに「同一メールアドレス、または同一IPアドレスと同一メールアドレスの組み合わせに対して、直近15分間に5回連続でログイン認証に失敗した場合、該当メールアドレスに対するログイン試行を30分間ロックアウトする」旨を定義し、大学のキャンパスWi-Fi等の共有IP環境で他ユーザーが巻き込まれてログイン不能（DoS状態）となる不具合を防止する仕様へと更新・明記しました。
