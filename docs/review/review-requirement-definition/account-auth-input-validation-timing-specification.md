# アカウント作成・パスワードリセット・メールアドレス変更におけるOTP発行前のバリデーション実行タイミングの未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 22:20:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
「アカウント作成」（L26-L32）、「パスワードリセット」（L62-L68）、および「アカウント編集（メールアドレス変更）」（L36-L43）の各フローにおいて、フォームで入力された各項目（ユーザー名、パスワード、メールアドレスのフォーマットや文字数・パスワード複雑性など）に対する入力値バリデーション（Validation）をどのタイミング（OTP送信前かOTP検証時・確定時か）で実行するかの明文規定が存在しません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L26-L30（アカウント作成）**:
  ```markdown
  - アカウント作成
  	- ユーザー名、パスワード、メールアドレスを入力
  	- メール認証を行う
  		- メールにてOTPを送信
  		- サイト内のOTP入力欄にOTPを入力する
  ```
- **L36-L37（メールアドレス変更）**:
  ```markdown
  - メールアドレスの変更
  	- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
  ```
- **L62-L66（パスワードリセット）**:
  ```markdown
  - パスワードリセット
  	- メールにてOTPを送信
  	- サイト内のOTP入力欄にOTPを入力する
  ```

### 仕様上の不備：
1. **バリデーション失敗時のOTP発行無駄遣い・DoSリスク**:
   ユーザーが入力したフォーム値（例: パスワード要件を満たさない文字列、不正な形式のメールアドレス、規定外の長さのユーザー名等）に対するバリデーションが「OTP送信前」に行われない場合、無効なデータ入力に対して不要なOTPが生成され、メール送信サービスのリソースを消費したり、メール配信攻撃（Email Flooding）の足がかりに利用されるリスクが生じます。
2. **エラーフィードバックの遅延**:
   ユーザーがOTP入力・検証を完了した後に「パスワードの要件を満たしていません」等のエラーが表示されると、ユーザー体験（UX）が著しく損なわれます。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の各フロー（アカウント作成、メールアドレス変更、パスワードリセット）の記述に、**「入力フォームの送信時（OTP生成・メール送信の前）に、バックエンドにて全入力項目のバリデーションチェックを行い、エラーが1件でもある場合はOTPを発行せず画面上に即座にエラーメッセージを表示する」** 旨を共通仕様として明記してください。

### 実施した修正内容
`docs/req-def/requirements.md` の「アカウント作成」「メールアドレスの変更」「パスワードリセット」の各フローにおいて、フォーム送信時（OTP生成・メール送信の前）にバックエンドにて入力値バリデーションを一括実施し、不備がある場合はOTPを発行せずエラー表示する旨が明文化されていることを確認し、完了としました。
