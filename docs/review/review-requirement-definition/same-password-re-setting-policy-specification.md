# パスワード変更およびパスワードリセット時における現在と同一のパスワード設定可否仕様の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 22:20:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
「パスワード変更」（L50-L53）および「パスワードリセット」（L62-L68）機能において、新しく設定・入力された変更後パスワードが「現在使用中のパスワードと同一（変更なし）」である場合のシステム挙動・バリデーション規則が定義されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L50-L53（パスワード変更）**:
  ```markdown
  - パスワード変更
  	- ログイン後のみ可能
  	- 既存のパスワードを知っていれば変更できる（5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト）
  	- 変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
  ```
- **L62-L68（パスワードリセット）**:
  ```markdown
  - パスワードリセット
  	- メールにてOTPを送信・検証成功（仮セッション発行）
  	- 変更後パスワードを入力後、新パスワードを設定完了すると同時に当該パスワードリセット用OTP/仮セッションを直ちに失効・物理削除し、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
  ```

### 仕様上の不備：
1. **現在と同一のパスワードへの変更許可リスク**:
   ユーザーが現在のパスワードと全く同じ文字列を「新パスワード」として入力した場合に、それを成功として受け入れるか、あるいはエラーとして拒否するかが明記されていません。
2. **セキュリティ上の懸念**:
   パスワードリセットやパスワード変更において、現在と同一のパスワードへの変更を許可してしまうと、パスワードの更新・安全化という本来の機能的意義が薄れるほか、セッションを一括無効化して再ログインを行わせる防犯的価値が低下します。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「パスワード変更」および「パスワードリセット」の各要件記述に、現在設定中のパスワードと同一の文字列への変更をバリデーションエラー（「現在のパスワードと同じパスワードは設定できません」）として拒否する仕様を追加・明記してください。

例（パスワード変更の場合）：
```markdown
	- パスワード変更
		- ログイン後のみ可能
		- 既存のパスワードを知っていれば変更できる（5回連続で既存パスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト）
		- 新パスワードが現在設定中のパスワードと同一の場合は「現在のパスワードと同じパスワードは設定できません」とエラー表示し拒否する
		- 変更後パスワードを入力した後、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
```

### 実施した修正内容
ヒアリングの結果に基づき、パスワード変更およびパスワードリセットにおける「現在設定中のパスワードと同一のパスワードの再設定」については、エラーで拒否せず許可する方針（同一パスワード入力時も更新成功として受け入れ・セッション一括無効化）を確定しました。現状の記述で要求を満たしていることを確認の上、ステータスを解決済みに更新しました。
