# メールアドレス変更手続き中における新旧メールアドレスの認証状態および重複ロックの未定義

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-13 20:40:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
アカウント編集における「メールアドレス変更」機能（L34-L38）において、新メールアドレス宛にOTPを発行してから認証を完了するまでの「変更手続き中（Pending状態）」における、ログイン認証で使用するメールアドレスおよび新メールアドレスに対する他ユーザーの重複登録の扱いが定義されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L34-L38 に以下の記述があります：

```markdown
- メールアドレスの変更
	- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
	- 変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する
	- 変更先メールアドレスが既に他ユーザーに登録済みの場合は、メールアドレスの登録有無を秘匿するため、実際にはOTPを発行せずダミーOTP入力画面へ遷移する
	- 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
```

### 仕様上の不備：
1. **変更未完了時のログイン識別子**:
   メールアドレス変更のOTP発行後、ユーザーが認証を確定する前にログアウトしたり別端末からログインしようとした場合、ログインに使用するメールアドレスは「変更前の旧メールアドレス」である必要がありますが、これが明記されていません。
2. **変更手続き中の新メールアドレスの排他ロック**:
   ユーザーAが `new@example.com` への変更リクエストを行いOTP待機状態（有効期限5分）にある間に、別ユーザーBが `new@example.com` で新規会員登録やメールアドレス変更を試みた場合、`new@example.com` は仮押さえ（ロック）されているべきか、あるいは後勝ちなのかが定義されていません。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「メールアドレスの変更」に以下の規定を追加してください：

```markdown
- メールアドレスの変更
	- 変更先の新メールアドレスにOTPを送信し、メール認証を完了することで変更を確定する
	- 変更先メールアドレスが現在設定中の自分自身のメールアドレスと同一の場合は「現在のメールアドレスと同じです」とエラー表示し拒否する
	- 変更先メールアドレスが既に他ユーザーに登録済みの場合は、メールアドレスの登録有無を秘匿するため、実際にはOTPを発行せずダミーOTP入力画面へ遷移する
	- 変更完了時、旧メールアドレス宛に変更完了通知メールを送信する
	- メール認証未完了の「変更手続き中」状態においても、ログイン識別子は変更前の旧メールアドレスが維持される
	- OTP有効期限内（5分間）は、変更先予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または期限切れまで排他維持する
```

### 実施した修正内容
要件定義書（`requirements.md`）の「アカウント編集 - メールアドレスの変更」セクションにおいて、OTP認証完了前の「変更手続き中（Pending）」状態におけるログイン識別子は旧メールアドレスが維持されること、およびOTP有効期限内（5分間）は新メールアドレスが排他ロック（他ユーザーからのリクエストにはダミーOTP画面を返却）されることを明記しました。
