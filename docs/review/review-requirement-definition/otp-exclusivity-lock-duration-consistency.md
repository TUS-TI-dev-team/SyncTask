# OTP排他ロック有効期間の記述不整合（単一5分間表記と最大15分間表記の齟齬）

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-16 02:22:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書内の「アカウント作成（L34）」「アカウント編集 - メールアドレス変更（L50）」「非機能要件 - アカウント新規作成（L192）」において、メールアドレスの排他ロック期間が「OTP有効期限内（5分間）」と記述されていますが、後述の「OTP要件（L207）」および「セッション管理（L255）」では「再送信を行っても、1回の手続きにおけるセッションおよび排他ロックの全体最大有効期限は初回発行から15分間」と定義されており、セクション間で期間表記の齟齬・曖昧さがあります。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の以下の箇所に記載があります：

- **L34（アカウント作成） / L50（メールアドレス変更） / L192（セキュリティ）**:
  ```markdown
  - OTP有効期限内（5分間）は、作成予定のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または有効期限切れまで排他維持する
  ```
- **L207（OTP要件） / L255（セッション管理）**:
  ```markdown
  - 有効期限: 発行から5分間（ただし再送信を行っても、1回の手続きにおけるセッションおよび排他ロックの全体最大有効期限は初回発行から15分間とする。15分経過時はセッションおよび排他ロックを失効して初期画面へ戻す）
  ```

### 仕様上の不備：
1. **排他ロック解除タイミングの解釈不一致リスク**:
   - ユーザーが手動または自動でOTPの再送信を行い、手続きセッションが最大15分まで継続している場合、他ユーザーからの割り込み・重複を防ぐ排他ロックが「最初の5分で切れてしまうのか」、それとも「セッションが継続している限り全体最大15分間維持されるのか」が、L34/L50/L192の「5分間」という単一記述により誤解を招く原因となっています。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の L34, L50, L192 における記述を、L207/L255 の定義と整合するように更新してください。

### 実施した修正内容
`docs/req-def/requirements.md` の「アカウント作成」「メールアドレスの変更」「非機能要件 > セキュリティ > アカウント新規作成」の各箇所における排他ロック期間の記述を、「OTPセッション有効期間中（初回発行から5分間、再送信を含め全体最大15分間）」に統一・更新し、セクション間の不整合を解消しました。
