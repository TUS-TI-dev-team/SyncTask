# 新規アカウント登録手続き中におけるメールアドレスの排他ロック仕様の欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:02:19
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「アカウント編集 - メールアドレスの変更（L40）」では、手続き中の新メールアドレスに対して5分間の排他ロック（他ユーザーからの重複リクエストに対するダミーOTP応答）が定義されていますが、「アカウント作成（新規登録、L26-L30, L142-L145）」における認証未完了の登録手続き中（Pending）状態にあるメールアドレスへの排他ロック仕様が欠落しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L143 には以下の記述があります：

```markdown
- アカウント新規作成
  - アカウント登録時にすでに有効な他ユーザー（未削除アカウント）として登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
```

### 仕様上の不備：
1. **未確定登録手続き中アドレスに対する割り込み・上書きの発生**:
   ユーザーAが `user@example.com` を入力して新規登録を開始し、OTP有効期限（5分間）の入力待機画面にある間に、第三者であるユーザーBが同一の `user@example.com` で新規アカウント登録やメールアドレス変更をリクエストした場合、`user@example.com` はまだDB上に「有効な他ユーザー（登録済みアカウント）」として存在していません。
2. **挙動の不整合**:
   L143の判定条件（登録済みユーザーの存在チェック）のみでは、ユーザーBからのリクエストに対して本物のOTPが送信されてユーザーAのPending状態が上書きされたり、競合が発生します。メールアドレス変更（L40）と同様に、新規登録手続き中であってもOTP有効期限内（5分間）は対象メールアドレスを排他ロックし、他ユーザーからの重複申請にはダミーOTP画面を返却する仕様が必要です。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > アカウント新規作成」セクションに、以下の排他ロック規定を追加してください：

```markdown
- アカウント新規作成
  - アカウント登録時にすでに有効な他ユーザー（未削除アカウント）として登録されているメールアドレスが入力された場合はOTPの発行を行わない状態でOTP入力画面に遷移させる
  - OTP有効期限内（5分間）は、新規登録手続き中（未認証）のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または期限切れまで排他維持する
  - 入力制限(5回)を超えて間違えた場合はOTPを再送したというメッセージを表示させる(...)
```

## 修正完了報告

### 実施した修正内容
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ > アカウント新規作成」に、「OTP有効期限内（5分間）は、新規登録手続き中（未認証）のメールアドレスに対する他ユーザーからの重複登録・変更リクエストを拒否（ダミーOTP処理対象）とし、認証確定または期限切れまで排他維持する」規定を追加し、登録手続き中の割り込み・競合防止およびユーザー存在の秘匿性を担保しました。
