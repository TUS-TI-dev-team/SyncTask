# パスワードハッシュ化アルゴリズムおよびソルト生成仕様の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-16 02:40:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「非機能要件 > セキュリティ（L177-L267）」および「パスワード要件（L241-L244）」において、ユーザーのパスワードをデータベースに保存する際の安全なパスワードハッシュ化アルゴリズム（例: Argon2id, bcrypt 等）、ソルト（Salt）の生成・付与、および平文保存の明示的禁止についてのセキュリティ要件が定義されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L241-L244 にパスワード強度要件が記述されています：

```markdown
- パスワード要件
	- 8文字以上128文字以下
	- 英大文字、英小文字、数字、記号( `!"#$%&'()=-~^|\{}[]+;:*_/?.>,<` )の4種類のうち3種類以上を含むこと
	- ユーザ名文字列、およびメールアドレスの @ より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する（いずれも大文字・小文字を区別せず［Case-Insensitive］に部分一致判定を行う）
```

### セキュリティ上の不備：
1. **DB保存時のハッシュ化方式の未定義**:
   - パスワードの入力バリデーション規則は規定されていますが、システム内部（DB等）でパスワードをどのような暗号学的ハッシュ関数を用いて安全にハッシュ化・保存すべきかが記載されていません。
2. **クラッキング耐性・セキュリティリスク**:
   - 要件定義書でセキュアなパスワードハッシュ化方式が指定されていない場合、DB設計や実装フェーズで MD5, SHA-256, SHA-512 等の高速ハッシュ関数や平文保存が採用されてしまうリスクがあり、万が一データベースが漏洩した際にオフライン辞書攻撃やレインボーテーブル攻撃によってパスワードが容易にクラックされる危険性があります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「非機能要件 > セキュリティ」配下に「パスワード保存仕様」を追加し、安全なハッシュ化アルゴリズム（Argon2id または bcrypt）の採用、暗号論的擬似乱数によるソルト付与、平文保存の禁止を明記してください：

```markdown
- パスワード保存仕様
	- ユーザーのパスワードは平文でDBに保存することを厳禁とし、安全なパスワードハッシュ関数（Argon2id 推奨、または bcrypt コスト係数12以上）を用いてハッシュ化して保存する
	- パスワードハッシュ化時にはユーザー（パスワードレコード）ごとに暗号論的に安全な擬似乱数生成器（CSPRNG）により一意なソルト（Salt）を自動生成・付与してストレッチングを実施し、レインボーテーブル攻撃を防止する
```

### 実施した修正内容
ヒアリング結果に基づき、要件定義書で特定のハッシュアルゴリズムを固定せず、`docs/req-def/requirements.md` の「非機能要件 > セキュリティ」に「パスワード保存仕様」を追加しました。「ユーザーのパスワードは平文でDBに保存することを厳禁とし、安全なパスワードハッシュ関数を用いてハッシュ化して保存する」「パスワードレコードごとに暗号論的一意なソルトを付与してストレッチング・ハッシュ化を行いレインボーテーブル攻撃を防止する」旨を規定しました。
