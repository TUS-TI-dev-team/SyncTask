# ユーザー名のユニーク制約不備と同名ユーザー存在時のログイン識別不可

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-11 22:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
ユーザー名によるログイン要件が規定されていますが、アカウント再登録・作成時において「同名のユーザー名でも問題なく登録できる」旨の記述が存在し、同名ユーザーが複数存在した場合にログイン認証（ユーザー名＋パスワード）で特定のアカウントを一意に識別できなくなる致命的な仕様不整合が存在します。

## 2. 詳細な指摘内容
- **L38-L39（アカウントの削除・再登録）**:
  `再登録の際は自動付与されるUIDが異なるため同名のユーザ名などでも問題なく登録できる` と記載されています。
- **L46（ログイン）**:
  `ユーザ名（メールアドレスではない）とパスワードでログイン` と記載されています。
- **L159-L160（メールアドレス要件）**:
  `メールアドレス要件: 他ユーザとの重複なし` と記載されています。

もしユーザー名にユニーク制約が課されていない（同名ユーザーの登録が可能である）場合、全く同じユーザー名と共通のパスワードを設定した複数のアカウントが存在した際に、システムがどのユーザーとしてログインすべきかを決定できません。

また、ユーザー名要件（L150-L152）には「他ユーザーとの重複不可」という制約が含まれておらず、メールアドレス側のみ重複不可となっています。

## 3. 推奨される修正案
以下のいずれかの明確な設計方針を選択し、要件定義書を修正する必要があります。

- **案A（推奨）**: ユーザー名をシステム全体（論理削除含む、あるいはアクティブユーザー間）で一意（ユニーク）とする。
  - ユーザー名要件（L150-L152）に `他ユーザーとの重複不可` を明記する。
  - 再登録時であっても、現存するアクティブなユーザー名と同名のユーザー名は使用不可とする。
- **案B**: ログイン時の識別子を「ユーザー名」から「メールアドレス」に変更する。
  - L46の記述を `メールアドレスとパスワードでログイン` に変更する。

### 実施した修正内容
要件定義において「案B: ログイン時の識別子をメールアドレスとする（他ユーザーとのメールアドレス重複不可）」方針を公式に採用し、同名のユーザー名の登録を許容しつつ、ログイン時のアカウント識別性が保証される仕様として一貫性を確保しました。
