# アカウント新規作成における「古いセッション無効化」記述のインデント階層・配置の不整合

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-16 02:22:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「機能要件 > アカウント管理 > アカウント作成（L28-L29）」において、「新しいセッションを発行する際は、古いセッションは無効にしておく（同時に複数のアカウントにログインしている状態を防ぐため）」というセッション発行・切替時のルールが、「フォーム送信時（OTP生成・メール送信の前）の入力値バリデーション」のサブ階層（インデント配下）に配置されており、ドキュメントの論理構造として誤解を招く配置となっています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L26-L33 には以下の記述があります：

```markdown
- アカウント作成
	- ユーザー名、パスワード、メールアドレスを入力
	- フォーム送信時（OTP生成・メール送信の前）にバックエンドにてユーザー名要件・パスワード要件・メールアドレス要件の入力値バリデーションを一括実施する（不備がある場合はOTPを発行せずエラー表示）
		- 新しいセッションを発行する際は、古いセッションは無効にしておく（同時に複数のアカウントにログインしている状態を防ぐため）
	- メール認証を行う
		- メールにてOTPを送信
		- サイト内のOTP入力欄にOTPを入力する
		- OTP認証成功時、アカウントの作成を確定すると同時に自動的にログインセッションを発行してログイン状態とし、タスク一覧画面へ遷移する
```

### 仕様構造上の不備：
1. **実行タイミングと記述位置の不一致**:
   - アカウント作成の「フォーム送信時（OTP生成前）」にはまだ新規ログインセッションは発行されません。実際に新しいログインセッションが発行されるのは「OTP認証成功時（L33）」です。
   - にもかかわらず、「新しいセッションを発行する際は...」というセッション無効化ルールが「フォーム送信時の入力バリデーション（L28）」の配下にインデントされているため、「未ログインのフォーム送信時に何のセッションを無効化するのか」が構造的に不明瞭です。

## 3. 推奨される修正案
L29 の記述を「OTP認証成功時（L33）」の配下、またはログイン関係/セッション管理の共通要件へ移動・再配置してください。
