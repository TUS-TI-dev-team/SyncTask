# パスワードリセットにおける仮セッション（検証済み）の認可スコープ制限の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-16 02:04:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「ログイン関係 > パスワードリセット（L75-L76）」および「セッション管理 > OTPセッション（L253）」において、パスワードリセットのOTP検証成功時にステータスが「検証済み」に変更された15分間の仮セッションが発行されますが、この仮セッションがアクセス可能な「認可スコープ（許可エンドポイント）」が明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L75-L76 および L253 に以下の記述があります：

- **L75-L76**:
  - `OTP検証成功時に当該OTPセッションのステータスを「検証済み」に変更し、そこから仮セッションの有効期限を15分間とする`
  - `変更後パスワードを入力後、新パスワードを設定完了すると同時に当該パスワードリセット用OTP/仮セッションを直ちに失効・物理削除し、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する`
- **L253**:
  - `有効期限 5分（ただしパスワードリセットにおけるOTP検証成功時はステータスを「検証済み」に変更し、そこから有効期限を15分間とする）`

### 仕様上の不備・認可バイパスリスク：
1. **認可スコープ（アクセス可能API）の未限定**:
   - パスワードリセット用の仮セッションは、「新パスワード設定エンドポイント（例: `POST /api/auth/password-reset/confirm`）」のみを実行するための単一目的の一時トークン/セッションである必要があります。
   - 要件定義書にスコープ制限が明記されていない場合、実装時に通常のログインセッション用認証ミドルウェアと共通化されたり、ユーザー情報閲覧APIやタスク操作APIなど他の保護されたリソースへアクセスできてしまう認可バイパス・権限昇格（Broken Object Level Authorization / BOLA）の脆弱性が発生するリスクがあります。
2. **仮セッションCookie/トークンの明示的破棄**:
   - 新パスワード設定完了時、DB上のOTPレコード物理削除だけでなく、クライアント側の仮セッションCookie/トークンを確実に破棄（クリア）する仕様を明記する必要があります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「パスワードリセット」および「セッション管理」セクションに、仮セッションの認可スコープ制限を明記してください：

```markdown
		- OTP検証成功時に当該OTPセッションのステータスを「検証済み」に変更し、そこから仮セッションの有効期限を15分間とする（この仮セッションは新パスワード設定APIへのアクセスのみを許可する制限付きセッションとし、タスク操作等の通常ログイン必須APIへのアクセス権限は一切付与しない）
		- 変更後パスワードを入力後、新パスワードを設定完了すると同時に当該パスワードリセット用OTP/仮セッションを直ちに失効・DBから物理削除し（クライアント側の仮セッションCookieも消去）、該当ユーザーのすべての既存ログインセッション（他端末・他ブラウザを含む）を一括無効化（物理削除）して再度ログインを要求する
```

## 修正完了報告

### 実施した修正内容
`docs/req-def/requirements.md` の「パスワードリセット」および「セッション管理」において、OTP検証成功時に発行される15分間の仮セッションが「新パスワード設定APIへのアクセスのみを許可する制限付きセッションであり、タスク操作等の通常ログイン必須APIへのアクセス権限を一切付与しない」認可スコープ制限を明記しました。また新パスワード設定完了時にDBから物理削除するとともにクライアント側Cookieを確実に消去する仕様を明確化しました。
