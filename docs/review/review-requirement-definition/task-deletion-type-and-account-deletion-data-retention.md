# タスク個別の削除種別（物理削除/論理削除）およびアカウント論理削除時のタスクデータ保持・削除方針の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-13 21:02:19
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「タスク管理 > タスク削除（L74）」において、ユーザーが不要なタスクを削除した際のデータベース上の削除方式（物理削除か論理削除か）が明記されていません。また、「アカウント削除（L41-L46）」によってアカウント本体が論理削除された際の、所有するタスクデータのDB保持・削除方針が未定義です。

## 2. 詳細な指摘内容
1. **個別タスク削除の種別未定義 (L74)**:
   - アカウント削除（L43）では「アカウント本体は論理削除、ログインセッションは物理削除」と明記されていますが、タスク削除（L74）については削除方式が記載されておらず、物理削除なのか削除フラグ（`deleted_at` 等）による論理削除なのか開発者が判断できません。
2. **アカウント論理削除に伴うタスクデータのライフサイクル未定義 (L46)**:
   - L46には「アカウント論理削除に伴い、所有するタスクデータへの参照・操作アクセス権限も即座に無効化する」とありますが、アクセス権限が無効化された後、DB上のタスクデータレコード自体を物理削除するのか、論理削除状態として保持するのか、あるいはアカウントデータとともに一定期間後に一括パージするのかが定義されていません。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の「タスク管理」および「アカウントの削除」セクションに以下の規定を追記してください：

```markdown
- タスク管理
  - タスク削除
    - ユーザー操作によるタスクの削除は物理削除とする

- アカウントの削除
  - アカウント論理削除に伴い、所有するタスクデータへの参照・操作アクセス権限も即座に無効化する（アカウント論理削除中はタスクデータもアクセス不可状態として保持され、アカウント物理パージ時に一括削除される）
```
