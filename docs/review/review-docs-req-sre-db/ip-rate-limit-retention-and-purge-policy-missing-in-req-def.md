# 要件定義書におけるIPアドレス単位レートリミットの保持期間・パージ方針の記載欠落

- **Status**: Open
- **Severity**: Minor
- **Created At**: 2026-08-18 20:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)
  - [database_design.md](docs/design/database_design.md)
  - [job_design.md](docs/design/job_design.md)

## 1. 問題の概要
要件定義書の「セキュリティ > ログイン認証」において「IPアドレス単位レートリミット」が規定されていますが、「非機能要件 > ログ管理 > ログ保持・パージ方針」および「セッション管理」の各項において、このレートリミット管理用レコードのデータ保持期間および定期削除（パージ）方針が記載されておらず、DB設計・ジョブ設計との間に要件上の記載漏れがあります。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L199 に以下のセキュリティ要件があります：

```markdown
	- IPアドレス単位レートリミット（パスワードスプレー対策）: 同一IPアドレスから5分間のインターバルを挟まずに累計30回以上のログイン認証失敗が発生した場合、該当IPアドレスからのログインAPIリクエストを一律15分間一時遮断（HTTP 429 Too Many Requests、遅延1s±0.1s）する
```

しかし、「非機能要件 > ログ管理 > ログ保持・パージ方針」（L251-253）には以下のようにログイン情報ログ、APIアクセスログ、メール認証ログのパージ方針しか記載されていません：

```markdown
	- ログ保持・パージ方針
		- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
		- APIへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
```

### 問題点：
- 設計書側（`database_design.md` L116、`job_design.md` L150）では、`LOGIN_IP_RATE_LIMIT` テーブルの保持期間およびパージ用日次Cronジョブ（`CLEANUP_RATE_LIMITS` 毎日 03:00 JST / Cron: `0 3 * * *`）が定義されています。
- 要件定義書にこのデータ保持方針が記載されていないため、要件定義書単体で不要データ蓄積の防止方針やバッチ仕様を追跡することができなくなっています。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の L253 付近（ログ保持・パージ方針）または L199 付近に、IPアドレス単位レートリミットデータの保持期間と定期パージ方針を追記してください：

```markdown
	- ログ保持・パージ方針
		- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
		- APIへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
		- ログインレートリミット管理データ: 遮断解除日時を経過し、かつ最終失敗から24時間以上経過した不要レコードは、日次Cronジョブ（毎日 03:00 JST / Cron: `0 3 * * *`）にてDBから物理削除する
```
