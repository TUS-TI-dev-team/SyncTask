# OTP除外文字リストの大文字小文字表記混在および利用可能文字セットの曖昧さ

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-18 19:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
OTPの文字種要件において、「英数字は大文字小文字を区別しない」と規定されている一方で、除外文字リストに大文字・小文字が混在して列挙されており、また全角カンマの使用や生成・検証時の文字セットおよび正規化方式が曖昧です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L221-228 に以下の記述があります：

```markdown
- OTP要件
	- OTPは英数字8桁，英数字は大文字小文字を区別しない
	  - ただし下記の文字はユーザに混乱を与える可能性があるため利用しない
	    - 「O」と「0」（オー と 数字のゼロ）
		- 「I」と「l」と「1」（アイ、エル、数字のイチ）
		- 「S」と「5」（エス と 数字のゴ）
		- 「Z」と「2」（ゼット と 数字のニ）
		- 「B」と「8」（ビー と 数字のハチ）
```

### 問題点：
1. **全角カンマ**: `OTPは英数字8桁，英数字は...` のカンマが全角文字 `，` になっています。
2. **大文字小文字の混在**:
   - `「I」と「l」と「1」` のみ小文字の `l` が明記されていますが、他の項目（O, S, Z, B）は大文字のみ列挙されています。
   - 「英数字は大文字小文字を区別しない（Case-Insensitive）」と定めているため、システム内部およびユーザー入力照合時にどのような処理を行うのか（例: 生成時は英大文字＋数字のみで生成し、検証時に入力文字列を大文字化して比較する）が明記されていないと、実装時に混乱を招きます。
3. **利用可能な文字セットの明示**:
   - 英数字36文字（A-Z, 0-9）から除外文字（O, 0, I, 1, S, 5, Z, 2, B, 8）を引いた残りの文字セット（26文字: `A, C, D, E, F, G, H, J, K, L, M, N, P, Q, R, T, U, V, W, X, Y, 3, 4, 6, 7, 9` ※Lを除外するかどうかも含め）を具体的に定義することで、生成アルゴリズムの仕様が確定します。

## 3. 推奨される修正案
L221-228 を以下のように修正し、全角記号を修正するとともに生成文字セットと検証時の大文字正規化ルールを明確化してください：

```markdown
- OTP要件
	- OTPは英数字8桁、英数字は大文字小文字を区別しない（Case-Insensitive）
	  - 生成仕様: ユーザーの視認性向上・誤読防止のため、混同しやすい以下の文字を除外した英大文字および数字（計26文字: `A, C, D, E, F, G, H, J, K, L, M, N, P, Q, R, T, U, V, W, X, Y, 3, 4, 6, 7, 9`）からランダムに8桁生成する
	    - 除外文字: `O`, `0`（オー / ゼロ）、`I`, `1`（アイ / イチ）、`S`, `5`（エス / ゴ）、`Z`, `2`（ゼット / ニ）、`B`, `8`（ビー / ハチ）
	  - 検証仕様: 入力されたOTP文字列の前後の空白を除去（トリム）し、大文字に正規化（`toUpperCase()`）した上で照合を行う
```
