# メールアドレス変更時における現在のパスワード再認証要件の未定義

- **Status**: Open
- **Severity**: Medium
- **Created At**: 2026-08-18 19:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
アカウント管理における「アカウント削除」および「パスワード変更」では「現在のパスワードによる再認証」が必須と明記されているのに対し、「メールアドレス変更」手続きにおいてはパスワード再認証の要否が明記されておらず、セキュリティ設計上の曖昧さがあります。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` において各アカウント操作の要件は以下のように記述されています：

1. **ユーザ名の変更 (L40)**:
   - `パスワード再認証は不要（入力・送信で即時変更）` と不要であることが明記。
2. **アカウントの削除 (L53)**:
   - `ログイン後の画面からのみ可能 (確認ダイアログ + パスワード再認証要。ログイン後の再認証(アカウント削除・パスワード変更時利用)にて5回連続で現在のパスワード認証に失敗した場合はログインセッションを破棄［物理削除］してログイン画面にリダイレクトする)` と明記。
3. **パスワード変更 (L60)**:
   - `既存のパスワードを知っていれば変更できる（ログイン後の再認証(アカウント削除・パスワード変更時利用)にて5回連続で現在のパスワード認証に失敗した場合はログインセッションを破棄してログイン画面にリダイレクト）` と明記。
4. **メールアドレスの変更 (L42-51, L213-218)**:
   - メールアドレス変更手続きにおいて、新メールアドレスへのOTP送信・検証については詳細に記述されているものの、**申請時に「現在のパスワード」の入力を要求するかどうか** が記載されていません。
5. **セキュリティ要件 (L219-220)**:
   - `ログイン後の再認証(アカウント削除・パスワード変更時利用)にて5回連続で現在のパスワードの認証に失敗したら、セッションを破棄（物理削除）してログイン画面に戻す` と記載されており、対象が「アカウント削除・パスワード変更時利用」のみとなっています。

### セキュリティ上の懸念：
メールアドレスはアカウントのログイン識別子およびパスワードリセットの送達先となる最も重要な認証情報です。離席時やセッションハイジャック等の際にパスワード再認証なしでメールアドレス変更リクエスト（新メールアドレスへのOTP送達）を許すと、攻撃者が自分のメールアドレスにOTPを送ってアカウントを容易に乗っ取ることが可能になります。
したがって、メールアドレス変更申請時にも現在のパスワード再認証を必須とするか、あるいはOTP送達のみとするのかを明確に定義する必要があります。

## 3. 推奨される修正案
メールアドレス変更手続き（L43付近およびL219-220）において、申請時に現在のパスワード再認証を必須とする仕様を追記・統一してください：

```markdown
<!-- L43付近 -->
		- メールアドレスの変更
			- ログイン後の画面からのみ可能（確認ダイアログ + 現在のパスワード再認証要。5回連続失敗時はセッション破棄・ログイン画面リダイレクト）
			- フォーム送信時（OTP生成・メール送信の前）にバックエンドにてパスワード再認証および新メールアドレスの入力値バリデーションを一括実施する（不備がある場合はOTPを発行せずエラー表示）
```

```markdown
<!-- L219-220 -->
- パスワード変更時、メールアドレス変更時、およびアカウント削除時の「現在のパスワード」再認証
	- ログイン後の再認証（パスワード変更・メールアドレス変更・アカウント削除時利用）にて5回連続で現在のパスワードの認証に失敗したら、セッションを破棄（物理削除）してログイン画面に戻す
```
