# ログ管理におけるAPIアクセスログと定期削除方針の用語不整合

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-18 19:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書の「非機能要件 > ログ管理」において、ログ項目名が「APIへのアクセスログ」に更新されているのに対し、パージ方針では旧名称の「DBへのアクセスログ」のまま残っており、内部で用語の不整合が発生しています。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L250-256 に以下の記述があります：

```markdown
	- APIへのアクセスログ
		- 日時、ユーザーID (UID、未登録・未ログイン時は null)、アクセス元IPアドレス、エンドポイント、閲覧・操作対象リソースID
	- メール認証ログ
		- 日時、ユーザーID (UID、未登録・未ログイン時は null)、対象メールアドレス、認証種別（新規登録 / パスワードリセット / メールアドレス変更）、アクセス元IPアドレス、処理イベント種別（OTP発行 / 検証成功 / 検証失敗 / 手動再送依頼 / 5回失敗時自動処理/ 有効期限切れによる失効）、成否、ダミー処理区分（実処理 / ダミー表示）
	- ログ保持・パージ方針
		- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
		- DBへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
```

L250 では項目名が `APIへのアクセスログ` と定義されているにもかかわらず、L256 のパージ方針では `DBへのアクセスログ: 90日間保持し...` と以前の名称のままとなっています。
これにより、開発者やレビュアーが「DBアクセスログ」という別のログテーブル/ストレージが存在するのか、それとも「APIアクセスログ」のパージ方針なのか混乱するリスクがあります。

## 3. 推奨される修正案
L256 の「DBへのアクセスログ」を「APIへのアクセスログ」に修正し、用語を統一してください：

```markdown
	- ログ保持・パージ方針
		- ログイン情報・メール認証ログ: 1年間（365日間）保持し、日次Cronジョブ（毎日 02:00 JST / Cron: `0 2 * * *`）にて経過レコードを物理削除する
		- APIへのアクセスログ: 90日間保持し、日次Cronジョブ（毎日 01:00 JST / Cron: `0 1 * * *`）にて経過レコードを物理削除する
```
