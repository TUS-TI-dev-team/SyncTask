# OTP有効期限・セッション全体上限およびパスワードリセット時延長仕様の不整合

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-18 19:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
OTP単体の有効期限（5分）、手続き全体の最大有効期限（15分）、およびパスワードリセットにおけるOTP検証成功後の仮セッション有効期限について、「そこから有効期限を15分間延長する」と「そこから仮セッションの有効期限を15分間とする」という表現の食い違いやセッション管理項での定義の曖昧さがあります。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` において、以下の記述が混在しています：

1. **機能要件（パスワードリセット L76）**:
```markdown
OTP検証成功時に当該OTPセッションのステータスを「検証済み」に変更し、そこから仮セッションの有効期限を15分間とする（この仮セッションは新パスワード設定APIへのアクセスのみを許可する制限付きセッションとし、タスク操作等の通常ログイン必須APIへのアクセス権限は付与しない）
```

2. **セキュリティ要件（OTP要件 L229-231）**:
```markdown
有効期限: 発行から5分間（ただし再送信を行っても、1回の手続きにおけるセッションおよび排他ロックの全体最大有効期限は初回発行から15分間とする。15分経過時はセッションおよび排他ロックを失効して特定の画面へリダイレクトさせる）
- OTPの再発行は新しいOTPの有効期限を5分として再度測定する
- OTP発効から5分経過後はユーザにOTPの有効期限が切れたことを知らせ再送信を促す
```

3. **セッション管理（OTPセッション L280-281）**:
```markdown
  - OTPセッション
    - 有効期限 15分（パスワードリセットにおけるOTP検証成功時はステータスを「検証済み」に変更し、そこから有効期限を15分間延長する）
```

### 問題点：
- L281 の「そこから有効期限を15分間延長する」という表現は、「残りの有効期限に15分を加算する」のか「検証成功時点から起算して新たに15分間とする」のかが曖昧です。L76の「そこから仮セッションの有効期限を15分間とする（検証成功時点から15分間）」と表現を統一する必要があります。
- また、セッション管理項（L281）において「有効期限 15分」とだけ書かれているため、個別のOTPコード自体の入力有効期限（5分）と、セッション全体の最大有効期間（初回発行から15分）の2層構造がセッション管理項単体では読み取れなくなっています。
- L229 の「特定の画面へリダイレクトさせる」という記述も、機能要件（L34/L51のアカウント作成画面/アカウント編集画面）と整合した具体的な記述にすることが望まれます。

## 3. 推奨される修正案
`docs/req-def/requirements.md` のセッション管理項（L280-282）およびL229を次のように整理・統一してください：

```markdown
  - OTPセッション
    - 有効期限: セッション発行から最大15分間（ただしセッション内の各OTPコードの入力有効期限は発行から5分間。パスワードリセットにおけるOTP検証成功時はステータスを「検証済み」に変更し、検証成功時刻から起算して新たに15分間の有効期限を設定する）
    - 有効期限切れまたは無効化・使用済みとなったOTPセッションレコードは、新パスワード設定完了時等に直ちに物理削除するほか、Cronジョブ（15分ごと / Cron: `*/15 * * * *` JST）にてDBから一括物理削除する
```
