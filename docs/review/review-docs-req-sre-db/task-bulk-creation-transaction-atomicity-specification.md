# 毎週タスク自動作成におけるトランザクション原子性（All-or-Nothing）とエラー処理要件の明記

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-18 20:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
期間・曜日指定による「毎週タスク自動作成（即時一括生成方式）」において、複数件のタスク（最大100件）を生成・DB登録する処理中にエラーやDB障害が発生した場合のトランザクション原子性（All-or-Nothing / 全件ロールバック）およびエラー応答についての要件定義が明記されていません。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L85-94 に以下の記述があります：

```markdown
		- 期間と曜日を指定し、その範囲内で毎週タスクを自動作成できる（即時一括生成方式）
			- 期間指定: 開始日と終了日をそれぞれYYYY/MM/DD形式で入力（テキスト入力またはポップアップ表示のカレンダーから選択可能）
			- 期間・生成件数バリデーション:
				- 開始日 <= 終了日（開始日と終了日が同一日の場合も指定曜日に合致すれば1件作成可能）
				- 開始日には過去日も指定可能
				- 指定可能な最大期間は1年間（最大52週）以内、かつ計算される生成タスク数は1件以上100件まで（期間内に選択された曜日が1日も含まれず生成件数が0件となる場合は「指定された期間内に該当する曜日が存在しません」とエラー表示し処理を中断する。また、期間および選択曜日の組み合わせにより生成予定件数が100件を超える場合は送信前に警告または送信時に「生成件数が上限（100件）を超えています」とエラー表示し、タスクの一括作成処理を一切実行せず中断する［All-or-Nothing］）
			- 曜日指定: 「日、月、火、水、木、金、土」より1つまたは複数選択可能（1つ以上選択必須）
			- 毎週作成サイクル: 開始日から終了日までの期間内で、選択された該当曜日ごとに毎週タスクを生成する
			- 生成タスクの属性: 入力されたタスク名、優先度、コメント、初期ステータス（「未着手」）を各タスクへコピーする。締切時刻（hh:mm JST）は任意入力とし、指定がある場合はその時刻を各該当日付に適用し、未指定（省略）の場合は該当日の「23:59 JST」をデフォルト締切時刻として適用する
			- 生成後の個別独立性: 自動作成されたタスクはそれぞれ独立した通常タスクとしてDBに個別登録され、以降は個別に編集・状態変更・削除が可能（繰り返しタスク間の一括連動更新機能は提供しない）
```

### 問題点：
- 「送信前の件数チェック」による All-or-Nothing については L90 に記載されていますが、**バックエンドでのDB一括登録処理（INSERT）自体のトランザクション整合性**が明記されていません。
- 例えば、50件の生成対象タスクのうち30件目を登録中にDBタイムアウトやエラーが発生した場合に、一部のタスクのみが登録された中途半端な状態（部分作成）を防ぐため、単一トランザクション内で実行し全件ロールバックすることが必須要件となります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の L94 付近に、トランザクション原子性とエラー処理に関する仕様を追記してください：

```markdown
			- トランザクション原子性: 複数件の一括タスク生成・登録処理はバックエンドにおいて単一のデータベーストランザクション内で実行する。生成処理中の一部でエラーやDB例外が発生した場合は即座に全件ロールバック（All-or-Nothing）し、中途半端な部分作成状態を完全に防止してユーザーへエラーを返却する
```
