# パスワード入力欄のマスキング仕様および表示切替UIの画面間不統一

- **Status**: Open
- **Severity**: Medium
- **Created At**: 2026-08-18 20:50:00
- **Target Files**:
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
`docs/design/screen_design.md` において、ログイン画面では「パスワード入力欄(マスク在り・表示も可能)」と定義されているのに対し、アカウント作成画面では「パスワード入力欄(マスクなし)」と定義されており、さらにパスワード変更画面や再設定画面、アカウント削除画面ではマスキングや表示切替UIの有無が未定義となっており、システム全体でパスワード入力UIの仕様が不統一です。

## 2. 詳細な指摘内容
`docs/design/screen_design.md` におけるパスワード入力欄の各画面での定義は以下のようになっています：

1. **ログイン画面（L7）**:
   - `パスワード入力欄(マスク在り・表示も可能)`
2. **アカウント作成/情報入力画面（L8）**:
   - `パスワード入力欄(マスクなし)`
   - `パスワード確認用入力欄(マスクなし)`
3. **パスワードリセット/パスワード再設定画面（L12）**:
   - `パスワード入力欄`
   - `パスワード確認用入力欄`（マスク有無の記載なし）
4. **パスワード変更画面（L59）**:
   - `現在のパスワード入力欄`
   - `新しいパスワード入力欄`
   - `新しいパスワード（確認）入力欄`（マスク有無の記載なし）
5. **アカウント削除/パスワード再認証画面（L60）**:
   - `現在のパスワード入力欄`（マスク有無の記載なし）

### 問題点：
- アカウント作成画面においてパスワードを平文（マスクなし）固定で表示する設計は、周囲からの覗き見（ショルダーハッキング）のリスクを高めるセキュリティ上の懸念があります。
- パスワード入力欄によって「マスクあり（表示可能）」「マスクなし」「未指定」が混在しており、フロントエンド実装時におけるUIコンポーネントの統一性が損なわれます。

## 3. 推奨される修正案
1. システム全体のすべてのパスワード入力欄（新規作成、ログイン、変更、再設定、削除再認証）において、**「デフォルトはマスク表示（●●●）とし、入力欄右側のトグルアイコン（目のアイコン等）を押下することで平文表示/マスク表示を切り替え可能とする」** 方針に統一してください。
2. `docs/design/screen_design.md` の各画面定義の構成要素欄を更新し、「共通UI・セキュリティ補足」にパスワード入力コンポーネントの統一仕様（マスク表示＋表示切替トグル）を明記してください。
