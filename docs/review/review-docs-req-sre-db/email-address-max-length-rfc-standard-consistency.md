# メールアドレス最大文字数（320文字）とRFC標準規格との乖離

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-18 19:55:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
メールアドレス要件において「320文字以下の文字列」と定義されていますが、RFC 5321（SMTP規格）におけるメールアドレス全体の最大長は 254文字 であり、一般的なDBスキーマ定義（`VARCHAR(254)` / `VARCHAR(255)`）との整合性に注意が必要です。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L273-277 に以下の記述があります：

```markdown
- メールアドレス要件
  - 320文字以下の文字列
  - 入力されたメールアドレス（新規登録、ログイン、メールアドレス変更、パスワードリセット等の全機能）は、前後の空白文字（半角・全角スペース、タブ、改行）を自動的に除去（トリム）して処理する
  - メールアドレスはシステム内部（登録・ログイン・重複判定・認証処理等）で一律小文字（`toLowerCase()`）に正規化して保持・比較し、Case-Insensitive な一意性を保証する
  - 有効な他ユーザ（未削除アカウント）との重複なし
```

### 問題点：
- 「320文字」という上限値は、ローカル部最大64文字 + `@` 1文字 + ドメイン部最大255文字 = 320文字 という古い単純合算に基づく値と考えられます。
- しかし、RFC 5321 (Section 4.5.3.1.3) および RFC 3696 Errata により、有効なメールアドレス（Path）の最大長は **254文字** と規定されています。255文字以上のメールアドレスには実際にメールを到達させることができません。
- DB設計において `VARCHAR(254)` または `VARCHAR(255)` を採用する場合、要件定義で320文字を許容しているとバリデーションとDBカラム長の間で不整合（桁あふれエラーやDBエラー）が発生する原因となります。

## 3. 推奨される修正案
メールアドレスの最大文字数を RFC 5321 準拠の 254文字（または一般的な 255文字）以下と明記し、DB設計との整合性を担保してください：

```markdown
- メールアドレス要件
  - 254文字以下の文字列（RFC 5321準拠）
  - 入力されたメールアドレス（新規登録、ログイン、メールアドレス変更、パスワードリセット等の全機能）は、前後の空白文字（半角・全角スペース、タブ、改行）を自動的に除去（トリム）して処理する
  - メールアドレスはシステム内部（登録・ログイン・重複判定・認証処理等）で一律小文字（`toLowerCase()`）に正規化して保持・比較し、Case-Insensitive な一意性を保証する
  - 有効な他ユーザ（未削除アカウント）との重複なし
```
