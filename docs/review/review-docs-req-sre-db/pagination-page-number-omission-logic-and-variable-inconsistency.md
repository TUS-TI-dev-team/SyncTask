# ページネーション表示省略ロジックの境界値における定義不備および変数名誤記

- **Status**: Open
- **Severity**: Medium
- **Created At**: 2026-08-18 20:50:00
- **Target Files**:
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
`docs/design/screen_design.md` の「ページネーションの補足」において、全ページ数 $N > 10$ の場合のページ番号省略仕様 `[1, 2, ..., n-1, n, n+1, ..., N]` が、カレントページ $n$ の境界値（$n=2, 3$ や $n=N-2, N-1$）で破綻する記述となっており、また条件分岐文内の変数名誤記（「ただしNが下記の場合は下記とする」）が存在します。

## 2. 詳細な指摘内容
`docs/design/screen_design.md` の L22-L27 に以下の記述があります：

```markdown
- ホーム画面，タスク一覧画面にてページネーション操作UIのページ番号表示について下記の仕様に変更
   - 全ページ数Nが10を超える(N>10)の場合
      - 現在のページnに対して: [1, 2, ..., n-1, n, n+1, ..., N]のページ数のみ表示する．ただしNが下記の場合は下記とする
        - n == 1 -> [1, 2, 3, ..., N]
        - n ==N -> [1, 2, ..., N-2, N-1, N]
   - 全ページ数Nが10以下の(N<=10)場合: すべてのページを表示する
```

### 問題点：
1. **変数名の誤記**:
   - `ただしNが下記の場合は下記とする` と全ページ数 $N$ が書かれていますが、条件式は `n == 1`, `n == N` と現在のページ番号 $n$ を判定しているため、`ただしnが下記の場合は下記とする` の誤記です。
2. **境界値における配列生成の破綻**:
   - カレントページ $n = 2$ の場合、一般式 `[1, 2, ..., n-1, n, n+1, ..., N]` に当てはめると `[1, 2, ..., 1, 2, 3, ..., N]` となり、先頭で `1, 2` が重複し、省略記号 `...` の配置が不正になります。
   - $n = 3$ の場合も `[1, 2, ..., 2, 3, 4, ..., N]` となり、連続する数値の間に不要な省略記号が入ってしまいます。
   - 同様に末尾付近の $n = N-1$ や $n = N-2$ の場合も同様に省略記号と数値の並びが破綻します。

## 3. 推奨される修正案
`docs/design/screen_design.md` の L22-L27 を以下のように境界条件を明確に切り分けた定義に修正してください：

```markdown
- ホーム画面、タスク一覧画面におけるページネーション操作UIのページ番号表示仕様：
   - 全ページ数 $N \le 10$ の場合：すべてのページ番号を表示する（`[1, 2, 3, ..., N]`）
   - 全ページ数 $N > 10$ の場合：カレントページ $n$ の位置に応じて以下のように省略記号（`...`）を挟んで表示する：
      - 先頭付近（$n \le 3$）：`[1, 2, 3, 4, ..., N]`
      - 中間位置（$4 \le n \le N - 3$）：`[1, ..., n - 1, n, n + 1, ..., N]`
      - 末尾付近（$n \ge N - 2$）：`[1, ..., N - 3, N - 2, N - 1, N]`
```
