# スマートフォン（Android）対応におけるレスポンシブ画面設計およびレイアウト方針の未定義

- **Status**: Open
- **Severity**: Minor
- **Created At**: 2026-08-18 21:05:00
- **Target Files**:
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
要件定義書においてスマートフォン（Android Chrome / Firefox）が公式サポート対象プラットフォームとして明記されているにもかかわらず、`docs/design/screen_design.md` にモバイル表示（SP幅）におけるレスポンシブレイアウト方針（ナビゲーション、カレンダー、ポップアップ表示等）が一切定義されていません。

## 2. 詳細な指摘内容
- 要件定義書 `docs/req-def/requirements.md` L173-178 において、対象プラットフォームとして PC（Windows/Linux）に加え、スマホ（Android: Chrome / Firefox）が対応ブラウザとして定義されています。
- 一方、`docs/design/screen_design.md` では、ヘッダーのリンク一覧、カレンダーの月グリッド表示（7列）、各種ポップアップモーダル、タスク一覧のフィルタ群などがデスクトップ幅を前提とした記述のみとなっています。
- スマートフォン等の狭幅画面（ビューポート幅 < 768px）において以下の対応方針が未定義です：
  1. **ヘッダーナビゲーション**: 画面上部の横並びリンクが収まらない場合のハンバーガーメニューまたは下部ボトムナビゲーションバーへの切り替え方針。
  2. **カレンダー月グリッド表示**: モバイル画面幅での7列月グリッド表示時の日付セル内テキストの折り返し・省略表示方針（週表示の推奨や日付セルタップによるポップアップ展開の操作性）。
  3. **モーダルポップアップ**: タスク作成・編集ポップアップや日付詳細ポップアップを、モバイル画面では画面下部からのボトムシート（ドロワー）または全画面モーダルとして表示する方針。

## 3. 推奨される修正案
`docs/design/screen_design.md` に「共通UI・レスポンシブ対応補足」セクションを新設し、スマートフォン表示時の方針を明記してください：

- **レスポンシブ設計方針**:
  - **ヘッダー**: モバイル幅時はハンバーガーメニュー（ドロワーメニュー）または下部ナビゲーションに切り替える。
  - **タスク一覧・検索フィルタ**: 検索欄・絞り込みプルダウンをアコーディオン開閉または縦並びレイアウトとし、操作性を確保する。
  - **カレンダー表示**: 月グリッド表示時は日付セル内のタスク表示をバッジ/ドット等の簡略表示とし、日付タップで「日付詳細ポップアップ（ボトムシート）」を展開して詳細操作を行えるようにする。またモバイル時は週表示を優先表示可能とする。
  - **ポップアップ・ダイアログ**: モバイル画面では全画面モーダルまたはボトムシート形式で展開し、フォーム操作やスクロールを容易にする。
