# パスワード禁止文字列判定における「4文字以上」の適用範囲曖昧さおよび短小ユーザー名による誤検知リスク

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-18 20:15:00
- **Target Files**:
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
パスワード要件において、「ユーザ名文字列、およびメールアドレスのローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する」と規定されていますが、「ただし4文字以上の場合に限る」という条件がメールアドレスのローカル部にのみかかるのか、ユーザー名にもかかるのかが曖昧です。また、2〜3文字のユーザー名に対して無条件で部分一致禁止を適用すると、パスワード設定の過度な誤検知（設定不能）が発生するリスクがあります。

## 2. 詳細な指摘内容
`docs/req-def/requirements.md` の L258-265 に以下の記述があります：

```markdown
- ユーザ名要件
	- 2文字以上20文字以内
	- 英小大文字、数字
	- 同名のユーザー名登録は可（ログイン識別子にはメールアドレスを使用するため）
- パスワード要件
	- 8文字以上128文字以下
	- 英大文字、英小文字、数字、記号( `!"#$%&'()=-~^|\{}[]+;:*_/?.>,<` )の4種類のうち3種類以上を含むこと
	- ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する（いずれも大文字・小文字を区別せず［Case-Insensitive］に部分一致判定を行う）
	- ソルトを用いたハッシュ化を行い安全に保存する
```

### 問題点：
1. **短小文字列による部分一致の誤検知**:
   - ユーザー名要件では「2文字以上」が許容されています（例: ユーザー名 `ab`, `my`, `go` など）。
   - もし「ただし4文字以上の場合に限る」がローカル部のみに適用され、2〜3文字のユーザー名に対して部分一致禁止チェックを行うと、例えばユーザー名が `ab` のユーザーは、一般的な英単語を含むパスワード（例: `About#2026!`, `Database$99`, `Enable*123` など `ab` を含むすべての文字列）が設定できなくなり、著しいユーザビリティ低下を引き起こします。
2. **修飾関係の曖昧さ**:
   - 文言上、「ユーザ名文字列（文字数制限なし）、およびメールアドレスのローカル部（4文字以上）」と読めるため、実装者がユーザー名の長さに関わらず部分一致チェックを実装してしまう危険性があります。

## 3. 推奨される修正案
`docs/req-def/requirements.md` の L265 を修正し、「4文字以上の場合に限り部分一致チェックを行う（3文字以下の文字列は完全一致またはチェック対象外とする）」旨を明記してください：

```markdown
	- ユーザ名文字列およびメールアドレスの `@` より前のローカル部（いずれも4文字以上の場合に限る）を含むパスワードの設定を禁止する（いずれも大文字・小文字を区別せず［Case-Insensitive］に部分一致判定を行う。なお、ユーザー名またはローカル部が3文字以下の場合は部分一致チェックをスキップし、パスワード文字列と完全に一致する場合のみ設定を禁止する）
```
