# POST/PATCH tasks における due_datetime のタイムゾーン補正・正規化仕様の未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-17 17:15:00
- **Target Files**:
  - [04_tasks.md](docs/design/api_design/04_tasks.md)
  - [01_overview.md](docs/design/api_design/01_overview.md)

## 1. 問題の概要
`POST tasks` (3.3.2 節) および `PATCH tasks/{task_id}` (3.3.4 節) の `due_datetime` フィールドにおいて、タイムゾーンオフセット（例: `+09:00`）を含まない ISO 8601 文字列や UTC/他タイムゾーンの文字列が入力された場合のバックエンドでの変換・正規化仕様が明記されていません。

## 2. 詳細な指摘内容
1. **タイムゾーンオフセットなし ISO 8601 文字列の扱い**:
   - `due_datetime` の型定義（L114, L233）では「ISO 8601 日時文字列（例: `2026-08-20T23:59:00+09:00`）、または日付のみ `YYYY-MM-DD`（時刻省略時は `23:59:00+09:00` を設定）」と規定されています。
   - クライアントから `2026-08-20T23:59:00` のように末尾のタイムゾーン表記（`+09:00` や `Z`）が省略された日時文字列が指定された場合、サーバーがこれを JST (`+09:00`) として扱うのか、バリデーションエラー (`400 Bad Request`) とするのかが不透明です。
2. **UTC または他タイムゾーン指定時の表示・保持仕様**:
   - `2026-08-20T14:59:00Z`（UTC）などの他タイムゾーン文字列が送信された場合、バックエンドで JST (`+09:00`) に即時変換・正規化して DB 保存およびレスポンス返却 (`2026-08-20T23:59:00+09:00`) を行うべきである旨が共通仕様 (`01_overview.md` Section 1) と関連付けて明確化されていません。

## 3. 推奨される修正案
`POST tasks` および `PATCH tasks/{task_id}` の `due_datetime` フィールド定義注記に以下を明確に追記してください：
1. タイムゾーンオフセットを含まない ISO 8601 日時文字列が渡された場合は、デフォルトで JST (`+09:00`) の日時として解釈する。
2. UTC (`Z`) や他タイムゾーンの ISO 8601 日時文字列が渡された場合は、JST (`+09:00`) に変換・正規化した上で登録・返却を行う。
