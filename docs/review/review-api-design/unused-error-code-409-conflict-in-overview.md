# 代表的なエラーコード一覧における未定義エラーコード 409 CONFLICT の記載

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 16:35:00
- **Target Files**:
  - [01_overview.md](docs/design/api_design/01_overview.md)

## 1. 問題の概要
`01_overview.md` の 1.3 節「代表的なエラーコード一覧」テーブル（L70）に `409 CONFLICT`（`CONFLICT`）が掲載され、「※アカウント列挙防止のためメールアドレス重複等には使用しません」と注記されているが、詳細設計書（`02_auth.md`, `03_users.md`, `04_tasks.md`）のいずれのエンドポイントにおいても `409 CONFLICT` を返却する条件が定義されておらず、本システムで一切使用されない未使用のエラーコードが一覧に含まれている。

## 2. 詳細な指摘内容
1. **エンドポイント詳細定義との不一致**:
   - `01_overview.md` L70 にて `409` | `CONFLICT` | `リソースの競合（※アカウント列挙防止のためメールアドレス重複等には使用しません）` と記載されている。
   - しかし、`02_auth.md`（新規登録・ログイン・パスワードリセット・メールアドレス変更）、`03_users.md`（ユーザー更新・削除・パスワード変更）、`04_tasks.md`（タスク一覧・作成・詳細・更新・削除）のすべてにおいて、`409 CONFLICT` を返却するエラー仕様は一切存在しない。

2. **フロントエンド実装への混乱**:
   全APIエンドポイントの設計において返却されないHTTPステータスおよびエラーコードが「代表的なエラーコード一覧」に存在すると、共通エラーハンドラー等の実装時に不要な分岐を作成することになり、仕様上の混同を招く。

## 3. 推奨される修正案
`01_overview.md` 1.3 節の「代表的なエラーコード一覧」テーブルから `409 CONFLICT` の行を削除するか、またはもし将来的な楽観的ロック等で `409` を利用する想定がある場合は、該当するエンドポイントおよび返却条件を明記してください。
