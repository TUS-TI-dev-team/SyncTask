# アカウント削除 API のリクエスト評価順序における存在しないステップへの参照エラー

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 17:15:00
- **Target Files**:
  - [03_users.md](docs/design/api_design/03_users.md)

## 1. 問題の概要
`03_users.md` の 3.2.3 節 (`DELETE users/{user_id}`) における「リクエスト評価順序」のステップ 4 にて、パスワード再認証成功時の動作として「照合成功時は即座に `REAUTH_FAILED_COUNT` を 0 にリセットしてステップ5に進む。」と記載されていますが、該当エンドポイントにはステップ 5 が存在しません（評価順序はステップ 1〜4 のみ）。

## 2. 詳細な指摘内容
- **`03_users.md` L112-L113 (3.2.3 リクエスト評価順序ステップ 4)**:
  ```markdown
  4. **パスワード再認証検証 (`401 REAUTH_FAILED` / `SESSION_DESTROYED`)**:
     現在のパスワードのハッシュ照合を実施。不一致時は一律 `1.0s ± 0.1s` の遅延を適用し、失敗回数をカウントアップ。5回達成分は操作中の該当ログインセッションのみを強制破棄および Cookie 削除ヘッダーを付与。**照合成功時は即座に `REAUTH_FAILED_COUNT` を 0 にリセットしてステップ5に進む。**
  ```

### 問題点
1. **存在しない評価ステップへの不整合な参照**:
   3.2.3 節 (`DELETE users/{user_id}`) のリクエスト評価順序は「1. 認証・CSRF検証」「2. リクエスト構文・入力バリデーション」「3. 認可チェック・IDOR/BOLA検証」「4. パスワード再認証検証」の全 4 ステップで構成されています。
   隣接する 3.2.4 節 (`PATCH users/{user_id}/password`) には「5. ビジネスルール検証 (`422 SAME_AS_CURRENT_PASSWORD`)」が存在しますが、3.2.3 節にはビジネスルール検証ステップが存在しないため、「ステップ5に進む」という記述は転記ミスによるドキュメントの整合性エラーとなっています。
2. **仕様理解および実装時の混乱防止**:
   仕様書を参照する開発者が後続ステップ（ステップ 5）の記載漏れを疑ったり、処理フローの理解に不要な迷いが生じる原因となります。

## 3. 推奨される修正案
`03_users.md` の 3.2.3 節 (`DELETE users/{user_id}`) の「リクエスト評価順序」ステップ 4 の文末表現を「ステップ5に進む」から「アカウント削除処理（論理削除・セッション削除等）を実行する」へ修正してください。

**修正案の例 (`03_users.md` 3.2.3)**:
```markdown
4. **パスワード再認証検証 (`401 REAUTH_FAILED` / `SESSION_DESTROYED`)**:
   現在のパスワードのハッシュ照合を実施。不一致時は一律 `1.0s ± 0.1s` の遅延を適用し、失敗回数をカウントアップ。5回達成分は操作中の該当ログインセッションのみを強制破棄および Cookie 削除ヘッダーを付与。**照合成功時は即座に `REAUTH_FAILED_COUNT` を 0 にリセットしてアカウント削除処理を実行する。**
```
