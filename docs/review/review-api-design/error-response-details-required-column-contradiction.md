# 共通エラーレスポンス定義における details フィールドの必須属性定義の矛盾

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 17:06:00
- **Target Files**:
  - [01_overview.md](docs/design/api_design/01_overview.md)

## 1. 問題の概要
`01_overview.md` 1.3 節の「エラーレスポンス スキーマ定義」テーブルにおいて、`error.details` フィールドの「必須」列が `×`（任意）と表記されている一方で、「説明」列では「対象フィールドが存在しないエラー応答の場合は空配列 `[]` を返却（`null` やキー省略は不可）」と記述されており、必須性とキー省略可否の定義に矛盾が生じている。

## 2. 詳細な指摘内容
1. **スキーマ定義テーブル内の矛盾**:
   - 1.3 節のスキーマ定義テーブル:
     ```markdown
     | `error.details` | array | × | フィールド単位のバリデーション詳細情報リスト。対象フィールドが存在しないエラー応答の場合は空配列 `[]` を返却（`null` やキー省略は不可） |
     ```
   - 「説明」欄で `null` やキー省略を禁止し、対象フィールドが存在しない場合も常に空配列 `[]` をキーとして出力させるルールを定めているため、JSON レスポンス構造上 `error.details` は常に必須キー（必須: `○`）として存在する。
   - にもかかわらず「必須」列が `×`（任意）になっているため、スキーマ定義内で記述の不整合が発生している。

2. **実装・検証時の混乱リスク**:
   - スキーマバリデーション（OpenAPI / JSON Schema 等）や自動テストにおいて、「必須: `×`」と「キー省略不可（必須: `○`）」のどちらを正として判定・設計すべきか実装者やレビューアが混乱する可能性がある。

## 3. 推奨される修正案
`01_overview.md` 1.3 節の「エラーレスポンス スキーマ定義」テーブルにおける `error.details` の「必須」列を `○` に更新し、定義を一貫させてください。

```markdown
| フィールド | 型 | 必須 | 説明 |
| :--- | :--- | :---: | :--- |
| `error.details` | array | ○ | フィールド単位のバリデーション詳細情報リスト。対象フィールドが存在しないエラー応答の場合は空配列 `[]` を返却（`null` やキー省略は不可） |
```
