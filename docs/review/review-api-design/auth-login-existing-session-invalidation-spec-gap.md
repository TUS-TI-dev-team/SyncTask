# ログインAPI (`POST auth/login`) における既存セッションCookie保持時の旧セッション破棄処理の定義漏れ

- **Status**: Resolved

## 修正完了報告

- **Resolved At**: 2026-08-17 17:03:00
- **Status**: Resolved

### 実施した修正内容
`02_auth.md` 3.1.4 節 (`POST auth/login`) のレスポンス注記に、リクエスト時に既存のログインセッションCookie（`sync_task_sid`）が送信された場合は旧セッション（`LOGIN_SESSION`）をDBから物理削除して新しいログインセッションを発行する旨を追記しました。

## 1. 問題の概要
`02_auth.md` の 3.1.2 `POST auth/register/verify-otp`（L69）では、「リクエスト時に既存のログインセッションCookie（`sync_task_sid`）が送信された場合は、複数アカウントへの同時重複ログインを防止するため、その旧セッション（`LOGIN_SESSION`）もDBから物理削除した上で新しいログインセッションを発行します」と明確に規定されています。しかし、3.1.4 `POST auth/login` には既存セッションCookie送信時の旧セッション無効化・DB物理削除に関する記述が存在しません。

## 2. 詳細な指摘内容
1. **ログインと会員登録におけるセッション破棄仕様の不整合**:
   - ユーザーがブラウザで既に別のアカウントでログインしている状態で、新たに `POST auth/login` を実行してログインを行った場合、リクエストには既存の `sync_task_sid` Cookie が含まれます。
   - 3.1.2 (`register/verify-otp`) では旧セッションを DB から物理削除して重複ログインを防ぐ仕様が明示されていますが、3.1.4 (`auth/login`) ではこの記述が抜け落ちており、旧セッションが DB 上に残存したまま新しいセッションが発行されるのか、あるいは旧セッションが無効化されるのかが不透明です。
2. **セキュリティおよびセッション管理の一貫性**:
   - 同一ブラウザ端末からの別アカウントログイン時において、旧セッションを DB から物理削除して確実に無効化するルールは、新規登録完了時と通常ログイン時で統一されるべきです。

## 3. 推奨される修正案
`02_auth.md` の 3.1.4 `POST auth/login` の Response (200 OK) または説明部分に、3.1.2 と同様の以下の注記を追加してください：

```markdown
※なおリクエスト時に既存のログインセッションCookie（sync_task_sid）が送信された場合は、複数アカウントへの同時重複ログインを防止するため、その旧セッション（LOGIN_SESSION）もDBから物理削除した上で新しいログインセッションを発行します。
```
