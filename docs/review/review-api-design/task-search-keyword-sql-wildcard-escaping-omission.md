## 1. 問題の概要
`GET tasks`（3.3.1）のクエリパラメータ `keyword` によるタスク名およびコメントの部分一致検索仕様において、入力文字列に含まれる SQL ワイルドカード特殊文字（`%` や `_`）のリテラルエスケープ処理に関する仕様が明記されていません。

## 2. 詳細な指摘内容
`04_tasks.md` L16 では `keyword` パラメータについて「タスク名およびコメントの部分一致検索（Case-Insensitive、前後の空白文字をトリム処理。未入力またはトリム後空文字の場合はキーワードによる絞り込みを行わない）」と記載されています。

しかし、クライアントから `%`（0文字以上の任意の文字列）や `_`（任意の1文字）を含むキーワード（例: `進捗 100%`, `test_task`）が送信された際、バックエンドの SQL クエリ（`ILIKE '%keyword%'` 等）でエスケープ処理を施さずにそのまま埋め込んだ場合、ワイルドカードとして解釈されてしまい以下の問題が発生します：
1. **検索精度の低下**: `100%` で検索した際にすべてのタスクがヒットする。
2. **意図しない全件検索によるパフォーマンス低下および情報漏洩リスク**: パターンマッチ制御の意図しない挙動。

## 3. 推奨される修正案
`04_tasks.md` (L16) の `keyword` パラメータ説明欄に、ワイルドカード特殊文字（`%`, `_`, `\` 等）をリテラルエスケープ（例: `\%`, `\_`, `\\`）した上で部分一致検索を行う旨を明確に追記してください。
