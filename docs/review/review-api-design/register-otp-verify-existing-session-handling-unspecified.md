# 新規登録OTP検証成功時の既存ログインセッション上書き処理の未記載

- **Status**: Open
- **Severity**: Minor
- **Created At**: 2026-08-17 15:01:00
- **Target Files**:
  - [api_design.md](docs/design/api_design.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書では、新規登録のOTP認証成功時に「ブラウザ上に既存の古いログインセッションが存在する場合は無効化・上書きし、複数アカウントへの同時重複ログイン状態を防止する」と明記されているが、API設計書の `POST auth/register/verify-otp`（3.1.2）にはこの処理に関する記述がない。

## 2. 詳細な指摘内容
- **要件定義書 L32**: 「OTP認証成功時、アカウントの作成を確定すると同時に自動的に新しいログインセッションを発行してログイン状態とし、タスク一覧画面へ遷移する（なお、ブラウザ上に既存の古いログインセッションが存在する場合は無効化・上書きし、複数アカウントへの同時重複ログイン状態を防止する）」
- **API設計書 L136-171**: `POST auth/register/verify-otp` では `Set-Cookie` で新しいセッショントークンを発行するが、既存の `sync_task_sid` Cookie（別アカウントでログイン中だった場合）に紐づくセッションの無効化処理について言及がない。

この仕様欠落により、あるアカウントでログインした状態で別の新規アカウントを登録した場合、旧アカウントのセッションがDBに残存し続ける可能性がある（Cookie自体は新しいセッションで上書きされるため表面上は問題ないが、DB側でセッションが残存するのはセキュリティ上のリスク）。

## 3. 推奨される修正案
`POST auth/register/verify-otp`（3.1.2）のレスポンス仕様に以下を追記する:

```
※リクエスト時に有効なログインセッションCookie（`sync_task_sid`）が送信された場合、
そのセッションをDBから物理削除した上で新しいセッションを発行します
（複数アカウントへの同時重複ログイン状態を防止するため）。
```
