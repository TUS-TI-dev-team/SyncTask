# ユーザー名更新API (PUT users/{user_id}) におけるトリム処理後文字数・使用可能文字バリデーション境界の明記

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 16:45:00
- **Target Files**:
  - [03_users.md](docs/design/api_design/03_users.md)

## 1. 問題の概要
`PUT users/{user_id}` (3.2.2) の `username` のリクエストパラメータ制約において、「2〜20文字、英数字（大文字小文字可）。前後の空白は自動トリム」と記載されています。
しかし、自動トリムを行った後の文字列に対して文字数チェック（2〜20文字）や使用可能文字チェック（英数字のみ）が適用されること、およびトリム後の文字列がこれらの条件を満たさない場合（例: 空白のみ送信時、トリム後1文字以下、記号混入時）に `400 Bad Request` (code: `"BAD_REQUEST"`) が返却される境界仕様をより明確にする必要があります。

## 2. 詳細な指摘内容
1. `3.2.2` のバリデーションテーブルには「前後の空白は自動トリム。トリム後のユーザー名が現在のユーザー名と同一の場合は 422 エラー」と記述されています。
2. もしクライアントが `" a "` のように空白付き3文字（トリム後 `"a"` で1文字）を送信した場合、トリム処理が文字数バリデーション（2〜20文字）の前に実行されるか後に実行されるかで、2文字以上として通過してしまうバグや不整合が生じる可能性があります。
3. トリム処理を最初に行い、トリム後の文字列に対して「文字数 2〜20文字」および「英数字のみ」の判定を行う制御順序をテーブルおよびエラー定義に明記することが推奨されます。

## 3. 推奨される修正案
`03_users.md` の 3.2.2 (`PUT users/{user_id}`) のリクエストパラメータテーブルおよび `##### Errors` を以下のように表現を調整・明記してください。

```markdown
| フィールド | 型 | 必須 | 制約・バリデーション |
| :--- | :--- | :---: | :--- |
| `username` | string | ○ | 前後の空白を自動トリム後、2〜20文字かつ英数字（大文字小文字可）であること。要件違反時は 400 エラー。トリム後のユーザー名が現在のユーザー名と同一の場合は 422 エラー |
```

`##### Errors` 400 Bad Request:
- `400 Bad Request`: トリム後のユーザー名要件違反（文字数2〜20文字範囲外・使用可能文字不正・空白のみ送信等、code: `"BAD_REQUEST"`）
