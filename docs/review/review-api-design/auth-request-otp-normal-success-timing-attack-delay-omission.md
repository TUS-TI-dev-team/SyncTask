# OTP発行・再送APIにおける正常成功時のレスポンス遅延（1.0s ± 0.1s）適用仕様の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-17 16:53:00
- **Target Files**:
  - [02_auth.md](docs/design/api_design/02_auth.md)
  - [01_overview.md](docs/design/api_design/01_overview.md)

## 1. 問題の概要
`01_overview.md` 1.2 節（L32, L39）にて「正常成功時・ダミー発行時を一貫して区別せずレスポンス遅延（1.0s ± 0.1s）を適用した上で `200 OK` を返却します」と定義されているのに対し、`02_auth.md` の OTP 発行・再送 API 群（3.1.1, 3.1.3, 3.1.6, 3.1.8, 3.1.10, 3.1.12）のレスポンス注記では「ダミーの `otp_session_id` を返却する場合」にのみ遅延（1.0s ± 0.1s）を適用するような限定的表現となっており、正常成功時にも同様に遅延を適用する仕様が欠落しています。

## 2. 詳細な指摘内容
1. **`01_overview.md` と `02_auth.md` の記述ギャップ**:
   - `01_overview.md` 1.2 節（L32）:
     `新規登録（auth/register/request-otp）、パスワードリセット（auth/password-reset/request-otp）、メールアドレス変更（auth/change-email/request-otp）において...正常成功時・ダミー発行時を一貫して区別せずレスポンス遅延（1.0s ± 0.1s）を適用した上で 200 OK を返却します。`
   - しかし、`02_auth.md` の各セクションでは以下のように「ダミー時」のみに限定して遅延が言及されています:
     - 3.1.1 L31: `※既に登録済みのメールアドレス...が指定された場合も...ダミーの otp_session_id とマスク文字列を返し、200 OK（遅延 1.0s ± 0.1s）を返却します。`
     - 3.1.6 L190: `※未登録のメールアドレス...が指定された場合も...ダミーの otp_session_id とマスク文字列を返し、200 OK（遅延 1.0s ± 0.1s）を返却します。`
     - 3.1.10 L324: `※登録済みの他ユーザーのメールアドレス...が指定された場合も...ダミーの otp_session_id とマスク文字列を返し、200 OK（遅延 1.0s ± 0.1s）を返却します。`
     - 3.1.3 L102, 3.1.8 L254, 3.1.12 L398: `※ダミーセッションの場合も実際のメール送信は行わずに同様の 200 OK（遅延 1.0s ± 0.1s）を返却します。`

2. **Timing Attack（サイドチャネル攻撃）によるアカウント列挙リスク**:
   - 実装者が `02_auth.md` の上記注記のみを参照した場合、正常な OTP 発行（実在メール・新規メールへの送信）を即時（数十ms）でレスポンスし、ダミー発行時のみ人工遅延（1.0s ± 0.1s）を挟む実装となる危険性があります。
   - この場合、レスポンス時間の測定（Timing Attack）によって「高速応答＝新規/実在アドレス」「1秒後応答＝登録済み/未登録/ダミーアドレス」であることが外部から容易に識別可能となり、アカウント列挙防止対策が無効化します。

## 3. 推奨される修正案
`02_auth.md` の 3.1.1, 3.1.3, 3.1.6, 3.1.8, 3.1.10, 3.1.12 の各注記を更新し、正常成功時（実メール送信時）およびダミー処理時のいずれにおいても一律でレスポンス遅延（1.0s ± 0.1s）を適用した上で `200 OK` を返却する旨を明確に統一追記してください。

- **3.1.1, 3.1.6, 3.1.10 注記の修正案**:
  ```markdown
  ※アカウント列挙防止および Timing Attack 対策として、正常成功時（実メール送信時）およびダミー発行時（既に登録済みのメールアドレス、他ユーザーの有効なOTPセッション期間中等の指定時）を一貫して区別せず、一律でレスポンス遅延（1.0s ± 0.1s）を適用した上で `200 OK` を返却します。
  ```

- **3.1.3, 3.1.8, 3.1.12 注記の修正案**:
  ```markdown
  ※Timing Attack 対策として、正常再送時（実メール送信時）およびダミーセッション再送時（実際のメール送信を行わない場合）を一貫して区別せず、一律でレスポンス遅延（1.0s ± 0.1s）を適用した上で `200 OK` を返却します。
  ```
