## 1. 問題の概要
`02_auth.md` の 3.1.5 `POST auth/logout` において、`認証: 必須 (Cookie)` および CSRF トークン検証失敗時の `403 Forbidden` (`FORBIDDEN`) が定義されている一方で、補足において「未ログインまたはセッションが既に無効化・期限切れの状態で呼び出された場合もエラーとせず、200 OK を返却してCookieを確実に消去する（冪等性の確保）」と定められています。しかし、CSRF検証とログイン認証/セッション検証の適用評価順序が定義されていません。

## 2. 詳細な指摘内容
1. **CSRF検証と未ログイン判定の優先順序の未定義**:
   - `01_overview.md` (1.2節) では、「認証を必要とするすべての状態変更リクエストにおいて CSRF トークンの検証を必須とする（未認証のログイン・会員登録等を除く）」と定義されています。
   - もし `auth/logout` において CSRF トークン検証が未ログイン判定より前に評価された場合、セッションが期限切れまたは未ログイン状態のクライアントが CSRF トークンヘッダーを付与せずにログアウトを呼び出した際、`403 Forbidden` (`FORBIDDEN`) エラーが返却されてしまいます。
   - これにより、未ログイン/セッション期限切れ状態のユーザーがログアウト API 呼び出しによってローカルCookieを正常に消去できず、要件定義書および `02_auth.md` で意図されている「未ログイン時も 200 OK でCookieを消去するログアウト操作の冪等性」が破損します。

2. **リクエスト評価順序の欠落**:
   - `3.1.5 POST auth/logout` には `##### リクエスト評価順序` セクションが存在せず、CSRF トークンチェックと未ログイン/無効セッション判定のどちらを先に評価すべきかが明記されていません。

## 3. 推奨される修正案
`3.1.5 POST auth/logout` に `##### リクエスト評価順序` セクションを追加し、以下のいずれかの方針を明記してください：
1. **未ログイン・セッション無効時の挙動**: ログインセッションの有効性を確認し、未ログインまたはセッションが無効・期限切れの場合は CSRF 検証の有無にかかわらず `200 OK` を返却し、Cookie 削除ヘッダー（`Set-Cookie: sync_task_sid=; Max-Age=0`, `Set-Cookie: XSRF-TOKEN=; Max-Age=0`）を返す。
2. **有効ログインセッション存在時**: ログインセッションが有効な場合のみ CSRF トークン（`X-CSRF-Token`）を検証し、欠落・不一致時は `403 Forbidden` (`FORBIDDEN`) を返却する。
