# カレンダー表示時の完了タスクフィルタおよびソート仕様のAPI設計不足

- **Status**: Open
- **Severity**: Medium
- **Created At**: 2026-08-17 15:01:00
- **Target Files**:
  - [api_design.md](docs/design/api_design.md)
  - [requirements.md](docs/req-def/requirements.md)
  - [screen_design.md](docs/design/screen_design.md)

## 1. 問題の概要
`GET tasks`（3.3.1）のクエリパラメータ仕様において、カレンダー表示で使用する `start_date` / `end_date` パラメータは定義されているが、要件定義書および画面設計書で明記されている以下のカレンダー特有のフィルタ・ソート仕様がAPI側に反映されていない。

1. **カレンダー表示の完了タスクフィルタ**: 要件定義書 L142 にて「カレンダー画面上に『完了タスクを含める / 除外する』の表示切り替えフィルタを提供する」と記載。API設計書の `include_completed` パラメータは存在するが、`start_date` / `end_date` と `include_completed` の組み合わせ時のデフォルト値の挙動が不明確（カレンダー表示ではデフォルトで全ステータス対象なのか、リスト表示と同様に `false` なのか）。
2. **カレンダー表示時のソート**: 要件定義書 L140 にて「同一日付セル内に複数のタスクが存在する場合の並び順は、1. ピン留め優先、2. 締切時刻（hh:mm:ss）が早い順（昇順）、3. 作成日時の新しい順（降順）」と記載。API設計書の `sort_by` パラメータには `default` のみが定義されており、カレンダー用のソートモードが存在しない。
3. **カレンダー期間取得時のページネーション不要性**: カレンダー表示で `start_date` / `end_date` を指定した期間取得の場合、ページネーションが適用されるか否かが不明。要件上はグリッド内全タスクを一括取得する必要がある。

## 2. 詳細な指摘内容
- **API設計書 L598-607**: `start_date` / `end_date` は定義されているが、これらが指定された場合の挙動（ページネーション無効化、ソート順変更、`include_completed` のデフォルト変更等）が明確にされていない。
- **要件定義書 L139-142**: カレンダー表示では「締切日時が設定されている**全ステータス**のタスクを取得する」とされているが、同時にフィルタも提供される。API側では `start_date` / `end_date` 指定時の `include_completed` のデフォルトが `true`（カレンダーでは全ステータスを含むのがデフォルト）であるべきかが未定義。
- **要件定義書 L147**: 「バックエンドAPIはグリッド全体の開始日から終了日までのタスクを取得する」とあり、カレンダー期間取得ではページネーションなしの全件取得が想定される。

## 3. 推奨される修正案
`GET tasks`（3.3.1）に以下の仕様を追記する:

1. `start_date` / `end_date` 指定時（カレンダー期間取得モード）の挙動を明記:
   - ページネーション: 無効（期間内の全タスクを一括返却。ただしパフォーマンス保護のため上限件数を設定する場合はその値を明記）
   - `include_completed` デフォルト: `true`（カレンダーでは全ステータスが表示対象のため）
   - ソート: カレンダー用ソート（1. ピン留め優先、2. 締切時刻 昇順、3. 作成日時 降順）

2. または `sort_by` に `calendar` モードを追加して上記ソート順を適用する仕様とする。
