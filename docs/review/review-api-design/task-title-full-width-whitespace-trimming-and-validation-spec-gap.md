# POST tasks および PATCH tasks における title の全角空白トリム処理および空白のみ入力拒否仕様の明記漏れ

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 16:53:00
- **Target Files**:
  - [04_tasks.md](docs/design/api_design/04_tasks.md)

## 1. 問題の概要
`POST tasks` および `PATCH tasks` API のリクエストボディ定義において、タスク名 `title` のバリデーションルールが「1〜100文字（トリム後）」と簡易記述されているため、全角スペース（`\u3000`）を含むトリム範囲および空白文字のみの入力拒否挙動についての明確な定義が不足しています。

## 2. 詳細な指摘内容
要件定義書（`docs/req-def/requirements.md` L78, L94）では、タスク名（`title`）について以下のように定義されています：
> 前後の空白文字［半角・全角スペース、タブ、改行］を除去［トリム］した上で1〜100文字必須。空白文字のみの入力はバリデーションエラーとして拒否する。なお、タスク名は1行テキストとし、文字列内部の改行コード［CR/LF］やタブ等の制御文字の入力はバリデーションエラーとして拒否する

しかし、`04_tasks.md` L94 (`POST tasks`) および L194 (`PATCH tasks`) のフィールド定義表では、以下のようにのみ記載されています：
> `title` | string | ○ | 1〜100文字（トリム後）。改行・タブ等の制御文字禁止

この記述のままだと、バックエンド実装で標準的な `trim()`（半角スペースのみ除去）のみが適用され、全角スペース（`\u3000`）が前後や空白のみの入力でトリム除去されずにバリデーションを通過してしまう恐れがあります。

## 3. 推奨される修正案
`04_tasks.md` L94 (`POST tasks`) および L194 (`PATCH tasks`) の `title` のバリデーション説明文を以下のように修正してください。

```markdown
| `title` | string | ○ | 前後の空白文字（半角・全角スペース、タブ、改行）を除去（トリム）した上で1〜100文字必須。空白文字のみの入力および文字列内部への改行・タブ等の制御文字入力は 400 Bad Request（code: `"BAD_REQUEST"`）として拒否 |
```

## 修正完了報告

### 実施した修正内容
`04_tasks.md` の 3.3.2 (`POST tasks`) および 3.3.4 (`PATCH tasks`) の `title` フィールド制約・バリデーション説明文を修正し、前後の空白文字（半角・全角スペース、タブ、改行）を除去（トリム）した上で1〜100文字必須であること、空白文字のみの入力拒否、および文字列内部への制御文字入力拒否（`400 Bad Request`）を明確に記載しました。
