# メールアドレス変更完了時の旧メールアドレスへの変更通知メール送信仕様の欠落

- **Status**: Open
- **Severity**: Medium
- **Created At**: 2026-08-17 15:01:00
- **Target Files**:
  - [api_design.md](docs/design/api_design.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
要件定義書（requirements.md）の「メールアドレスの変更」セクションには「変更完了時、旧メールアドレス宛に変更完了通知メールを送信する」と明記されているが、API設計書（api_design.md）の `POST auth/change-email/verify-otp`（3.1.11）の仕様記述にはこの通知メール送信処理に関する記載が一切存在しない。

## 2. 詳細な指摘内容
- **要件定義書 L47**: 「変更完了時、旧メールアドレス宛に変更完了通知メールを送信する」と記載されている。
- **API設計書 L400-427**: `POST auth/change-email/verify-otp` のレスポンス仕様では、OTP検証成功時にメールアドレス変更を確定し、全セッションを物理削除する処理は記載されているが、旧メールアドレスへの変更完了通知メール送信処理については触れられていない。

この通知メールは、アカウントの不正変更（なりすまし・乗っ取り）に対するセキュリティ上の重要な通知手段であり、ユーザーが身に覚えのないメールアドレス変更を検知するための唯一の手段となる。API設計書に仕様が欠落していると、実装時に通知が省略されるリスクがある。

## 3. 推奨される修正案
`POST auth/change-email/verify-otp`（3.1.11）のレスポンス仕様または処理説明に、以下の内容を追記する:

```
※メールアドレス変更の確定処理に成功した場合、変更前の旧メールアドレス宛に「メールアドレスが変更されました」旨の変更完了通知メールをバックエンドからシステム送信します。この通知はAPI応答とは非同期で行われ、レスポンスの成否には影響しません。
```
