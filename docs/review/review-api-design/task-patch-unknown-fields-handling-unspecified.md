# PATCH tasks/{task_id} における未定義・未知のリクエストボディフィールド指定時の挙動未定義

- **Status**: Open
- **Severity**: Minor
- **Created At**: 2026-08-17 17:55:00
- **Target Files**:
  - [04_tasks.md](docs/design/api_design/04_tasks.md)

## 1. 問題の概要
`PATCH tasks/{task_id}` (3.3.4 節) のリクエストボディにおいて、タスク定義に存在しない未定義・未知のフィールド（例: `{"unknown_param": "value"}`）が含まれていた場合のバリデーション処理（単に無視して200 OKを返すのか、400 Bad Requestで拒否するのか）が明記されていません。

## 2. 詳細な指摘内容
1. **読み取り専用フィールドと未知のフィールドの区別の曖昧さ**:
   - `04_tasks.md` L270 および L283 では、システムの読み取り専用フィールド（`id`, `user_id`, `created_at`, `updated_at`）が含まれている場合はエラーとせず単に無視すること、および空リクエストボディ `{}` が送信された場合は変更を行わずに `200 OK` と現在のタスク情報を返却することが明確に定義されています。
   - しかし、システム読み取り専用フィールドでも正規の更新対象フィールドでもない未知のキー（例: typo による `{"tittle": "新タイトル"}` や未定義プロパティ `{"foo": "bar"}`）がリクエストボディに含まれていた場合の扱いが記載されていません。
2. **サイレントな更新漏れのリスク**:
   - 未知のキーを無視して200 OKを返した場合、クライアントはタイポ等による更新失敗に気づかず成功したと誤認する可能性があります。一方、厳格なスキーマ検証により `400 Bad Request`（code: `"BAD_REQUEST"`）を返却する仕様であるならば、その挙動が明示されている必要があります。

## 3. 推奨される修正案
`04_tasks.md` 3.3.4 節 (`PATCH tasks/{task_id}`) のリクエスト評価順序または Request Body 注記に、以下のいずれかの処理方針を明記してください：

- **案A (厳格なバリデーション)**: 定義されていない未知のフィールドキーが含まれる場合は 400 Bad Request（code: `"BAD_REQUEST"`）を返却する。
- **案B (無視処理の明記)**: システム読み取り専用フィールドと同様に、定義されていない未知のフィールドキーが含まれる場合は更新対象外として単に無視し、定義済み更新対象フィールドのみを評価・適用する（有効な更新対象フィールドが存在しない場合は 200 OK と現在のタスク情報を返却する）。
