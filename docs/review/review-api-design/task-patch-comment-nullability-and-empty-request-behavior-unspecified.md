# PATCH tasks/{task_id} における comment の null 許容性および空リクエスト時の挙動未定義

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 16:30:00
- **Target Files**:
  - [04_tasks.md](docs/design/api_design/04_tasks.md)

## 1. 問題の概要
`PATCH tasks/{task_id}` において、設定済みのコメントを削除・クリアする際の入力仕様（`null` 送信 vs 空文字 `""` 送信）の定義が不足している点、およびフィールドを一切含まない空のリクエストボディ `{}` が送信された場合の挙動が未定義である点についての不備があります。

## 2. 詳細な指摘内容
1. **コメントクリア時の null 許容性の未記載**:
   - `PATCH tasks/{task_id}` のフィールド定義表 (L191) において、`due_datetime` には `string / null (null 指定で締切解除)` と明記されている一方、`comment` は `string`（0〜1000文字）と記載されています。
   - 既存のコメントをクリア（削除）したい場合に、空文字列 `""` を送信するのか、`null` を送信するのか（あるいは両方を許容するのか）が不透明です。`null` を送信した場合にバリデーションエラーとなるかどうかの解釈に差異が生じるリスクがあります。

2. **空のリクエストボディ (`{}`) 受信時の挙動未定義**:
   - リクエストボディに更新対象フィールドが一つも指定されていない場合（`{}`）のサーバー挙動（変更なしで `200 OK` と現在のタスク情報を返却するか、または `400 Bad Request` とするか）が定義されていません。

## 3. 推奨される修正案
1. `PATCH tasks/{task_id}` のフィールド定義表における `comment` の型を `string / null` に修正し、「空文字 `""` または `null` 指定でコメントをクリア」と明記してください。
2. 更新対象フィールドが未指定のリクエストボディ `{}` に対する処理方針（`400 Bad Request` を返却する、または変更なしで `200 OK` を返却する）を注記に追記してください。

## 修正完了報告

- **Resolved At**: 2026-08-17 16:42:00
- **Status**: Resolved

### 実施した修正内容
`PATCH tasks/{task_id}` の `comment` フィールドの型を `string / null` に修正し、空文字 `""` または `null` 送信でコメントを削除・クリアする挙動を明記しました。また、更新対象フィールド未指定の空リクエストボディ `{}` 送信時は変更なしで `200 OK` と現在のタスク情報を返却する仕様を追記しました。
