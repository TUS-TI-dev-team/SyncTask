# パスワードリセットにおけるユーザー名・ローカル部包含禁止バリデーションの実現方法未記載

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 15:01:00
- **Target Files**:
  - [api_design.md](docs/design/api_design.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
`POST auth/password-reset/reset`（3.1.9）のエラー仕様（L364）にて「パスワード要件違反（文字数・文字種・ユーザー名/ローカル部包含禁止）」と記載されているが、パスワードリセットフローはOTPセッションIDのみで処理が行われ、リクエストボディにはユーザー名やメールアドレスが含まれない。バリデーション時にユーザー名やメールアドレスのローカル部を参照するためには、OTPセッションIDからユーザーを逆引きして取得する必要があるが、その処理の流れが明記されていない。

## 2. 詳細な指摘内容
- **API設計書 L348-366**: `POST auth/password-reset/reset` のリクエストボディは `otp_session_id` と `new_password` のみ。
- **要件定義書 L253**: パスワード要件として「ユーザ名文字列、およびメールアドレスの `@` より前のローカル部（ただし4文字以上の場合に限る）を含むパスワードの設定を禁止する」と記載。
- パスワードリセットフローでは、OTPセッション → ユーザーID → ユーザー名 / メールアドレスの参照チェーンが必要だが、API設計書のバリデーション仕様にはこの参照方法が明示されていない。

実装者がリクエストボディのフィールドのみでバリデーションを実装しようとした場合、ユーザー名・ローカル部の包含チェックが漏れる可能性がある。

## 3. 推奨される修正案
`POST auth/password-reset/reset`（3.1.9）のバリデーション説明に以下を補足する:

```
※パスワード要件における「ユーザー名・メールアドレスローカル部の包含禁止」バリデーションは、
OTPセッションIDに紐づくユーザー情報（ユーザー名・メールアドレス）をDB参照した上で実施します。
```

---

## 4. 修正完了報告

- **対応内容**: `POST auth/password-reset/reset`（3.1.9）の仕様に、`otp_session_id` からDB上のユーザー情報を参照してユーザー名およびローカル部包含チェックを行う旨を補足・明記しました。
