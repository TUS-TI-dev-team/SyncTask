# メールアドレス重複・変更時のアカウント列挙防止とエラーコード整合性

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-17 13:17:00
- **Target Files**:
  - [api_design.md](docs/design/api_design.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
メールアドレスの重複登録、同一メールアドレスへの変更、パスワードリセット、ログイン等において、エラーコードやレスポンスの差異からアカウントの存在有無（登録済みメールアドレス）を第三者が推測・列挙できるアカウント列挙脆弱性（CWE-204）を完全に防止するための仕様が一部曖昧です。また、共通エラーコード一覧と各エンドポイントの振る舞いとの間に不整合が存在します。

## 2. 詳細な指摘内容
1. **メールアドレス重複および変更時のアカウント列挙防止**:
   - `docs/design/api_design.md` 1.3 の共通エラーコード一覧（L56-57）において、`409 CONFLICT`（リソースの競合）および `422 UNPROCESSABLE_ENTITY`（同一ユーザー名への変更等）が定義されています。
   - 新規登録（`auth/register/request-otp`）やメールアドレス変更（`auth/change-email/request-otp`）において、重複や同一メールアドレスに対して `409 Conflict` や `422 Unprocessable Entity` などの個別エラーコードを返却してしまうと、攻撃者が任意のメールアドレスの登録状況を特定できてしまいます。
   - 新規登録、パスワードリセット、メールアドレス変更（重複・同一メール宛含む）のいずれのリクエスト時も、一律でダミーOTPセッションを発行して `200 OK`（応答遅延 1s±0.1s）を返却し、成功時と一切区別できないように統一する必要があります。

2. **OTP検証（`verify-otp`）および再送信（`resend-otp`）におけるダミーセッションの挙動明記**:
   - `POST auth/register/verify-otp`（L154-158）、`POST auth/password-reset/verify-otp`（L276）、`POST auth/change-email/verify-otp`（L368）において、ダミーOTPセッションに対して検証リクエストが送られた場合の挙動が明確に定義されていません。
   - ダミーセッションに対しても実セッションと全く同一のエラーレスポンス構造（`400 Bad Request`: 不一致、5回失敗時 `422 Unprocessable Entity`、期限切れ `410 Gone`）および同一の応答遅延（1s±0.1s）を返す仕様を明記しないと、APIの応答差分からダミーセッションであることが判明する恐れがあります。

3. **ログインAPI（`POST auth/login`）における認証失敗エラーコードの統一**:
   - 存在しないメールアドレス、パスワード不一致、論理削除済みアカウントのいずれの場合も、一律で `401 Unauthorized`（code: `UNAUTHORIZED`）および応答遅延 1s±0.1s を返し、理由を詳細化しないことを明記する必要があります。

## 3. 推奨される修正案
1. `docs/design/api_design.md` の第1章「共通仕様」および各エンドポイント定義（`auth/register/*`, `auth/change-email/*`, `auth/password-reset/*`）において、メールアドレスの登録有無・重複・同一メール宛の別にかかわらず、一貫してダミーセッションを発行し `200 OK` を返す仕様を明確化してください。
2. 共通エラーコード一覧の `409 CONFLICT` はメールアドレス重複には使用しない方針を明記してください。
3. `verify-otp` および `resend-otp` において、ダミーOTPセッションであっても実セッションと同一のエラーコード（400, 410, 422, 429）および遅延（1s±0.1s）を返す旨を各エンドポイント仕様に明記してください。

## 修正完了報告

### 実施した修正内容
- `docs/design/api_design.md` の第1章「共通仕様」に「1.2 セキュリティ & CSRF・アカウント列挙対策」を定義し、新規登録・パスワードリセット・メールアドレス変更の全手続きにおいて、メールアドレスの登録有無・重複・同一アドレス指定にかかわらず一貫してダミーOTPセッションを発行し `200 OK`（応答遅延 1.0s ± 0.1s）を返却する仕様を明文化しました。
- 共通エラーコード一覧において `409 CONFLICT` をメールアドレス重複には使用しない旨を明記しました。
- 各エンドポイント（`auth/register/*`, `auth/password-reset/*`, `auth/change-email/*`）の `verify-otp` および `resend-otp` において、ダミーOTPセッション時も実セッションと全く同一のエラーコード（400, 410, 422, 429）および遅延（1.0s ± 0.1s）で応答する仕様を明記しました。
- `POST auth/login` において、メールアドレス未登録・パスワード不一致・論理削除済みアカウントのいずれも `401 Unauthorized`（code: `UNAUTHORIZED`）で一律返却する仕様を統一しました。
