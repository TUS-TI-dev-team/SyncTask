# `POST auth/change-email/verify-otp` における旧メールアドレス宛ての変更完了通知メール送信仕様の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-17 16:45:00
- **Target Files**:
  - [02_auth.md](docs/design/api_design/02_auth.md)

## 1. 問題の概要
`02_auth.md` の 3.1.11 `POST auth/change-email/verify-otp` の説明（L358）において、メールアドレス変更確定時のDB更新や既存セッション削除についての記載はあるが、要件定義書（`requirements.md` L47）で定められている「旧メールアドレス宛てへの変更完了通知メールの送信」に関する仕様記述が欠落している。

## 2. 詳細な指摘内容
- **要件定義書における規定**: `docs/req-def/requirements.md` L47 にて「変更完了時、旧メールアドレス宛に変更完了通知メールを送信する」と明確に規定されている（不正なアカウント乗っ取り防止・セキュリティ通知のための重要仕様）。
- **`02_auth.md` 3.1.11 L358 の記述**:
  `※指定された otp_session_id に紐づくユーザーID（OTP_SESSION.USER_ID）が現在認証中のログインユーザーIDと一致していることを検証します。検証成功後、アカウントのメールアドレスを更新し、当該ユーザーのすべての既存ログインセッション（LOGIN_SESSION）を物理削除してCookieを消去し、新メールアドレスでの再ログインを要求します。`
- **問題点**: メールアドレス更新完了時に旧メールアドレスへ通知メールを非同期送信する処理が仕様から漏れており、実装時に通知機能が実装されないリスクがある。

## 3. 推奨される修正案
`3.1.11` の補足説明（L358以降）に、以下の文章を追加してください：

`検証成功後、アカウントのメールアドレスを更新し、旧メールアドレス宛てに変更完了通知メールを送信（非同期処理）します。同時に、当該ユーザーのすべての既存ログインセッション（LOGIN_SESSION）を物理削除してCookieを消去し、新メールアドレスでの再ログインを要求します。`

## 修正完了報告

### 実施した修正内容
`02_auth.md` 3.1.11 (`POST auth/change-email/verify-otp`) の補足説明に、「旧メールアドレス宛てに変更完了通知メールを送信（非同期処理）」する旨の仕様記述を追加しました。
