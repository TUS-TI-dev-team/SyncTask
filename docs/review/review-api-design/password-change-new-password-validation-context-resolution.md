# パスワード変更APIにおける新パスワードのユーザー名・メールアドレス含有チェック時の参照コンテキストの明記不足

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 16:45:00
- **Target Files**:
  - [03_users.md](docs/design/api_design/03_users.md)

## 1. 問題の概要
`PATCH users/{user_id}/password` (3.2.4) のリクエストボディ検証仕様において、`new_password` の制約として「ユーザー名・メールのローカル部（4文字以上の場合）を含まないこと」と記載されています。
しかし、本 API のリクエストボディには `current_password` と `new_password` のみが含まれており、`username` や `email` は含まれていません。バックエンドがログインセッション/DBから該当ユーザーの情報を取得してチェックを行う旨が明記されていないため、検証の仕様記述として補足が必要です。

## 2. 詳細な指摘内容
1. アカウント新規登録 API (`POST auth/register/request-otp`) ではリクエストボディ内に `username` と `email` が共に送信されるため、同一リクエストパラメータ内で比較検証が完結します。
2. 一方、パスワード変更 API (`PATCH users/{user_id}/password`) ではリクエストボディに含まれないユーザー名および登録メールアドレスのローカル部との照合が必要となります。
3. 実装者が「クライアントから送られたボディのみでバリデーションするのか」「DB/セッションからユーザー情報を引いてバリデーションするのか」で迷わないよう、コンテキスト参照の仕様を明文化しておくことが望まれます。

## 3. 推奨される修正案
`03_users.md` の 3.2.4 のリクエストパラメータテーブル `new_password` の説明、または補足注記に以下の文言を追加してください。

```markdown
| `new_password` | string | ○ | 8〜128文字。英大文字/英小文字/数字/記号のうち3種以上を含む。ログインセッション/DBから取得した対象ユーザーのユーザー名・メールアドレスのローカル部（4文字以上の場合）を新パスワード内に含まないこと。現在のパスワードと同一の場合は 422 エラー |
```
