# GET tasks の keyword パラメータにおける最大文字数制限および全角スペーストリムの未定義

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-17 17:15:00
- **Target Files**:
  - [04_tasks.md](docs/design/api_design/04_tasks.md)

## 1. 問題の概要
`GET tasks` (3.3.1 節) の `keyword` パラメータにおいて、入力文字列の最大文字数制限（上限）が未定義である点、およびトリム対象となる空白文字に全角スペース（`\u3000`）等が含まれるかの詳細定義が不足しています。

## 2. 詳細な指摘内容
1. **極端に長いキーワード指定による DB DoS / パフォーマンス劣化リスク**:
   - `04_tasks.md` L16 および L27-28 のリクエスト評価順序において、`keyword` の最大文字数（例: 100文字以内）のバリデーション制約が規定されていません。
   - 悪意あるユーザーやクライアントの不具合により数千〜数万文字の `keyword` が送信された場合、DB側で非常に重い部分一致検索（SQL ILIKE / LIKE 処理）が実行され、データベースサーバーに過度な負荷がかかる脆弱性（DoS）につながる恐れがあります。
2. **トリム対象の文字種表現の不完全さ**:
   - `04_tasks.md` L16 では「前後の空白文字をトリム処理」と記載されていますが、`title`（L111）のように「半角・全角スペース、タブ、改行」と具体的に規定されておらず、全角スペースのみが送信された場合にトリム後に空文字とみなす処理の実装ブレが生じるリスクがあります。

## 3. 推奨される修正案
1. `GET tasks` の `keyword` パラメータ仕様およびバリデーション評価順序に、「トリム後のキーワードが100文字を超える場合は 400 Bad Request（`code: "BAD_REQUEST"`）を返却する」制約を追加してください。
2. トリム対象の空白文字の定義を「前後の空白文字（半角・全角スペース、タブ、改行）」と明確化してください。

### 実施した修正内容
`04_tasks.md` 3.3.1 節 (`GET tasks`) の `keyword` パラメータ定義およびリクエスト評価順序において、トリム対象の空白文字を「半角・全角スペース、タブ、改行」と具体化し、トリム後100文字を超える場合は 400 Bad Request（code: `"BAD_REQUEST"`）を返却するバリデーション制約を明記しました。
