# パスワードリセット・メールアドレス変更API群におけるバリデーション表・エラー定義・応答構造の欠落

- **Status**: Resolved
- **Severity**: Major
- **Created At**: 2026-08-17 16:30:00
- **Target Files**:
  - [02_auth.md](docs/design/api_design/02_auth.md)

## 1. 問題の概要
`02_auth.md` 内のパスワードリセット系（3.1.6〜3.1.9）およびメールアドレス変更系（3.1.10〜3.1.11）のエンドポイントにおいて、入力バリデーション定義表、エラーコード仕様（400, 410, 422, 429等）、アカウント列挙防止注記、およびレスポンスフィールド（`masked_email`, `expires_in_seconds`）が統一性を欠いて欠落しています。

## 2. 詳細な指摘内容
1. **バリデーション制約表の欠落**:
   - `3.1.1`, `3.1.2`, `3.1.4` では「制約・バリデーション」表が明記されていますが、`3.1.6` (`email`), `3.1.7` (`otp_session_id`, `otp`), `3.1.8` (`otp_session_id`), `3.1.9` (`new_password`), `3.1.10` (`new_email`), `3.1.11` (`otp_session_id`, `otp`) にはバリデーション制約表が存在しません。
2. **エラー仕様 (`##### Errors`) の欠落**:
   - `3.1.8`, `3.1.9`, `3.1.10`, `3.1.11` に `##### Errors` セクション自体が存在せず、クールダウン超過（`429`）、有効期限切れ（`410`）、入力不備（`400`）、5回失敗時自動再送（`422 OTP_REISSUED_DUE_TO_FAILURES`）などのHTTPステータスコードおよびエラーコードが定義されていません。
3. **レスポンス構造・アカウント列挙防止注記の不統一**:
   - `3.1.10` (`request-otp`) のレスポンスに `masked_email` が含まれておらず、`3.1.1` や `3.1.6` と不統一です。
   - `3.1.8` (`resend-otp`) のレスポンスが `{"message": "..."}` のみとなっており、`3.1.3` や `3.1.12` で返却される `masked_email` および `expires_in_seconds` が欠落しています。
   - `3.1.6` および `3.1.10` において、未登録アドレスや他ユーザーの重複指定時にダミーOTPセッションを発行して `200 OK`（遅延 1.0s ± 0.1s）を返却するアカウント列挙防止の挙動注記が記載されていません。

## 3. 推奨される修正案
1. `3.1.6`〜`3.1.11` の全エンドポイントに対し、`3.1.1` や `3.1.2` と同様の「制約・バリデーション」テーブルを追加し、`email`, `new_email`, `new_password`, `otp_session_id`, `otp` の文字数・形式・トリム・正規化・包含チェック条件を明示してください。
2. 欠落している `##### Errors` セクションを全エンドポイントに追加し、発生し得るエラーコード（`400 Bad Request`, `410 Gone`, `422 Unprocessable Entity`, `429 Too Many Requests`）を明確に定義してください。
3. `3.1.8` および `3.1.10` のレスポンスJSON構造を `3.1.3` / `3.1.12` と統一（`masked_email`, `expires_in_seconds` を包含）し、`3.1.6` と `3.1.10` にダミーセッション発行および応答遅延（1.0s ± 0.1s）のアカウント列挙防止注記を追加してください。
