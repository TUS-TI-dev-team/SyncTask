# GET tasks における keyword パラメータのトリム後空文字（空白のみ入力）時の無視動作の仕様記述漏れ

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 16:45:00
- **Target Files**:
  - [04_tasks.md](docs/design/api_design/04_tasks.md)
  - [requirements.md](docs/req-def/requirements.md)

## 1. 問題の概要
`GET tasks` の検索キーワード `keyword` パラメータにおいて、スペースのみが入力された場合（トリム後に空文字となる場合）に絞り込みを行わず全件検索対象とする旨の明記が欠落しています。

## 2. 詳細な指摘内容
要件定義書 `requirements.md` (L126) では以下のように定義されています。
> キーワード検索（タスク名・コメント）は、入力された検索文字列の前後の空白文字を自動的に除去（トリム）し、英大文字・小文字を区別しない部分一致検索（Case-Insensitive）を行う（未入力またはトリム後空文字の場合はキーワードによる絞り込みを行わない）

しかし、`04_tasks.md` (L16) では以下のように短縮して記載されているのみです。
> `keyword` | string | × | - | タスク名およびコメントの部分一致検索（Case-Insensitive、トリム処理）

このため、クライアントから `keyword=%20%20`（半角スペースのみ）などのパラメータが送信された際、バックエンドでトリム後空文字の判定を行わずに `LIKE '% %'` などのSQLクエリを発行し、意図せず検索結果が0件になってしまう実装ミスが生じるリスクがあります。

## 3. 推奨される修正案
`04_tasks.md` (L16) の `keyword` パラメータ説明欄を以下のように明確化してください。

```markdown
| `keyword` | string | × | - | タスク名およびコメントの部分一致検索（Case-Insensitive、前後の空白文字をトリム処理。未入力またはトリム後空文字の場合はキーワードによる絞り込みを行わない） |
```
