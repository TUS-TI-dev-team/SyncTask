# 一部の認証APIエンドポイント（3.1.3, 3.1.4, 3.1.8, 3.1.9, 3.1.12）におけるリクエスト評価順序セクションの欠落

- **Status**: Resolved
- **Severity**: Medium
- **Created At**: 2026-08-17 17:07:00
- **Target Files**:
  - [02_auth.md](docs/design/api_design/02_auth.md)

## 1. 問題の概要
`02_auth.md` の全12個のエンドポイントのうち、7個のエンドポイントには `##### リクエスト評価順序` セクションが設置され、入力バリデーション（400）、認証・認可（401/403/404）、レートリミット/ロックアウト（429）、セッション状態検証（400/410）、ビジネスルール検証（422）、および Timing Attack 対策遅延（1.0s ± 0.1s）の適用順序が明確に規定されています。
しかし、残る5個のエンドポイント（3.1.3 `register/resend-otp`, 3.1.4 `login`, 3.1.8 `password-reset/resend-otp`, 3.1.9 `password-reset/reset`, 3.1.12 `change-email/resend-otp`）には `##### リクエスト評価順序` セクションが完全に欠落しており、リクエスト処理の評価優先順位が不透明になっています。

## 2. 詳細な指摘内容
1. **ログインAPI (`3.1.4 POST auth/login`)**:
   - リクエスト構文・入力バリデーション（400 `BAD_REQUEST`、パラメータ欠落・形式不正）を、IPレートリミットおよびアカウントロックアウト（429 `RATE_LIMIT_EXCEEDED`）やパスワード照合（401 `UNAUTHORIZED`）より前に実施するかどうかが明示されていません。
   - 入力フォーマット違反時に失敗カウンター加算や応答遅延なしで即時 400 を返却し、その後にレートリミット判定、最後にパスワードハッシュ照合（1.0s ± 0.1s 遅延）を実施する一貫した評価順序の定義が必要です。
2. **OTP再送API群 (`3.1.3`, `3.1.8`, `3.1.12`)**:
   - `3.1.12` では Cookie 認証（401）および CSRF 検証（403）が入力バリデーション（400）や OTP セッション所有権/ステータス検証（400/403/410）、および 60秒クールダウン（429）に対してどの順序で評価されるかが記載されていません。
   - `3.1.3`, `3.1.8` についても、入力構文バリデーション（400 即時返却）→ セッション存在・ステータス/有効期限検証（400/410）→ クールダウン判定（429）→ Timing Attack 対策（1.0s ± 0.1s 遅延 + 200 OK）の評価流動が定義されていません。
3. **パスワードリセット完了API (`3.1.9 POST auth/password-reset/reset`)**:
   - 入力バリデーション（400）→ OTPセッション状態・期限検証（400/403/410）→ 現在のパスワードとの同一性チェック（422 `SAME_AS_CURRENT_PASSWORD`）→ セッション無効化・パスワード更新（200 OK）の順序が定義されていません。

## 3. 推奨される修正案
`02_auth.md` の 3.1.3, 3.1.4, 3.1.8, 3.1.9, 3.1.12 の各セクションに `##### リクエスト評価順序` を追加してください。

### 実施した修正内容
`02_auth.md` の 3.1.3, 3.1.4, 3.1.8, 3.1.9, 3.1.12 の全5個のエンドポイントに `##### リクエスト評価順序` セクションを追加し、入力バリデーション・認証認可・レートリミット・ビジネスルール検証および遅延制御の処理シーケンスを明確化しました。

### 変更したファイル
- [02_auth.md](docs/design/api_design/02_auth.md)

### 3.1.4 `POST auth/login` の修正例:
```markdown
##### リクエスト評価順序
1. **リクエスト構文・入力バリデーション (`400 Bad Request`)**:
   リクエストボディの JSON 形式、必須パラメータ（`email`, `password`）の有無を検証します。不備がある場合は即座に `400 Bad Request`（code: `"BAD_REQUEST"`）を返却します（遅延なし、失敗カウンター加算なし）。
2. **IPレートリミット・アカウントロックアウト検証 (`429 Too Many Requests`)**:
   該当IPからの連続失敗遮断（`BLOCKED_UNTIL`）または該当メールアドレスのロックアウト（`LOGIN_LOCK_UNTIL`）を検証します。該当する場合は `429 Too Many Requests`（code: `"RATE_LIMIT_EXCEEDED"`、遅延 1.0s ± 0.1s）を返却します。
3. **認証照合処理 (`401 Unauthorized` / `200 OK`)**:
   メールアドレスの存在確認およびパスワードハッシュ照合を実施します（論理削除アカウント含む）。
   - 認証失敗: 失敗カウンターを加算し、`401 Unauthorized`（code: `"UNAUTHORIZED"`、遅延 1.0s ± 0.1s）を返却します。
   - 認証成功: 失敗カウンターを0にリセットし、セッションを発行して `200 OK` を返却します。
```
