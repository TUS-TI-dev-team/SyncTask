# アカウント削除 API のリクエスト評価順序における再認証成功時カウンターリセット記述の統一性不足

- **Status**: Resolved
- **Severity**: Minor
- **Created At**: 2026-08-17 17:05:00
- **Target Files**:
  - [03_users.md](docs/design/api_design/03_users.md)

## 1. 問題の概要
`03_users.md` の 3.2.4 節 (`PATCH users/{user_id}/password`) の「リクエスト評価順序」ステップ 4 では、パスワード再認証成功時に即座に `REAUTH_FAILED_COUNT` カウンターを 0 にリセットする旨が明記されていますが、3.2.3 節 (`DELETE users/{user_id}`) の評価順序ステップ 4 には同記述が欠落しており、両エンドポイント間でステップ記述の表現が統一されていません。

## 2. 詳細な指摘内容
- **`03_users.md` L101-L103 (3.2.3 評価順序ステップ 4)**:
  > 4. **パスワード再認証検証 (`401 REAUTH_FAILED` / `SESSION_DESTROYED`)**:
  >    現在のパスワードのハッシュ照合を実施。不一致時は一律 `1.0s ± 0.1s` の遅延を適用し、失敗回数をカウントアップ。5回達成分は操作中の該当ログインセッションのみを強制破棄および Cookie 削除ヘッダーを付与。
- **`03_users.md` L154-L155 (3.2.4 評価順序ステップ 4)**:
  > 4. **パスワード再認証検証 (`401 REAUTH_FAILED` / `SESSION_DESTROYED`)**:
  >    `current_password` のハッシュ照合を実施。不一致時は一律 `1.0s ± 0.1s` の遅延を適用し、失敗回数をカウントアップ。5回達成分は操作中の該当ログインセッションのみを強制破棄および Cookie 削除ヘッダーを付与。**照合成功時は即座に `REAUTH_FAILED_COUNT` を 0 にリセットしてステップ5に進む。**

### 問題点
1. **エンドポイント間での評価順序テキストの不統一**:
   3.2.3 節の注記欄（L124）では「再認証成功時に 0 にリセットされる」と記述されていますが、リクエスト評価順序の各ステップの記述内容が 3.2.4 節とで表記統一されていないため、実装者が評価シーケンスを読み解く際に戸惑う要因となります。

## 3. 推奨される修正案
`03_users.md` の 3.2.3 節 (`DELETE users/{user_id}`) の「リクエスト評価順序」ステップ 4 の文末に、3.2.4 節と同様に「照合成功時は即座に `REAUTH_FAILED_COUNT` を 0 にリセットして後続処理に進む」旨を追記し、表記を統一してください。
