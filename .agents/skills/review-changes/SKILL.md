# review-changes Skill

このスキルは、開発・修正が完了したブランチにおいてテストを実行・検証した上で、対象ファイル（指定されたファイル、またはブランチ分岐点からの変更点）のレビューを行い、発見された問題点を `docs/review/<sanitized-branch-name>/` ディレクトリ配下に個別の Markdown ファイルとして出力します。

## 実行フロー

### 1. ブランチ名の取得とサニタイズ
1. コマンド `git branch --show-current` を実行して現在のブランチ名を取得します。
2. ブランチ名に含まれるスラッシュ `/` やファイルパスに使用できない特殊文字をハイフン `-` に置換し、サニタイズされたブランチ名 `<sanitized-branch>` を定めます。
   - 例: ブランチ名が `docs/init` の場合 → `docs-init`
   - 例: ブランチ名が `feature/user-auth` の場合 → `feature-user-auth`
3. 指摘ファイルの保存先ディレクトリを `docs/review/<sanitized-branch>/` に定めます。

### 2. テストの実行と確認
コード変更に対する品質担保のため、レビュー前にプロジェクトのテストを自動実行します。
- `backend` ディレクトリが存在する場合: `backend` ディレクトリで `go test ./...` を実行します。
- `frontend` ディレクトリが存在する場合: `frontend` ディレクトリで `npm test`（または `npm run lint` や `npm run build`）を実行します。

> [!WARNING]
> テストが1つでも失敗した場合は、エラー出力を収集してユーザーに報告し、**レビュー処理を即座に中断**してください。

### 3. レビュー対象および変更点の抽出
テストが成功したら、レビュー対象となるファイルおよび変更点を抽出します。

- **レビュー対象が明示的に指定されている場合**:
  - ユーザー指示等で特定のファイルまたはディレクトリがレビュー対象として指定された場合は、**その指定されたファイル（または指定ディレクトリ配下のファイル）**およびその関連ファイルをレビュー対象とします。
  - 指定されたファイルの現状の内容および git 変更履歴・差分（`git diff` や `git status` 等）を確認します。
- **レビュー対象が指定されていない場合（デフォルト）**:
  - ブランチ分岐点 (例: `main`) からの変更差分および未コミット変更差分を取得・確認します：
    - `git diff main...HEAD`
    - `git status`
  - ブランチ分岐点から変更されたソースコードおよび `docs/` 配下の仕様書ファイル一覧を中心に対象として抽出・確認します。

### 4. レビューの実施
レビュー対象ファイルについて、以下の観点で総合的に査読します：
- **仕様書との整合性**: 仕様書 (`docs/`) の定義と実装コードの整合性。
- **コード品質 & 設計**: 保守性、適切な設計パターンの適用、命名規則遵守等。
- **エラーハンドリング & 堅牢性**: 例外処理や境界値チェックの不足。
- **セキュリティ**: 脆弱性やセキュリティ上の問題点の有無。
- **パフォーマンス**: 著しいパフォーマンス劣化の有無。

### 5. レビュー結果の記録

#### A. 問題点が1件以上見つかった場合
各問題点について、1問題につき1つの Markdown ファイルを `docs/review/<sanitized-branch>/` 内に作成します。
ファイル名は `kebab-case-title.md` のように英字 kebab-case のタイトルにします。

**問題ファイルのテンプレート**:
```markdown
# <見つかった問題の簡潔なタイトル>

- **Status**: Open
- **Severity**: [Major/Medium/Minor]
- **Created At**: <YYYY-MM-DD hh:mm:ss>
- **Target Files**:
  - [<file1_basename>](<path_to_file1>)
  - [<file2_basename>](<path_to_file2>)
  - ...

## 1. 問題の概要
<問題点の要約>

## 2. 詳細な指摘内容
<具体的なコード行や仕様記述の不備についての説明>

## 3. 推奨される修正案
<どのように修正すべきかの具体案>
```

#### B. 問題点が0件（修正不要）の場合
`docs/review/<sanitized-branch>/summary.md` を作成し、レビューを通過した旨を記録します。

```markdown
# レビュー結果サマリ

- **Status**: Passed
- **Reviewed At**: <YYYY-MM-DD>

本ブランチでの変更点（コードおよび仕様書）に対するレビューを実施した結果、修正が必要な問題点は見つかりませんでした。すべてのテストおよびレビューチェックを通過しています。
```
